# ⑪-C2 웹 — 문진표 화면 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 보호자가 링크(`/f/<토큰>`) 하나로 설치·가입 없이 아이의 정보를 적어 낸다. 고르는 칸이 대부분이고 글자를 치는 필수 칸은 넷 이하다.

**Architecture:** 동의서와 같은 주소·같은 관문이다 — `app/f/[token]/page.tsx` 가 `kind` 로 가른다. 칸의 규칙과 보낼 본문은 순수 함수(`lib/intake.ts`)가 만들고 화면(`components/IntakeForm.tsx`, `'use client'`)은 그것을 쓴다. 제출은 웹 자신의 경로(`app/f/[token]/intake/route.ts`)로 가고 웹 서버가 백엔드를 부른다.

**Tech Stack:** Next.js 16 App Router · TypeScript · Vitest · Playwright.

**Spec:** `docs/superpowers/specs/2026-11-16-consent-intake-design.md`(3.4·3.6 의 9~11·4절). 백엔드 계약은 `_docs/decisions/014-consent-intake.md` 의 "⑪-C1 … API 계약".

## Global Constraints

- **필수로 글자를 치는 칸은 4 이하**(보호자 이름·번호·아이 이름·품종 직접 적기). 나머지는 고르는 칸(칩·라디오)이다. e2e 가 수를 고정한다.
- 온 구성만 그린다 — 켜진 칸(`fields`), 매장의 질문, 지병 종류, `guardian_needed`. 끈 칸은 그리지도 보내지도 않는다.
- `update`(다시 받기)는 아이 이름만 보이고 전부 선택이다(`바뀐 것만 적어 주세요`). 지금 값은 화면에 없다.
- 낼 때: [보내기](다 적었어요 — `done: true`)와, 새 손님·새 아이에서는 [보내고 다른 아이도 적기](`done: false`). 둘째 아이부터 보호자 칸이 없다.
- 빠진 칸은 보내지 않고 그 칸 이름으로 말한다. 서버의 422 는 `적은 내용을 다시 확인해 주세요`.
- 개인정보 수집·이용 안내(항목·목적·보관 기간 — `keep_days`)와 동의 체크가 있다.
- 제출 경로: 다른 출처 403, 131,072바이트 초과·길이 없음 413, 모양 틀림 422, 상태 코드만 돌려준다. 응답 헤더 셋(`noindex`·`no-store`·`no-referrer`)은 그대로다. 미리보기(og)는 매장 이름과 "문진표"뿐이다.
- **토큰·적은 이름·전화번호·문진표의 글을 `console.*`·기록에 넣지 않는다.** 보호자의 브라우저는 백엔드를 직접 부르지 않는다.
- 스크립트가 오기 전에는 버튼이 잠겨 있다(값이 주소에 실리지 않게 `method="post"`). 폭 320 에서 가로로 넘치지 않는다. 해요체. "AI"·"법적 효력"이 없다.

## Review Focus

1. **보내는 사이 링크가 닫혔다(410)·끊겼다(404)** → 오류 글이 아니라 화면을 다시 읽어 닫힘·보냈어요로 간다. 적던 글이 사라지는 것은 받아들인다.
2. **[보내고 다른 아이도 적기] 뒤** → 아이 칸이 비워지고 보호자 칸은 사라지고, 방금 낸 아이의 이름을 알려 준다. 뒤로 가기·새로 고침에도 같은 답이 두 번 나가지 않는다.
3. **매장이 방금 칸을 끄거나 질문을 지웠다** → 낡은 화면에서 낸 답도 받아진다(서버가 버린다). 필수 질문이 새로 생겼으면 422 → 다시 읽으라는 안내.
4. **긴 글·이모지·붙여넣은 줄바꿈** → 칸의 길이 제한 안에서 잘리지 않고 그대로 간다. 줄바꿈이 든 글은 한 줄 칸에서 빈칸으로 바뀐다.
5. **느린 망에서 두 번 누른다** → 한 번만 나간다.
