## Global Constraints

- 앱 규칙(`app/CLAUDE.md`) 그대로: 기능 폴더 import 는 `visit → customer` 만(customer 는 visit 를 import 하지 않는다, sales 는 `auth` 만), 서버에서 읽는 화면 본문은 `AsyncBody`, 플러그인은 `core/proxy`(공유는 `shareSheetProvider`), 문구는 해요체, `print` 금지.
- 문구는 설계의 글 그대로(아래 각 작업에 적었다). "AI"·색 딱지·아이콘 줄·이모지를 쓰지 않는다. 줄·칸·머리 요약·하루 마무리의 끝 화면에 **금액 숫자가 없다**(결제 장의 총액 칸만 — 서버가 `sales:write` 일 때만 그 장을 준다).
- `marks` 는 `fromJson` 에서 한 번 enum 으로 바꾸고 **모르는 코드는 버린다**. 낱말·차례: `paid` 결제 완료 → `report_sent` 알림장 보냄 → `pass_used` 정기권 → `deposit_received` 예약금 받음. 가족 묶음은 완료한 방문이 모두 그 표시를 가질 때만. 한 줄의 낱말이 넷을 넘으면 뒤를 `+N` 으로 접는다.
- 새 응답 칸이 없는 서버(옛 응답)에도 죽지 않는다 — 새 칸은 `?? 기본값`(수 0, 목록 빈, `cycle_source` 는 `none`).
- 쓰기는 성공하든 실패하든 읽는 쪽을 무효화한다. 매장의 값(`revisit-settings`) 쓰기는 사장만(`isOwnerProvider`) — 직원에게는 바꾸는 줄이 없다. 아이의 주기·안내한 날 쓰기는 직원도.
- **안내 글(템플릿·만든 글)을 로그·오류 문구·테스트 출력·스크린샷 설명에 남기지 않는다.** 시뮬레이터 흐름은 아이 이름이 들었는지만 본다.
- 골든: 하루 화면·달력은 의도한 변화라 다시 찍고 눈으로 본다(`flutter test --update-goldens` 는 해당 파일만).
- 검증: `flutter analyze` 0, `flutter test` 전부, 시뮬레이터 흐름 iOS·안드로이드.

## Review Focus

1. 지난 초안의 날 옮기기 — 초안의 날이 오늘이거나 지났으면 **내일 이후**의 가장 가까운 같은 요일로, 시간은 그대로(오늘이 그 요일이어도 다음 주). 지나지 않았으면 그대로.
2. 하루 마무리에서 한 장을 처리하는 사이 다른 기기가 먼저 끝냈다(409·404) — 알리고 목록을 다시 읽어 다음 장으로 간다(멈추지 않는다). 건너뛴 장은 다시 읽어도 되살아나지 않는다. 처음부터 장이 없으면 곧바로 끝 화면이다.
3. 목록에서 [예약]으로 잡고 돌아오면 그 줄이 사라지고, [안내] 뒤에는 `오늘 안내` 가 보인다(목록·수를 다시 읽는다). 공유 시트가 실패해도 안내한 날은 적지 않는다.
4. 가족 묶음에서 한 아이만 결제했으면 `결제 완료` 가 뜨지 않는다. 앞날 칸에는 숫자가 없다(서버가 0 을 준다 — 앱은 더하기만 한다).
5. 새 칸이 없는 옛 응답(`marks`·`unpaid` 등 없음)과 모르는 `cycle_source`·`kind`·`marks` 코드 — 죽지 않고 그 항목·장만 버린다.

## Rulings (계획 때 정함)

- 주기 문구 함수는 `lib/core/time/grooming_cycle.dart`(visit·customer 가 함께 쓴다 — customer 는 visit 를 import 할 수 없다. 날짜·주의 말이라 `core/time` 이다).
- 숫자를 고르는 시트는 디자인 위젯 하나(`AppStepper` — `[−] 값 [+]`, 범위 밖으로 가지 않는다)를 쓴다. 매장의 값 시트(visit)와 아이의 주기 시트(customer)가 함께 쓴다.
- 목록 줄의 둘째 줄(주기 글)을 누르면 그 아이의 주기 시트, 줄의 나머지를 누르면 반려동물 상세다.
- 완료 시트의 `간격 바꾸기` 는 그 방문 아이의 주기 시트를 연다. 초안이 어림이고 사장이면 `기본 간격 바꾸기` 가 하나 더 있다(매장의 기본 간격 시트). 보호자만의 방문은 `기본 간격 바꾸기` 만(사장).
- 안내 글의 매장 이름은 서버가 채운다(매장 이름은 비어 있을 수 없다) — "매장 이름을 묻기"는 두지 않는다.
- 템플릿 편집의 미리 보기는 매장 이름(`shopNameProvider`)·예시 아이 이름 `콩이`·매장의 기본 간격 주 수로 채운다.
- 하루 마무리의 끝 문구는 오늘이면 `오늘 일을 다 마쳤어요`, 지난 날이면 `이날 일을 다 마쳤어요`. 그날의 수는 하루 응답의 `counts.completed` 와 `알림장 보냄` 표시가 있는 방문 수.
- 하루 마무리의 결제 장 [저장]은 기록 전체 교체다 — 방문 상세를 다시 읽어 기록의 다른 칸·사진 자리는 그대로 두고 총액·결제 수단만 바꾼다(기록이 없으면 총액·수단만 있는 새 기록). 409 `RECORD_VERSION_CONFLICT` 면 다시 읽어 한 번 더.
- 아이의 주기·안내한 날 쓰기 뒤 방문 쪽(다시 올 때 목록·수·완료 시트)은 지금의 `careMarksChangedPlugProvider` 로 알린다(`app.dart` 가 채우는 함수에 목록·수 무효화를 더한다 — 새 플러그를 만들지 않는다).
- 다시 올 때 목록의 쪽 나눔은 visit 에 새로 둔다(`state/revisit_list.dart` — 매출의 `SalesPagedController` 와 같은 규칙: 세대 번호, 다음 쪽 실패 시 보인 줄 유지, `reload()`). sales 를 import 할 수 없어서다.
