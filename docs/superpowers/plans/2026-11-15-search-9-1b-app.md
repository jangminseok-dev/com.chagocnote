# ⑨-1b 기록 검색 — 앱 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 매장이 적어 둔 글을 문장으로 찾는 검색 화면 하나(`/search`)와 들어가는 곳 둘(기록 피드 머리, 반려동물 상세 [기록] 탭)을 만든다.

**Architecture:** 새 기능 폴더 `lib/features/search`(`auth` 만 import). 서버 `GET /v1/shops/{shop_id}/search` 하나를 읽는다. 줄의 문구·갈 곳은 순수 함수(`state/search_rules.dart`), 늦게 온 옛 결과 버리기는 컨트롤러의 세대 번호가 한다. 상세로는 라우터 경로로만 간다(다른 기능을 import 하지 않는다).

**Tech Stack:** Flutter 3.41 · Riverpod 3 · go_router · dio

**Spec:** `docs/superpowers/specs/2026-11-14-record-search-design.md` 4절. 서버의 계약과 한계는 `_docs/decisions/013-record-search.md`, 앱 규칙은 `app/CLAUDE.md`.

## Global Constraints

- 브랜치 `feat/search-9-1b-app`. 커밋·주석·테스트 이름은 한국어, 커밋 끝에 `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`. 푸시·병합은 사용자가 말할 때만. 과금·외부 연결 없음. 백엔드·웹은 바꾸지 않는다.
- `features/search` 는 `auth` 만 import 한다(`test/design/feature_imports_test.dart`). 기능 폴더 안은 `api`·`state`·`screens` 세 층. 서버에서 읽는 본문은 `AsyncBody`. 문구는 해요체. `print` 금지. 웹뷰 금지.
- **검색어·걸린 문장을 로그·오류 문구·스크린샷 설명에 남기지 않는다.** 검색어를 기기에 저장하지 않는다(검색어 기록·추천어 없음).
- **톤**: "AI"·반짝이 아이콘·색 딱지·강조 표시 없음. 잉크색 글자와 가는 선. 뜻 검색이 됐는지(`semantic`)로 아무것도 그리지 않는다.
- 값(고정): 검색어 2~100자(다듬은 뒤) · 0.5초 쉰 뒤 묻는다 · 사진 40 · 걸린 문장 두 줄까지.
- 서버의 kind 는 enum 으로 한 번만 바꾼다. **모르는 kind·모양이 깨진 줄은 버린다**(나머지는 보인다).
- 검증(`app/` 에서): `flutter analyze`(경고 0) · `flutter test`. 시뮬레이터 흐름은 iOS(iPhone 17)와 안드로이드 에뮬레이터 둘 다.

## Review Focus

1. **늦게 온 옛 결과** — 빨리 고쳐 쓴 검색어의 앞 요청이 뒤 요청보다 늦게 와도 화면은 마지막 검색어의 결과다. 검색어를 2자 미만으로 지우면 진행 중인 요청의 결과가 뒤늦게 나타나지 않는다.
2. **갈 곳이 없는 줄** — `visit_id` 도 `open_pet_id` 도 없는 줄(아이가 없는 보호자의 메모)은 눌리지 않고 화살표가 없다. 죽지 않는다.
3. **모르는 값** — 모르는 kind, `owner` 가 없는 줄, 날짜가 깨진 줄이 섞여 와도 나머지 줄은 보인다.
4. **한글 조합** — 조합 중에는 묻지 않는다. 같은 검색어를 두 번 묻지 않는다. 앞뒤 공백·줄바꿈만 다른 검색어는 같은 검색어다.
5. **돌아왔을 때** — 줄을 눌러 상세에 갔다 돌아오면 검색어와 결과가 그대로다. 매장을 바꾸면 옛 매장의 결과가 남지 않는다.
