# ⑪-B 앱 — 보낼 것 시트·서류 설정 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 예약을 저장하면 보호자에게 보낼 글(예약 안내 + 동의서 링크)이 준비된 시트가 뜨고 공유 한 번으로 나간다. 사장은 서류 설정에서 동의서의 글·보내는 글·기준값을 자기 가게에 맞게 고친다.

**Architecture:** 묶음은 `features/visit`(API `sendBundle`, 시트 `send_bundle_sheet.dart`)이다. 서류 설정은 `features/customer`(모델·API·쓰기·화면)이고 설정 목록(`features/shop`)은 경로로만 간다. 화면은 낙관적으로 그리지 않고 다시 읽은 값으로 그린다. 전부 네이티브다.

**Tech Stack:** Flutter · Riverpod 3 · go_router.

**Spec:** `docs/superpowers/specs/2026-11-16-consent-intake-design.md`(3.2·3.5·3.6 의 1·6, 4절), 공통(1·3·4절). 백엔드 계약은 `_docs/decisions/014-consent-intake.md` 의 "⑪-B 백엔드 — API 계약".

## Global Constraints

- 편의 기준: **예약 저장 뒤 누르기 2번**([보내기] → 받는 사람)으로 나간다. **설정을 한 번도 열지 않아도** 기본 글로 나간다.
- 시트에서 **글을 고칠 수 있고 토막을 뺄 수 있다.** 보내지 않고 닫아도 예약은 저장돼 있다. 방문 상세의 [보호자에게 보내기]로 다시 연다.
- 앱은 **모르는 `kind` 의 토막도 글 그대로 싣는다.** 토막이 없으면 시트를 띄우지 않는다.
- **빈 글은 나가지 않는다** — 고쳐서 비운 토막은 빠진 것으로 치고, 전부 비었으면 [보내기]가 눌리지 않는다.
- 설정 줄의 이름은 일어나는 일로 쓰고, 줄 아래에 **보호자가 받는 모습**을 그대로 보인다. 널리 쓰는 말(템플릿)은 그대로 쓴다. "AI"·"법적 효력"이 없다. 해요체.
- 모든 값은 바꿀 수 있고 [기본 글로 되돌리기]·기본값이 보인다. 빈 글로 저장할 수 없다(되돌리기로만).
- 바꾸는 것은 사장만(`isOwnerProvider`), 직원에게는 읽기 전용. 보안 경계는 서버(403).
- **링크 주소(토큰)·보내는 글을 로그·오류 문구·테스트 출력·스크린샷 설명에 남기지 않는다.** `print` 금지, 웹뷰 금지.
- import 방향: `visit → customer` 만.

## Review Focus

1. **예약 저장은 됐는데 묶음 읽기가 실패한다** → 저장은 끝난 것이다. 알리지 않고 닫히거나(시트 없음) 방문 상세에서 다시 열 수 있다 — 저장 화면에 갇히지 않는다.
2. **시트에서 동의서 토막의 주소를 지우거나 망가뜨린다** → 막지 않는다(사장의 글이다). 다만 [처음 글로]로 되돌릴 수 있다.
3. **공유 시트가 실패하거나 취소된다** → 시트는 열려 있고 다시 누를 수 있다. 고친 글이 남아 있다.
4. **문안을 고치는 중에 뒤로 간다** → 고친 것이 있으면 묻는다. 저장 실패면 적은 글이 남는다.
5. **직원이 서류 설정을 연다 / 사장이 저장하는데 403·422** → 읽기 전용으로 보이고, 실패는 그 자리에서 말하고 값은 다시 읽은 것으로 돌아간다.
