# ③-B2 확인할 것·주의 고객 — 앱 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 예약을 잡을 때·방문을 열 때·하루를 볼 때 "확인할 것"이 보이고, 미용 동의와 주의 고객 표시를 앱에서 적고 지운다.

**Architecture:** 서버(③-B1)가 판정한 `{code, scope, detail}` 을 앱은 그리기만 한다. 확인할 것의 모델·문구·묶기는 `features/visit`(문구는 `state/check_rules.dart` 의 순수 함수), 동의·주의의 모델·쓰기·화면은 `features/customer`. 방문 상세의 [받았어요]는 `VisitCommands` 가 `CustomerCommands` 를 부른다(`visit → customer`). 고객 쪽 쓰기가 방문 쪽 읽기를 낡게 하므로 `core/plugs` 의 자리 하나로 알린다(customer 는 visit 를 import 하지 않는다).

**Tech Stack:** Flutter 3.41 · Riverpod · go_router · 기존 `design/widgets`

**Spec:** `docs/superpowers/specs/2026-11-14-visit-checks-design.md`(3.4, 4.3). API 계약은 `_docs/decisions/012-visit-checks.md`("③-B2 앱이 기댈 API 계약"). 앱 규칙은 `app/CLAUDE.md`.

## Global Constraints

- 브랜치 `feat/visit-3b2-app`(main 에서). 첫 커밋에 이 계획서. 커밋·주석·테스트 이름은 한국어, 커밋 끝에 `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`. 푸시·병합은 사용자가 말할 때만. 과금·외부 연결 없음. 백엔드·웹은 바꾸지 않는다.
- **예약을 막지 않는다.** 확인할 것은 읽는 중·읽기 실패면 묶음이 없고 저장 버튼은 그대로다.
- **모르는 code 와 모양이 깨진 항목은 버린다**(나머지는 보인다).
- 톤: 색 딱지·경고 삼각형·이모지 없음. 잉크색 글자와 가는 선, 할 일(`consent`)에만 버튼 하나.
- **주의 사유·지병 메모를 로그·오류 문구·테스트 출력에 남기지 않는다.** `print` 금지.
- 기능 폴더 규칙: `customer` 는 `auth` 만, `visit` 는 `auth`·`customer` 만 import 한다.
- 문구는 해요체, `AppStrings`. 서버에서 읽는 본문은 `AsyncBody`, 쓰기는 `runShopScoped`, 성공하든 실패하든 읽는 쪽을 무효화한다.
- 방문 수정 화면(`VisitEditScreen`)에는 미리 보기가 없다.
- 검증: `flutter analyze`(경고 0) · `flutter test` · 시뮬레이터 흐름 iOS·안드로이드.

## Review Focus

1. **모르는 항목** — 모르는 `code`, `detail` 의 칸이 빠지거나 형이 다른 항목, `checks` 칸이 아예 없는 옛 응답. 화면이 죽지 않고 아는 항목만 보인다.
2. **미리 보기의 실패와 순서** — 읽기 실패·읽는 중이면 묶음이 없고 저장할 수 있다. 아이·날짜를 빠르게 바꾸면 앞 선택의 응답이 지금 선택에 보이지 않는다. 보호자만의 방문은 보호자 항목만 묻는다.
3. **[받았어요]의 끝** — 연타하면 요청 한 번. 실패하면 스낵바가 뜨고 줄은 남는다. 성공하면 그 줄이 사라진다(상세를 다시 읽는다).
4. **주의 사유 입력의 끝** — 빈 칸·공백만(저장 안 됨), 100자(통과)·101자(입력이 안 됨), 붙여넣은 줄바꿈(한 줄로), 연타(요청 한 번), 실패하면 시트가 남고 원인 문구. 사유는 오류 문구에 실리지 않는다.
5. **수 세기** — 가족 묶음(두 마리)에서 보호자 항목 수는 한 번만 센다. 0 이면 `확인` 글자가 없다. 취소·노쇼·완료 방문에는 없다(서버가 0 을 준다 — 앱은 준 대로 그린다).

### Task 3: 고객 쪽 화면 — 미용 동의 줄, 주의 고객 줄·시트, 목록 표시

**Files:** Create `lib/features/customer/screens/grooming_consent_row.dart`·`caution_row.dart`; Modify `pet_detail_screen.dart`·`family_card_view.dart`; Test `test/features/customer/screens/care_marks_test.dart`(+ 골든 `pet_detail_caution.png`), `customer_list_tab_test.dart` 에 더한다

- **미용 동의 줄**(기본 탭, 메모 아래): 이름표 `미용 동의서`, 값 `받지 않았어요` 또는 `{yyyy년 M월 D일}에 받았어요`. 없으면 끝에 [받았어요](오늘로 적는다), 있으면 `···` → [오늘 다시 받았어요]·[받은 기록 지우기]. 지난 날짜를 고르는 입력은 만들지 않는다.
- **주의 고객 줄**([보호자] 탭, 노쇼 횟수 아래·보호자 계정 연결 줄 위): 표시가 있으면 `주의 고객 · {reason}` 과 `{M월 D일}까지`, `···` → [사유 고치기]·[주의 표시 지우기]. 없으면 `주의 고객으로 표시하지 않았어요` 와 [표시하기]; 노쇼가 2번 이상이면 그 위에 `노쇼가 {N}번 있어요` 가 붙고 시트의 사유가 `노쇼 {N}번` 으로 채워져 열린다.
- **시트**: 한 줄 입력(key `ValueKey('caution-reason')`, 100자), 안내 `다른 매장에는 보이지 않아요. 1년 뒤에 저절로 지워져요.`, [저장]. 빈 글이면 [저장]이 안 눌린다. 저장 중 연타 막기, 실패는 시트 안 문구(`messageFor`).
- **목록**: `FamilyCardView` 머리 줄 끝에 ` · 주의`(caution 이 true 일 때).
- [ ] 위젯 테스트(Review Focus 4 + 줄의 네 상태 + 노쇼 2번의 미리 채움 + 목록 표시) → 실패 확인 → 구현 → 전체 `flutter test`·골든 눈으로 → 변이 하나(시트의 연타 문지기 제거). 커밋 `feat(customer): 미용 동의 줄, 주의 고객 줄과 시트, 목록의 주의 표시`.
