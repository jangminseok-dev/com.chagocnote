# 차곡노트 — ⑧ 매출 통계 설계

2026-11-14. 사장이 홈의 [매출] 탭에서 이번 달이 어땠는지 한눈에 보고, 다시 올 때가 지난 아이를 챙긴다.

- 범위: 백엔드(`visit` 스포크의 읽기 슬라이스와 목표 저장), 앱(새 기능 폴더 `sales` — 매출 탭, 목록 화면 셋, 목표 시트, 요약 공유).
- 하지 않는 것: 6절.
- 바탕: 기반 설계(`2026-09-20-foundation-design.md` — `sales:read` 는 사장만), 기록 설계(④ — 총액·결제 수단·메뉴별 금액), 알림장 설계(⑤), 결정 기록 006·007·008. 화면의 기준 목업은 `.superpowers/brainstorm/50897-1794592195/content/sales-v2-photos.html` 의 ①(위)·②(아래)다.

## 1. 왜

기록마다 총액·결제 수단·메뉴별 금액이 쌓이고 있는데 볼 곳이 없다. 홈의 [매출] 탭은 "매출은 다음 업데이트에서 만나요"라고만 한다.

업계가 공통으로 보여 주는 것은 기간별 합계·결제 수단별·메뉴별이고(MoeGo·Gingr·그루머노트), 미용 업계가 가장 중요하게 보는 것은 "다시 오는 손님"이다. 차곡노트는 합계를 보여 주는 데서 끝나지 않고 **그 매출을 만든 아이들**과 **다시 올 때가 지난 아이**까지 잇는다.

## 3. 무엇을 보이나

### 3.1 낱말의 뜻 (모든 숫자가 따르는 규칙)

- **기간**: 일·주·월·연. 주는 월요일~일요일. 모두 **매장 시간대**의 날짜다.
- **방문한 날 기준**: 방문의 시작 시각(`visits.starts_at`)이 든 날에 센다. 돈을 받은 날 기준은 없다(선결제·외상·환불을 다루지 않는다).
- **매출**: 완료한 방문(`status = completed`)의 기록에 적힌 총액(`visit_records.total_amount`)의 합. 총액이 비어 있는 완료 방문은 0 이 아니라 **빠진 것**으로 치고 따로 센다(3.2 의 "금액을 적지 않은 완료 방문").
- **방문 수**: 완료한 방문의 수. **한 번에 평균**: 매출 ÷ 총액이 있는 완료 방문 수(원 단위에서 버림).
- **메뉴별**: `visit_record_items` 의 금액 합과 건수. 총액은 항목 합과 별개라(④ — 할인·추가금), 기간의 `매출 − 항목 합`이 0 이 아니면 메뉴 목록 맨 아래에 **"조정"** 한 줄로 보인다(음수일 수 있다). 메뉴 합 + 조정 = 매출.
- **결제 수단별**: 카드·현금·이체. 결제 수단을 고르지 않은 기록은 **"미선택"**으로 묶는다(0원이면 줄이 없다). 합은 매출과 같다.
- **아이**: `pet_id` 가 있는 완료 방문의 서로 다른 반려동물. 보호자만의 방문은 방문 수·매출에는 들고 아이 수에는 들지 않는다.
- **처음 온 아이**: 그 매장에서의 첫 완료 방문이 이 기간 안에 있는 아이. **다시 온 아이**: 나머지.
- **비교**: 바로 앞 기간(어제·지난주·지난달·작년). 지금 진행 중인 기간이면 **같은 길이만큼만** 견준다 — 11월 14일에 보는 11월은 10월 1~14일과. 작년 같은 기간의 매출이 0 보다 크면 작년 비교를 한 줄 더 보인다(연 보기에서는 앞 기간이 곧 작년이라 한 줄뿐이다).

### 3.2 매출 탭 (위에서 아래로)

1. **기간 고르기** — [일][주][월][연] 세그먼트와 ‹ ›. 처음 열면 이번 달. 앞날로는 넘어가지 않는다.
2. **큰 숫자** — 기간 이름(영문 기울임 `November` + 연도, 일·주는 날짜), 매출을 큰 세리프 숫자로.
3. **비교 문장** — "지난달 14일까지보다 **42만 원** 많아요." / "적어요." / "지난달 14일까지와 같아요." 앞 기간이 0 이면 문장이 없다. 작년 비교가 있으면 그 아래 한 줄.
4. **목표**(**이번 달**의 월 보기, 목표를 정했을 때만 — 지난 달에는 보이지 않는다) — "이번 달 목표 500만 원의 65%"와 가는 진행선. 정하지 않았으면 [이번 달 목표 정하기] 한 줄(작게).
5. **이번 기간의 아이들** — 최근에 다녀간 아이 여섯의 사진(겹쳐서)과 "41마리가 48번 다녀갔어요 / 한 번에 평균 67,700원".
6. **막대** — 일 보기: 없음. 주: 요일 7개. 월: 날짜별. 연: 월별 12개. 고른 칸만 검정, 나머지는 옅은 회색, 아직 오지 않은 칸은 점선. 고른 칸 위에 그날의 대표 사진.
7. **고른 날 카드**(주·월) — 캘린더 탭과 같은 글래스 카드: "14일, 토요일 · 310,000원", 그날 아이들의 겹친 사진과 이름. 누르면 그날의 하루 화면으로 간다. 연 보기에서 막대를 누르면 그 달의 월 보기로 바뀐다.
8. **결제 수단** — 줄마다 이름·가는 막대·금액·비율.
9. **메뉴** — 줄마다 그 메뉴를 가장 최근에 한 아이의 사진·이름·건수·금액. 금액순. 다섯 줄까지 보이고 [모두 보기]. 누르면 그 메뉴의 방문 목록.
10. **손님** — 처음 온 아이 N마리 / 다시 온 아이 N마리(각각 사진 몇 장), 그 아래 **단골**: 보고 있는 기간이 든 해에 가장 자주 온 아이 셋(사진·이름·횟수 — 진행 중인 해면 오늘까지. 2025년의 기간을 보면 2025년의 단골이다).
11. **다시 올 때가 지난 아이** — "다시 올 때가 지난 아이 7마리 ›". 누르면 3.3 의 목록. 0 이면 줄이 없다. 기간과 상관없이 오늘 기준이다.
12. **예약** — 남은 예약(이 기간의 지금 이후 `reserved` — 지난 기간이면 없음), 노쇼, 취소. 노쇼·취소 숫자를 누르면 그 방문 목록.
13. **요일**(월·연 보기) — 요일별 매출 막대 일곱, 가장 높은 요일만 검정.
14. **알림장** — "완료한 48건 가운데 40건에 알림장을 보냈고, 보호자가 31건을 열어 봤어요." **보냈다**는 그 방문에 알림장을 한 번이라도 만든 적이 있다는 뜻이다(`visit_reports` 에 줄이 있다 — 기간이 지나 닫혔거나 매장이 끊었어도 보냈던 것은 보낸 것이다. "지금 살아 있는 링크"로 세면 두 달 전 화면이 0건이 된다). **열어 봤다**는 그 방문의 줄 가운데 하나라도 처음 연 시각이 있다는 뜻이다. 완료한 방문이 없으면 이 구역이 없다.
15. **금액을 적지 않은 완료 방문 N건 ›** — 0 이면 없다. 누르면 그 방문 목록(방문 상세로 가서 채운다).
16. **요약 공유** — 맨 아래 작은 글자 버튼. 3.4.

**빈 기간**: 완료한 방문이 하나도 없으면 큰 숫자 자리에 0 을 크게 두지 않는다 — "아직 기록한 매출이 없어요"와 "방문을 완료하고 기록에 금액을 적으면 여기에 쌓여요." 한 줄. 예약·다시 올 때가 지난 아이는 그대로 보인다.

**사진이 없는 아이**: 고객 탭과 같은 빈 사진 칸(앱의 기존 `AppPhotoTile` 빈 상태)을 쓴다.

**직원**: 탭의 본문 대신 "매출은 사장님만 볼 수 있어요." 한 줄. API 를 부르지 않는다.

### 3.3 다시 올 때가 지난 아이

- 조건(모두): 마지막 완료 방문이 **8주(56일) 넘게** 지났다 · **1년은 넘지 않았다**(떠난 손님을 계속 보이지 않는다) · 앞으로 잡힌 예약(`reserved`)이 없다 · 무지개다리를 건너지 않았다 · 고객이 익명화되지 않았다.
- 목록: 사진·이름·"9주 전"(마지막 방문일), 오래된 순. 누르면 반려동물 상세(거기서 보호자 번호·예약으로 이어진다). 연락·알림 보내기 버튼은 이번에 없다.
- 8주는 고정값이다(설정으로 두지 않는다).

### 3.4 요약 공유

지금 보는 기간의 요약을 글로 만들어 기존 공유 시트에 넘긴다. 파일(엑셀·CSV)은 만들지 않는다. 글에는 기간, 매출, 방문 수, 결제 수단별, 메뉴별만 담는다 — **아이·보호자의 이름과 번호는 넣지 않는다.**

```
Hiss Haus · 2026년 11월 (14일까지)
매출 3,250,000원 · 방문 48건
카드 2,400,000원 / 현금 550,000원 / 이체 300,000원
전체 미용 2,100,000원(30건) · 목욕 750,000원(15건) · 스파 400,000원(8건)
```

### 3.5 목표

매장마다 **월 목표 금액 하나**를 둔다(매달 같은 값). 0 또는 지우기는 "목표 없음"이다. **이번 달의 월 보기에서만 보인다** — 목표의 이력을 두지 않으므로 지난 달을 지금의 목표와 견주지 않는다(목표를 바꾸면 지난 달의 달성률이 따라 바뀌는 일이 없게). `sales:read` 를 가진 사람(사장)이 정한다 — 새 권한을 만들지 않는다.

## 4. 구조

### 4.1 백엔드

- **새 스포크를 만들지 않는다.** 방문·기록·메뉴·알림장이 모두 `visit` 의 것이라 집계도 `visit` 의 읽기 슬라이스다. 아이의 이름·무지개다리·익명화는 `customer` 의 것이라 허브 포트 `CustomerDirectoryPort`(이미 있는 `briefs`)로 받는다. 사진은 지금 피드·달력이 쓰는 길(대표 미디어 → 서명 주소)을 그대로 쓴다.
- 경로는 모두 `/v1/shops/{shop_id}/sales/…` 이고 `require_permission("sales:read")` 다. 직원은 403 `PERMISSION_DENIED`.
- **집계는 읽을 때 SQL 로 한다.** 미리 계산해 둔 표·캐시·배치를 두지 않는다(작은 매장의 한 해 방문은 수천 줄이다). 날짜는 `starts_at AT TIME ZONE <매장 시간대>` 로 자른다.

| 경로 | 하는 일 |
|---|---|
| `GET /sales/summary?span=day\|week\|month\|year&anchor=YYYY-MM-DD` | 매출 탭 한 화면의 전부 — 기간의 경계, 매출·방문 수·평균, 앞 기간·작년 비교값, 칸별 매출(막대)과 칸의 대표 사진, 결제 수단별, 메뉴별(+조정), 아이들(얼굴 여섯, 아이 수, 처음·다시), 단골 셋, 예약(남은·노쇼·취소), 요일별, 알림장(보낸 수·연 수), 금액 없는 완료 방문 수, 다시 올 때가 지난 아이 수, 목표. `anchor` 는 그 기간 안의 아무 날. |
| `GET /sales/visits?span&anchor&filter=unrecorded\|no_show\|canceled\|menu&menu_id=&cursor=` | 탭에서 누르면 나오는 방문 목록(최신순 20개씩) — 방문 ID·날짜·아이 이름·사진·금액. |
| `GET /sales/due-pets?cursor=` | 다시 올 때가 지난 아이(오래된 순 20개씩) — `pet_id`·이름·사진·마지막 방문일. |
| `GET /sales/goal` · `PUT /sales/goal` `{monthly_amount: int \| null}` | 월 목표 읽기·정하기. 금액은 0~1억(기록의 총액과 같은 범위). |

- 고른 날의 글래스 카드는 **새 API 없이** 요약의 칸 정보(그날 매출·대표 사진)와 기존 하루 목록 조회로 그린다 — 어느 쪽으로 채울지는 만드는 사람이 정한다(요약에 그날의 아이 이름을 싣는 편이 왕복이 적다).
- 마이그레이션 `0015`: 목표 표 하나(`visit` 소유 — `shop_id` 기본 키, `monthly_amount`, 바꾼 시각·멤버). 집계용 색인이 모자라면 같은 마이그레이션에 더한다(지금 `visits` 에 `(shop_id, starts_at)` 로 읽는 길이 있는지 확인하고 정한다).
- 응답 스키마는 칸을 하나하나 적는다. 금액은 정수(원). 날짜는 `YYYY-MM-DD`, 시각은 매장 시간대.

### 4.2 앱

- 새 기능 폴더 `lib/features/sales/{api,state,screens}`. `home` 이 탭으로 꽂는다(지금의 준비 중 안내를 바꾼다). **다른 기능 폴더를 import 하지 않는다** — 방문 상세·하루 화면·반려동물 상세로는 라우터 경로로 간다. 사진은 `mediaImagesProvider`, 공유는 `shareSheetProvider`.
- 탭 본문은 `AsyncBody`(불러오는 중·실패·당겨서 새로고침). 기간을 바꾸면 그 기간의 요약을 읽는다. 기간과 고른 칸은 화면 상태다(앱을 다시 열면 이번 달).
- 사장인지는 `isOwnerProvider` 로 본다.
- 막대·진행선은 직접 그린다(차트 패키지를 들이지 않는다). 큰 숫자는 기존 세리프 숫자 스타일(`AppBigDate` 가 쓰는 것)을 따른다. 고른 날 카드는 캘린더의 미리보기 글래스 카드와 같은 위젯·같은 규칙을 쓴다 — 글래스는 떠 있는 조작 계층에만(이 카드는 캘린더와 같은 예외 자리).
- 움직임은 기간을 바꿀 때 숫자·막대의 짧은 전환뿐이다.
- 문구는 해요체. 영문 장식(`November`, `Payment`, `Menu`, `Guests`, `Bookings`, `Weekday`, `Report`)은 목업을 따른다.

## 5. 보안·경계

| # | 시나리오 | 막는 것 |
|---|---|---|
| S1 | 직원이 매출을 본다 | 모든 `/sales/…` 가 `sales:read`. 앱은 직원에게 API 를 부르지 않는다(가리는 것은 서버다). |
| S2 | 다른 매장의 매출·아이가 섞인다 | 모든 조회가 `ShopContext` 의 `shop_id` 로 거른다. 통합 테스트의 첫 줄은 테넌트 격리다. `menu_id` 가 남의 매장 것이면 빈 목록. |
| S3 | 익명화한 고객·삭제한 아이가 얼굴·단골·목록에 나온다 | 매출 합계에는 남고(돈은 있었다) 이름·사진이 드는 곳(얼굴, 단골, 메뉴의 사진, 고른 날 카드, 다시 올 때가 지난 아이, 방문 목록의 이름)에서는 뺀다. |
| S4 | 범위 끝 입력으로 500 | `anchor` 는 2000-01-01~2100-12-31 만(밖이면 422), `cursor` 조작·`menu_id` 넘침은 422. 앞날의 기간은 빈 요약이다(오류가 아니다). |
| S5 | 큰 기간으로 서버를 무겁게 한다 | 기간은 넷뿐이고 가장 긴 것이 한 해다. 임의의 시작·끝을 받지 않는다. |
| S6 | 요약 공유에 개인정보가 나간다 | 글에 아이·보호자 이름과 번호가 없다(3.4). |
| S7 | 금액이 로그에 남는다 | 접근 로그에 본문을 남기지 않는 지금 규칙 그대로. 새로 로그를 더하지 않는다. |
| S8 | 자정·시간대 경계에서 하루가 어긋난다 | 날짜 자르기는 매장 시간대로만. 23:30 에 시작한 방문은 그날의 것이다. 테스트에 자정 앞뒤 방문을 둔다. |

## 6. 하지 않는 것과 나중

| 항목 | 까닭·때 |
|---|---|
| 직원별 매출 | 예약에 담당 미용사가 없다(③ 결정). |
| 이번 달 예상 매출 | 메뉴에 기본 가격이 없다. "남은 예약 N건"만 보인다. |
| 엑셀·CSV 파일 | 파일 공유 채널이 없다. 글 요약으로 먼저. |
| 부가세·현금영수증 계산, 외상·선결제·환불 | 세무 판단·결제 추적이 필요하다. |
| 시간대별 매출, 업계 평균과 비교 | 예약제라 캘린더에 보인다 / 믿을 기준 수치가 없다. |
| 주간 요약 알림 | 푸시가 없다. |
| 다시 올 때가 지난 아이에게 알림 보내기 | 알림톡 실발송을 붙일 때. |
| 임의 기간(시작·끝 지정), 8주 기준 바꾸기, 달마다 다른 목표 | 필요하다는 말이 나오면. |
| 포인트 색 | 앱 전체의 톤을 다시 볼 때. |

## 7. 검증

- **백엔드**: 단위(스텁 포트) — 낱말의 뜻 하나하나(매출에 드는 방문, 빠진 금액, 조정, 미선택, 평균의 버림, 처음·다시, 비교의 같은 길이, 작년 줄의 유무, 빈 기간, 다시 올 때의 다섯 조건). 실제 DB — 날짜 자르기(자정 앞뒤·주의 월요일 시작·월말·윤년 2월·연말), 기간 넷의 경계, 쪽 나눔, 익명화·삭제한 아이가 빠지는 곳과 남는 곳. 통합 — 테넌트 격리, 직원 403, 범위 끝 입력 422, 합이 맞는지(결제 수단 합 = 메뉴 합 + 조정 = 매출 = 칸의 합). 구조 — 라우트 표 전후 비교, 로그인 없는 경로 목록 불변, 스키마 대조. 흐름 스크립트 `check_sales_flow.sh`(게이트웨이 경유 — 방문 몇 개를 만들고 요약의 숫자를 손계산과 견준다).
- **앱**: 위젯 — 기간 바꾸기, 비교 문장의 세 갈래와 없음, 목표 유무, 빈 기간, 직원 안내, 고른 칸과 카드, 조정·미선택 줄의 유무, 사진 없는 아이. 골든 — 월 보기 위·아래, 빈 기간. 시뮬레이터 흐름 — 준비한 방문들의 합이 화면의 숫자와 같다, 금액 없는 방문을 채우면 숫자가 는다, 다시 올 때가 지난 아이 → 상세, 목표 정하기, 직원에게는 안내만.
- 새 규칙마다 변이 한 번.

## 9. 내가 정한 것 (사용자가 따로 말하지 않은 것)

- 주는 월요일 시작, 방문한 날 기준 하나, 금액이 빈 완료 방문은 0 이 아니라 빠진 것(3.1).
- 조정·미선택 줄(3.1) — 합이 서로 맞게.
- 다시 올 때가 지난 아이의 기준 8주~1년, 고정값(3.3).
- 목표는 매달 같은 값 하나이고 이번 달에만 보인다(3.5). 달마다 다른 목표·이력은 나중.
- 알림장의 "보냈다"는 한 번이라도 만든 적이 있다는 뜻(3.2 의 14).
- 단골은 보고 있는 기간이 든 해 기준(3.2 의 10).
- 요약 공유의 글 모양과 이름·번호를 넣지 않는 것(3.4).
- 계획을 셋으로 나눈 것(8절).

## 10. 만드는 사람에게 맡기는 것

- 요약 하나를 SQL 몇 번으로 나눠 읽을지, 인터랙터·저장소 메서드를 어떻게 쪼갤지.
- 고른 날 카드의 아이들을 요약에 실을지 하루 목록 조회로 읽을지(4.1).
- 단골·얼굴의 동률 처리(같은 횟수면 최근에 온 아이가 앞).
- 막대의 정확한 치수와 전환 시간(목업의 비율을 따른다).
- 응답 칸의 이름.
