## 1. 목표

사장님이 미용을 끝낸 방문에서 버튼 두 번으로 알림장 링크를 만들어 공유 시트로 카카오톡에 보낸다. 보호자는 앱도 로그인도 없이 링크를 눌러 사진·영상·케어 메모를 보고 내려받는다.

지금 코드에는 공개 표면, 토큰, 웹 프론트가 없다. `visit_records.care_note`(공개 메모)와 `visit_state.py`의 "⑤에서 더해진다" 주석만 자리를 잡고 있다.

이 문서가 끝나면:

1. 완료된 방문에서 알림장 링크를 만들고, 끊고, 다시 공유할 수 있다.
2. 링크를 열면 서버 렌더링된 알림장 페이지가 나오고, 카카오톡 대화방에는 대표 사진과 이름이 든 미리보기 카드가 뜬다.
3. 매장이 링크 기간과 보여 줄 항목을 설정하고, 그 설정은 바꿀 때까지 매장의 기본값으로 남는다.
4. 공개 응답에는 공개하기로 한 것만 들어간다. 내부 메모·결제 수단·보호자 이름·전화번호는 어떤 설정에서도 나가지 않는다.
5. 살아 있는 링크가 있는 방문은 되돌리거나 기록을 지울 수 없다.

## 2. 사용자와 정한 것 (2026-09-28)

| 주제 | 결정 |
|---|---|
| 링크 기간 | 매장이 설정에서 고른다 — 7일·30일·계속(무기한). 기본 30일 |
| 실리는 사진·영상 | 기본은 전부. 보내기 전 미리보기에서 빼고 싶은 것만 뺀다 |
| 함께 보여 줄 항목 | 메뉴 이름·금액·몸무게·매장 정보를 모두 만들고 매장이 켜고 끈다. 한 번 정하면 바꿀 때까지 유지 |
| 항목의 처음 값 | 메뉴 이름·매장 정보 켬, 금액·몸무게 끔 |
| 보낸 뒤 기록 수정 | 같은 링크에 바로 반영. 알림장은 기록을 비추는 창이다 |
| '보냄' 판정 | 링크를 만든 시점. 공유 시트에서 실제로 보냈는지는 앱이 알 수 없다 |
| 끊기·재발급 | 끊거나 기간이 지나면 옛 링크는 영영 안 열리고 방문은 '안 보냄'으로 돌아간다. 다시 보내면 주소가 다른 새 링크. 살아 있는 동안 다시 공유하면 같은 링크 |
| 미리보기 카드 | 미용 후 대표 사진 + "○○의 미용 알림장" + 날짜·매장 이름 |
| 열람 확인 | 처음 연 시각만. 횟수·접속 주소·기기 정보는 저장하지 않는다 |
| 웹 방식 | Next.js 서버 렌더링, 저장소의 `web/`, Vercel. 조사 근거는 12절 |
| 토큰 저장소 | 링크는 Postgres. Redis 는 횟수 제한에만 쓴다. 조회 결과 캐시는 두지 않는다 |
| 권한 | 보내기·끊기는 `record:write`(직원 가능), 알림장 설정 변경은 `shop:update`(사장만) |
| 앱 화면 | 전부 네이티브. 웹뷰 패키지를 넣지 않는다 |
| 미루는 것 | CloudFront 서명 URL, 서버 측 EXIF 검증, 실제 Vercel 배포(10절) |

## 3. 구조와 흐름

### 3.1 구성 요소

| 요소 | 위치 | 하는 일 |
|---|---|---|
| 백엔드 | `backend/apps/visit` | 링크 발급·끊기, 알림장 설정, 공개 조회, 열람 기록 |
| 웹 | `web/` | 알림장 페이지 한 장, 미리보기 정보, 닫힌 링크·오류 화면. 데이터를 저장하지 않는다 |
| 앱 | `app/lib/features/visit` | 미리보기, 공유 시트, 보냄 표시, 알림장 설정 |

알림장은 새 스포크가 아니다. 방문 애그리거트 위에 쌓인다(기반 설계).

### 3.2 보내는 흐름

1. 완료된 방문 상세에서 [알림장 보내기].
2. 앱이 `GET …/report` 로 받은 내용을 네이티브 미리보기로 그린다. 사진·영상은 모두 선택된 상태이고 누르면 빠진다.
3. [보내기] → `PUT …/report`. 서버가 뺀 사진을 저장하고 링크를 만든다. 이 시점부터 '보냄'이다.
4. 앱이 응답의 `url` 을 OS 공유 시트에 넘긴다.

### 3.3 보는 흐름

1. 보호자가 `{REPORT_WEB_BASE_URL}/r/{token}` 을 연다.
2. 웹 서버가 토큰을 헤더에 실어 백엔드 공개 API 를 부른다.
3. 백엔드가 토큰을 검증하고, 매장 설정에서 켠 항목과 빼지 않은 미디어만 골라 새로 서명한 주소와 함께 돌려준다.
4. 웹 서버가 HTML 과 미리보기 정보(OG 태그)를 만들어 보낸다.
5. 페이지가 브라우저에서 열리면 스크립트가 웹 서버의 경로를 거쳐 열람 신호를 보낸다. 브라우저는 백엔드를 직접 부르지 않는다.

### 3.4 스포크 경계

- 공개 조회에는 로그인한 사용자가 없어 `ShopAccessPort.resolve(user_id, shop_id)` 를 쓸 수 없다. 허브 포트 `ShopProfilePort.public_profile(shop_id)` 를 더한다 — 이름·전화·주소·시간대·영업 중 여부. tenancy 가 구현하고 `main.py` 가 꽂는다.
- 공개 조회용 `ShopContext` 는 링크의 방문에서 읽은 매장 ID 와 `public_profile` 의 시간대로 만든다. 권한은 비어 있다.
- `MediaLibraryPort.read_urls` 의 `MediaUrls` 에 내려받기용 주소를 더한다. 브라우저의 `download` 속성은 다른 출처의 파일에 동작하지 않으므로 서명에 `response-content-disposition=attachment` 를 넣은 주소가 따로 필요하다. 서명 시각 규칙(가장 최근 04:00, 48시간)은 그대로다.
- 반려동물 이름은 `CustomerDirectoryPort.briefs` 로 읽는다.
- 익명화는 기존 `VisitLedgerPort.clear_customer_memos` 가 살아 있는 링크도 함께 끊는다(7.4).

## 4. 데이터 모델 (3NF, 마이그레이션 0010)

### 4.1 새 표 `visit_reports`

링크 하나가 한 줄이다.

| 칸 | 형식 | 뜻 |
|---|---|---|
| `id` | bigint PK | |
| `visit_id` | FK → `visits.id` ON DELETE CASCADE | 매장은 방문에서 읽는다 |
| `public_id` | bytea(16), 유일 | 토큰의 앞부분. `secrets.token_bytes(16)` |
| `expires_at` | timestamptz, null 가능 | null 이면 무기한. 발급 때 매장 설정으로 계산해 고정 |
| `revoked_at` | timestamptz, null 가능 | 끊은 시각 |
| `first_viewed_at` | timestamptz, null 가능 | 처음 연 시각 |
| `created_by_member_id` | bigint | tenancy 의 멤버 ID. 외래 키 없음 |
| `created_at` | timestamptz | 보낸 시각 |

- 부분 유일 색인 `uq_visit_reports_live (visit_id) WHERE revoked_at IS NULL` — 방문당 끊지 않은 줄은 하나.
- '살아 있음' = `revoked_at IS NULL AND (expires_at IS NULL OR expires_at > now)`. 색인에 현재 시각을 넣을 수 없으므로, 발급은 기간이 지난 줄을 먼저 `revoked_at = now` 로 닫고 새 줄을 넣는다.
- '보냄' 여부는 저장하지 않는다. 살아 있는 줄이 있는지로 계산한다.
- CHECK: `expires_at IS NULL OR expires_at > created_at`.

### 4.2 `visit_record_media` 에 칸 추가

`hidden_from_report boolean NOT NULL DEFAULT false` — 뺀 사진 표시. 링크가 아니라 사진에 붙는다. 링크를 끊고 새로 보내도 뺀 사진은 빠져 있다.

### 4.3 `visit_shop_settings` 에 칸 추가

| 칸 | 형식 | 기본값 |
|---|---|---|
| `report_link_days` | smallint, null 가능. CHECK `IN (7, 30)` 또는 null | 30 |
| `report_show_menus` | boolean | true |
| `report_show_shop_info` | boolean | true |
| `report_show_weight` | boolean | false |
| `report_show_amount` | boolean | false |

- 기간 설정을 바꿔도 이미 보낸 링크의 `expires_at` 은 그대로다.
- 보여 줄 항목은 조회할 때마다 읽으므로 이미 보낸 알림장에도 바로 적용된다.

### 4.4 3NF 점검

- `visit_reports` 에 `shop_id` 를 두지 않는다. 방문에서 나온다.
- 링크 주소를 저장하지 않는다. `public_id` 와 서버 키로 계산한다.
- 공개 항목 설정은 매장의 속성이라 매장 설정 표에, 뺀 사진은 (방문, 미디어)의 속성이라 기록 미디어 표에 둔다.

## 5. 토큰

```
token = base64url( public_id(16) ‖ HMAC-SHA256(REPORT_LINK_KEY, public_id)[:16] )   # 43글자, 패딩 없음
```

- DB 에는 `public_id` 만 있다. 토큰은 서버가 요청 때마다 다시 계산하므로 살아 있는 링크를 다시 공유할 수 있고, DB 만 유출되어서는 링크를 열 수 없다.
- 검증 순서: 길이 43·문자 집합 확인 → 디코딩 → 서명을 `hmac.compare_digest` 로 비교 → `public_id` 로 줄 찾기. 앞 세 단계에서 떨어지면 DB 를 읽지 않고 404 다.
- `REPORT_LINK_KEY` 는 `core/singleton/secret_manager.py` 로 읽는 API 프로세스의 비밀값이다. 32바이트 이상. `generate_dev_env.py` 가 개발용 값을 만든다.
- 키를 바꾸면 모든 링크가 한꺼번에 닫힌다. 키 교체 절차는 이번에 만들지 않는다.
- 토큰 계산·검증은 `visit/domain/services/report_token.py` 의 순수 함수다. 키는 인자로 받는다.

## 6. API

### 6.1 매장용 (로그인 필요)

| 주소 | 권한 | 하는 일 |
|---|---|---|
| `GET /v1/shops/{shop_id}/visits/{visit_id}/report` | 멤버 | 미리보기 — 보호자가 볼 내용, 미디어마다 `hidden`, 링크 상태 |
| `PUT /v1/shops/{shop_id}/visits/{visit_id}/report` | `record:write` | 본문 `{hidden_media_ids: [int]}`. 뺀 사진을 저장하고, 살아 있는 링크가 없으면 만든다 |
| `DELETE /v1/shops/{shop_id}/visits/{visit_id}/report` | `record:write` | 살아 있는 링크를 끊는다. 없으면 404 `REPORT_NOT_FOUND` |
| `GET /v1/shops/{shop_id}/report-settings` | 멤버 | 알림장 설정 |
| `PUT /v1/shops/{shop_id}/report-settings` | `shop:update` | 알림장 설정 전체 교체 |

- `PUT …/report` 하나가 처음 보내기·다시 공유·보낸 뒤 사진 빼기를 맡는다. 같은 본문으로 여러 번 불러도 결과가 같다.
- 링크 상태 응답: `{status: "none" | "live", url, expires_at, first_viewed_at, created_at}`. `none` 이면 나머지는 null.
- 미리보기의 "보호자가 볼 내용"은 공개 조회와 같은 조립 함수(`app/services/report_reader.py`)가 만든다. 매장용은 뺀 미디어도 `hidden: true` 로 함께 준다.
- 쓰기(PUT·DELETE)는 기존 방문 쓰기와 같은 잠금을 거친다 — `visit_locking.lock_visits`(고객 행 → 방문 행).

| 오류 | 상황 |
|---|---|
| 404 `VISIT_NOT_FOUND` | 없는 방문, 다른 매장의 방문 |
| 409 `VISIT_NOT_COMPLETED` | 완료가 아닌 방문에 PUT |
| 409 `VISIT_NO_RECORD_YET` | 기록이 없는 방문에 PUT(기존 코드) |
| 422 `REPORT_EMPTY` | 빼지 않은 미디어가 없고 케어 메모도 없다 |
| 422 | `hidden_media_ids` 에 이 기록의 것이 아닌 ID, 중복, 33개 초과, bigint 범위 밖 |
| 422 | `report_link_days` 가 7·30·null 밖, 켬·끔이 불리언이 아님(`StrictBool`) |

### 6.2 기존 응답에 더하는 것

- 방문 상세: `report`(6.1 의 링크 상태).
- 하루 목록·피드의 방문: `report_sent: bool`. 방문 여러 개의 링크는 한 번에 읽는다. 달력은 날짜 칸이 방문 단위가 아니라 바꾸지 않는다.
- 되돌리기(`POST …/visits/transitions` 의 `revert`)와 기록 삭제(`DELETE …/record`): 살아 있는 링크가 있으면 409 `VISIT_REPORT_SENT`.

되돌리기 금지는 상태 클래스에 둔다. `Visit` 에 `has_live_report: bool` 을 더하고(잠금 뒤 다시 읽을 때 채운다) `CompletedState.revert` 가 이를 보고 거절한다.

### 6.3 공개 (로그인 없음)

| 주소 | 헤더 | 응답 |
|---|---|---|
| `GET /v1/public/report` | `X-Report-Token` | 200 / 404 `REPORT_NOT_FOUND` / 410 `REPORT_CLOSED` / 429 |
| `POST /v1/public/report/viewed` | `X-Report-Token` | 204 / 404 / 410 / 429 |

토큰을 경로가 아니라 헤더로 받는다. 경로에 두면 백엔드와 게이트웨이(Caddy)의 접속 기록에 남는다.

**200 응답**

| 칸 | 조건 |
|---|---|
| `pet_name`(보호자만의 방문이면 null), `visit_date`(매장 시간대의 날짜) | 항상 |
| `care_note` | 항상. 비어 있으면 null |
| `media[]` — `kind`, `phase`, `width`, `height`, `duration_seconds`, `display_url`, `thumb_url`, `download_url` | `hidden_from_report = false` 인 것. 후 → 전, 그 안에서 `sort_order` |
| `cover` — `url`, `width`, `height` | 빼지 않은 미디어 가운데 기존 대표 규칙(후 → 전 → 영상 포스터). 없으면 null |
| `menus[]` — `name` | `report_show_menus` |
| `menus[].amount`, `total_amount` | `report_show_amount`. 메뉴를 끄고 금액만 켜면 `total_amount` 만 |
| `weight_kg` | `report_show_weight`. 기록에 없으면 null |
| `shop` — `name`, `phone`, `address` | `report_show_shop_info` |
| `expires_at` | 항상. 무기한이면 null |

끈 항목은 값이 null 이 아니라 칸 자체가 응답에 없다. 응답 스키마에는 내부 메모·결제 수단·예약 메모·보호자 이름·전화번호·각종 ID(방문·고객·반려동물·미디어·매장)의 칸이 없다.

**410** 은 끊은 링크, 기간이 지난 링크, 정지·폐업한 매장의 링크다. 본문은 `{code, message}` 뿐이다.

**열람 신호**는 `UPDATE visit_reports SET first_viewed_at = now WHERE id = … AND first_viewed_at IS NULL` 한 줄이다. 닫힌 링크에는 기록하지 않는다. 잠금을 잡지 않는다.

## 7. 보안과 오류 처리

### 7.1 추측과 남용

| 장치 | 내용 |
|---|---|
| 토큰 크기 | 무작위 128비트 + 서명 128비트 |
| 횟수 제한 | 접속 주소별 분당 60회, 넘으면 429. 실패(404)는 10분에 20회 — 넘으면 서명이 틀린 요청만 429 이고 서명이 맞는 토큰은 막지 않는다(결정 기록 008). Redis 고정 창 계수기 — `invite_attempt_redis_limiter.py` 와 같은 모양 |
| Redis 장애 | 제한 없이 통과시키고 경고 로그를 남긴다. 토큰 크기가 1차 방어다 |

백엔드가 보는 상대는 보호자가 아니라 웹 서버다. 웹 서버는 보호자의 접속 주소를 `X-Report-Client-IP` 로, 공유 비밀값을 `X-Report-Web-Secret` 으로 보낸다. 백엔드는 비밀값(`REPORT_WEB_SECRET`, `secret_manager`)이 맞을 때만 그 주소로 세고, 아니면 연결된 주소로 센다. 비밀값이 없는 요청도 받는다 — 공개 API 는 비밀값이 아니라 토큰이 지킨다.

### 7.2 웹 페이지가 지킬 것

| 항목 | 이유 |
|---|---|
| `X-Robots-Tag: noindex, nofollow` 와 같은 메타 태그 | 검색 결과에 나오지 않게 |
| `Cache-Control: private, no-store` | 끊은 링크가 중간 캐시에 남지 않게 |
| `Referrer-Policy: no-referrer` | 토큰이 든 주소가 다른 사이트로 넘어가지 않게 |
| 외부 분석·광고·글꼴 스크립트 없음 | 토큰이 든 주소를 제3자에게 보내지 않는다. 글꼴은 직접 싣는다 |
| 웹 서버 코드가 토큰을 로그에 찍지 않는다 | Vercel 자체 접속 기록에는 주소가 남는다. 피할 수 없어 감수한다 |

### 7.3 보호자에게 보이는 오류

| 백엔드 응답 | 화면 | 웹의 상태 코드 |
|---|---|---|
| 404, 형식이 틀린 토큰 | "알림장을 찾을 수 없어요" | 404 |
| 410 | "닫힌 알림장이에요" + "기간이 지났거나 매장에서 닫은 알림장이에요. 매장에 다시 요청해 주세요." 매장 정보 없음 | 200 |
| 429 | "잠시 후 다시 열어 주세요" | 200 |
| 연결 실패·5xx·그 밖 | "잠시 후 다시 열어 주세요" | 200 |

상태 코드는 200 과 404 뿐이다 — 2026-09-29 사용자와 정함, 결정 기록 008. App Router 페이지는 410·429·503 을 낼 수 없다. 형식이 틀린 토큰(`^[A-Za-z0-9_-]{43}$` 가 아님)은 웹이 백엔드를 부르지 않고 404 로 둔다.

오류 화면의 미리보기 정보는 일반 문구("차곡노트 미용 알림장")이고 사진이 없다.

### 7.4 다른 기능과 만나는 곳

| 상황 | 동작 |
|---|---|
| 기록 전체 교체·사진 덧붙이기 | `save` 가 미디어 줄을 지우고 다시 넣으므로, 인터랙터가 기존 `hidden_from_report` 를 미디어 ID 로 이어 붙인다. 새 미디어는 false |
| 고객 삭제(익명화) | `clear_customer_memos` 가 같은 트랜잭션에서 그 고객 방문의 살아 있는 링크를 끊는다 |
| 무지개다리 | 링크 유지 |
| 매장 정지·폐업 | 그동안 410. 풀리면 다시 열린다. 줄은 바꾸지 않는다 |
| 보낸 멤버가 매장을 떠남 | 링크 유지. 링크는 매장의 것이다 |
| 보낸 뒤 사진을 전부 빼거나 메모를 비움 | 막지 않는다. 페이지는 이름·날짜만 보인다. `REPORT_EMPTY` 는 링크를 새로 만들 때만 본다 |

### 7.5 위협 점검표

계획 ⑤-1 은 이 표의 줄마다 막는 코드와 테스트를 작업에 짝짓는다. 작업별 검토는 계획서와의 일치가 아니라 이 표를 기준으로 한다.

| # | 시나리오 | 막는 것 |
|---|---|---|
| R1 | 토큰을 마구 넣어 본다 | 토큰 크기 + 횟수 제한 |
| R2 | 다른 매장의 방문 ID 로 발급·끊기·미리보기 | `ShopContext` 로 방문을 찾는다 — 404 |
| R3 | 끊은 링크·기간 지난 링크를 연다 | 410, 데이터 없음 |
| R4 | 새 링크를 만들면 옛 링크가 되살아난다 | 줄이 다르고 `public_id` 가 다르다 |
| R5 | 기록 저장으로 뺀 사진이 공개된다 | 7.4 첫 줄 |
| R6 | 공개 응답에 내부 메모·결제 수단·전화번호·보호자 이름이 섞인다 | 스키마에 칸이 없다 + 표식 문자열 검사 |
| R7 | 설정에서 끈 금액·몸무게가 응답에 남는다 | 서버가 뺀다. 웹이 숨기는 것이 아니다 |
| R8 | 발급을 동시에 두 번 | 방문 행 잠금 + 부분 유일 색인 — 같은 링크 |
| R9 | 발급과 되돌리기·기록 삭제가 동시에 | 같은 잠금. 잠근 뒤 링크를 다시 읽는다 |
| R10 | 열람 신호가 동시에 여러 번 | 조건부 UPDATE |
| R11 | 닫힌 링크에 열람 신호 | 410, 기록 안 함 |
| R12 | 카카오톡 미리보기 로봇이 '열람'으로 찍힌다 | 열람 신호는 브라우저 스크립트가 보낸다 |
| R13 | 이상한 토큰 — 빈 값, 수천 글자, 한글, 깨진 base64, 헤더 없음 | 404. 500·422 가 아니다 |
| R14 | `hidden_media_ids` 에 남의 미디어 ID, 중복, 수천 개, 범위 밖 숫자 | 422 |
| R15 | 설정에 허용 밖의 기간, 문자열 불리언, 빠진 칸 | 422 |
| R16 | 직원이 알림장 설정을 바꾼다 | 403 |
| R17 | 위조한 접속 주소 헤더로 횟수 제한을 피한다 | 공유 비밀값이 맞을 때만 믿는다(`compare_digest`) |
| R18 | 토큰이 로그에 남는다 | 헤더 전달 + 로그 검사 |
| R19 | 익명화한 고객의 알림장이 계속 열린다 | 익명화가 링크를 끊는다 |
| R20 | 기간이 지난 링크가 부분 유일 색인에 걸려 새 링크를 못 만든다 | 발급이 먼저 닫는다 |
| R21 | 정지된 매장의 알림장이 열린다 | `public_profile` 의 영업 중 여부 — 410 |

### 7.6 막지 못하고 감수하는 것

1. 링크를 끊거나 사진을 빼도, 그 전에 미디어 서명 주소를 복사해 둔 사람은 최대 48시간 그 파일을 열 수 있다.
2. 카카오톡 대화방에 이미 뜬 미리보기 카드의 사진과 이름은 카카오 서버에 남는다.
3. 사장님이 링크를 직접 열어도 '확인함'으로 찍힌다.
4. 보호자가 링크를 남에게 넘기면 그 사람도 본다.
5. 앱을 거치지 않고 올린 사진의 EXIF 는 서버가 확인하지 않는다(10절).

## 8. 웹 (`web/`)

### 8.1 스택과 구조

- Next.js(App Router)·TypeScript·pnpm. 서버 컴포넌트가 백엔드를 부른다. 상태 관리·UI 라이브러리를 넣지 않는다.
- 경로는 `/r/[token]` 하나와 열람 신호용 경로 핸들러 `/r/[token]/viewed`(POST) 하나다. 루트(`/`)는 404 다 — 랜딩은 이번 범위가 아니다.
- 설정: `API_BASE_URL`(백엔드 주소), `REPORT_WEB_SECRET`. 둘 다 서버에서만 읽는다(`NEXT_PUBLIC_` 접두사를 쓰지 않는다). 둘 다 필수다 — 없으면 웹 서버가 요청을 받지 못한다(결정 기록 008).
- 개발: compose 에 `web` 서비스를 더한다(`next dev`, 호스트 포트 3010). 백엔드는 compose 안 이름(`http://backend:8000`)으로 부르고, `REPORT_WEB_SECRET` 은 백엔드와 같은 `.env` 에서 읽는다. 이때 미디어 서명 주소는 기존 공개 주소(`S3_PUBLIC_ENDPOINT_URL`)라 보호자 브라우저에서 열린다.
- 도메인을 바꿔도 옛 링크가 열리게 하는 일은 Vercel 설정(옛 주소 → 새 주소 리다이렉트)으로 하고, 백엔드는 `REPORT_WEB_BASE_URL` 만 바꾼다. 실제 배포는 이번 범위가 아니다(10절).

### 9.2 공유 시트 — `core/proxy/share_sheet.dart`

외부 패키지를 넣지 않고 기존 자체 채널 관례를 따른다. iOS 는 `UIActivityViewController`(아이패드는 앵커 사각형 필요), Android 는 `Intent.ACTION_SEND` + `createChooser`. 넘기는 것은 글자(주소)뿐이다. 결과(보냈는지·취소했는지)는 받지 않는다. iOS 는 글자를 `UIActivityItemSource` 로 넘기며 시트 머리에 보일 것(주소의 호스트)을 직접 준다 — 글자로만 넘기면 iOS 가 머리를 그리려고 그 주소를 받아 온다. Android 는 선택기에서 자기 앱을 뺀다(결정 기록 008).

### 9.3 상태와 API

- `features/visit/api/report_models.dart`·`report_api.dart`, 상태는 `features/visit/state/report_*.dart`.
- 발급·끊기 뒤에는 방문 상세·하루 목록·피드·미리보기의 해당 프로바이더를 무효화한다(기존 `visit_commands.dart` 방식). 실패해도 무효화한다.
- 보내기는 직전에 미리보기를 다시 읽어 서버의 지금 상태 위에 화면에서 누른 것만 덮어 보낸다(`hidden_media_ids` 가 "뺄 것 전부"라서 — 결정 기록 008).
- 409 `VISIT_REPORT_SENT` 는 되돌리기·기록 삭제 자리에서 "알림장을 보낸 방문이에요. 링크를 먼저 끊어 주세요." 로 안내한다. 나머지 오류는 오류 화면 다듬기 설계의 규칙을 따른다.
- 문구는 `l10n/app_strings.dart` 에 둔다(서버 오류 코드의 문구는 `core/error/error_messages.dart`).

### 11.5 실기기에서만 확인할 수 있는 것

지금 개발용 맥에는 연결된 아이폰이 없고 iOS 서명 팀도 설정되어 있지 않다(2026-09-28 확인). 아래는 실기기 확인 항목으로 남긴다.

1. 카카오톡 대화방에 미리보기 카드가 뜨는지, 사진이 잘리지 않는지 — 링크가 카카오 서버에서 닿는 주소여야 하므로 배포 뒤에만 확인할 수 있다
2. 카카오톡 내장 브라우저에서 저장이 되는지
3. 공유 시트에서 카카오톡으로 보낸 뒤 앱으로 돌아오는 동작
4. iOS Safari·Android Chrome 의 영상 재생과 모두 저장

⑤-2 웹을 만들며 더한 것(결정 기록 008). 개발 맥의 chromium 으로만 확인했다.

5. 모두 저장의 공유 시트 경로 — 시험 브라우저(chromium)에 `navigator.canShare` 가 없어 스텁으로만 확인했다. 미디어를 다 받는 동안 사용자 동작의 유효 시간이 지나는지, 저장소(MinIO·S3) 버킷에 CORS 가 없어 받기가 실패하는지
6. iOS Safari·카카오톡 내장 브라우저에서 여러 개를 차례로 내려받기
7. 크게 보기의 스크롤 잠금(`body` 의 `overflow: hidden`)이 iOS Safari 의 손가락 끌기에서도 막히는지, 영상 위에서 옆으로 밀 때 재생 막대와 겹치는지
8. iOS Safari·카카오톡 내장 브라우저가 열람 신호에 `Sec-Fetch-Site` 를 보내는지(보내지 않으면 통과한다)
9. 카카오 미리보기 로봇이 실제로 읽는 것(og 태그의 자리, 오류 화면에서 `<title>` 을 쓰는지), 대표의 서명이 만료된 뒤의 미리보기 그림
10. Vercel 에서 `x-forwarded-proto`·`host`(기본 미리보기 그림의 절대 주소), `x-forwarded-for`(접속 주소), 응답 헤더 셋이 실제로 어떤지
11. Android 에서 세리프(Didot)·명조가 무엇으로 바뀌어 보이는지
12. 뒤로 가기: Android 뒤로 몸짓·버튼, iOS Safari 가장자리 밀기, 카카오톡 내장 브라우저에서 크게 보기를 연 채 뒤로 가면 크게 보기만 닫히는지(e2e 는 `next dev` 위 chromium 에서만 돌았다)
13. 모두 저장의 메모리·데이터 양: 공유 경로는 미디어 전부(영상은 개당 최대 200MB)를 메모리로 받은 뒤 공유 시트를 연다 — 영상이 섞인 알림장에서 탭이 메모리 부족으로 죽거나 셀룰러 데이터를 크게 쓰는지, 받는 동안 사용자 동작의 유효 시간이 지나 공유가 거절되면 차례 내려받기가 같은 파일을 한 번 더 받는지

⑤-3 앱을 만들며 더한 것(결정 기록 008). iOS 시뮬레이터(27.0·26.5)와 Android 에뮬레이터(API 37)에서 공유 시트를 띄우는 것까지만 봤다 — 시트 안의 대상은 눌러 보지 못했다.

14. 공유 시트에서 대상을 실제로 누르기 — 카카오톡·메시지에 주소 글자가 그대로 넘어가는지, 복사한 글이 주소 그대로인지
15. iOS 공유 목록에 우리 공유 확장("차곡노트")이 남는지(시뮬레이터에서는 남았다), 누르면 알림장 링크가 카톡 초안 화면으로 들어오는지
16. iOS 공유 시트 머리 — 실기기에서도 주소를 받아 오지 않는지(받아 오면 보호자보다 먼저 페이지가 열린다), 그림 자리가 비어 보이는 것이 거슬리는지
17. 아이패드에서 공유 말풍선이 [보내기]·[다시 공유] 버튼에 붙는지(임시 화면의 버튼으로만 봤다), 화면 분할·회전
18. Android 실기기(제조사별 선택기)에서도 자기 앱이 대상에서 빠지는지
19. 3의 뒤 — 카카오톡으로 보내고 돌아왔을 때 방문 상세가 보낸 모습("완료 · 알림장 보냄", [다시 공유])인지, 미리보기가 닫힌 뒤 시트가 올라오는 순서가 어색하지 않은지
20. [다시 공유]를 빠르게 두 번 눌렀을 때 — 시트를 띄우는 중에 한 번 더 부르면 iOS 가 어떻게 하는지
21. 실제 사진 위에서 미리보기 타일의 체크·"뺌"·영상 표시가 읽히는지, VoiceOver·TalkBack 이 설정 스위치를 "켜짐/꺼짐"·"사용할 수 없음"으로 읽는지
