# ⑯ 들어오는 예약 — 네이버 예약 글 받기·전화 올 때 고객 표시(콜아이디)·화면 캡처에서 읽기 — 설계

2026-11-16. 경쟁 조사(`.superpowers/research/reports/펫미용 앱 경쟁 기능 비교.md`)의 10·11순위다. 세 기능은 서로 기대지 않는다 — **1부 글에서 예약 초안(네이버 예약 글 포함)**, **2부 콜아이디**(크다, 조건이 찰 때), **3부 화면 캡처에서 읽기**로 나눠 적는다. 만드는 순서는 1부 → 3부 → 2부다(13절).

공통 기준은 `2026-11-16-next-designs-common.md` 다. 이 문서와 어긋나면 공통 기준이 앞선다.

사용자가 정해 준 것: 과금되는 일과 외부 서비스 연결은 하지 않는다 · 통화 녹음과 콜봇은 하지 않는다 · 앱은 네이티브다(웹뷰 금지) · 주의 고객 정보는 매장 사이에 공유하지 않는다 · 자동화할 수 있는 것은 자동화하되 핵심 기능·설명·바꿀 길을 빼지 않는다 · 널리 쓰는 말(동기화 등)은 그대로 쓴다. **그 밖의 범위·방식·기준값은 내가 정한 것이다.**

## 1. 왜

예약은 카카오톡으로만 오지 않는다. 네이버 예약으로 들어온 것은 사장님이 달력에 손으로 옮겨 적고, 전화로 온 것은 받는 순간 누구인지 모른 채 "성함이…"부터 묻는다. 카카오톡 대화도 길면 글을 골라 복사하는 것이 번거롭다.

- **네이버 예약.** 공비서·뷰티인프라는 네이버 예약이 들어오면 달력에 자동 등록된다(각사 홍보 페이지 — 월 2만 원 안팎의 범용 도구다). 들어온 예약에 반려동물 정보는 없다(공비서 리뷰의 "반려동물 이름이 함께 표시되지 않는다"). 새 앱 띵동모아는 "네이버·인스타그램·전화 예약을 한 화면에"를 간판으로 삼았다(검색 요약으로만 확인 — 근거가 약하다). 정식 연동의 조건·비용·심사는 조사하지 못했다.
- **콜아이디.** 반짝은 안드로이드에서만 되고, iOS 요청이 2022-03·2022-04·2026-05 리뷰에 반복된다. 그루머노트는 릴리스 노트(3.14.0, 연도 추정)에 발신자 표시를 적었다. 티피는 기능 이름만 확인했다.
- **첫 매장에는 급하지 않다.** 첫 입점 매장은 예약을 전부 카카오톡으로 받는 1인 매장이다. 네이버 예약을 쓰는지는 모른다(15절의 가정). 전화 예약이 많다는 증언도 없다. 그래서 2부는 설계만 해 두고 계획을 쓰지 않는다(11절의 조건).

## 2. 지금 있는 것 (코드에서 확인)

- **글 → 예약 초안(③-A3).** `POST /v1/shops/{id}/visit-drafts`(`reservation:write`)가 1,000자까지의 글을 받아 날짜·시각·메뉴·보호자 후보를 돌려준다. 아무것도 저장하지 않는다. 해석은 `visit/domain/services/draft_parser.py`(순수 함수) — 날짜는 `오늘/내일/모레/글피`, `이번·다음 주 ○요일`, `○요일`, `M월 D일`, `M/D`, `D일`, 시각은 `오후 2시(반/N분)`, `2:30`, `2시`. 카카오톡 머리말(`[오후 2:31]`, `2026년 9월 24일 오후 2:31, `)은 지운다. **`2026.11.20`·`2026-11-20`·`11.20` 꼴은 읽지 못한다.**
- **"누구"** 는 글의 낱말(최대 20개, 4자리 숫자는 번호 뒷자리, 8자리 이상 숫자는 전체 번호)로 `CustomerDirectoryPort.find_draft_candidates` 가 찾는다(최대 5 가족). 응답의 번호는 가린 꼴(`phone_masked`)이다.
- **지난번처럼.** `GET …/visits/defaults` 가 그 아이의 지난 메뉴와 소요를 준다(금액은 싣지 않는다).
- **앱.** 예약 ① 위의 [카톡 붙여넣기](클립보드), 공유 받기(iOS 공유 확장 `ShareViewController.swift` + App Group `group.com.chagocnote.app` + `chagocnote://share`, 안드로이드 `ACTION_SEND` `text/plain`), 채널 `com.chagocnote.app/share`, 초안 화면 `/visits/draft`, 폼에 넘기는 `VisitPrefill`(`customerId`·`date`·`at`·`petIds`·`menus`). 공유 확장은 글만 받는다(주소 `public.url`·이미지는 받지 않는다). 기능 사이의 반대 방향 연결은 `lib/core/plugs/` 에 자리가 있다(`care_marks_plug.dart`·`pet_records_plug.dart`).
- **같은 예약 막기.** 같은 아이(보호자만이면 같은 보호자)의 같은 시각에 살아 있는 예약이 있으면 등록이 409 `VISIT_DUPLICATE` 다.
- **멤버가 빠지는 길.** `RemoveMemberInteractor`(사장이 내보냄)와 `ApplyWithdrawalInteractor`(회원 탈퇴 — `MembershipLifecyclePort` 의 구현, 인증 프로세스에서 돈다) 둘이다. **스스로 매장을 나가는 유스케이스는 없다.** 역할 바꾸기는 `ChangeMemberRoleInteractor` 다. 내보낸 멤버는 다음 요청부터 매장 가드에서 걸린다. `ShopContext` 에는 `role` 이 실려 있다.
- **없는 것.** 방문에 "어디로 들어온 예약인지"를 적는 칸이 없다. 전화번호는 `customers.phone`·`phone_alt`(숫자만, 11자까지)에 평문으로 있다(매장 안 유일은 `phone` 만). 고객 번호를 통째로 내려 주는 경로는 없다. 푸시가 없다. 기기에서 글자를 읽는 네이티브 코드가 없다.

## 2.5 편의 기준 (합격선 — 흐름 테스트로 확인한다)

| 하는 일 | 앱 안에서 누르는 횟수 | 조건 |
|---|---|---|
| 글 붙여넣기 → 예약 저장 | 3번 ([글 붙여넣기] → [예약 이어서] → [저장]) | 아는 고객, 글에 날짜·시각이 있음 |
| 다른 앱에서 글 공유 → 예약 저장 | 2번 ([예약 이어서] → [저장]) | 위와 같음 |
| 다른 앱에서 캡처 공유 → 예약 저장 | 2번 | 위와 같음 |
| 앱에서 캡처 고르기 → 예약 저장 | 4번 ([캡처에서 읽기] → 사진 고르기 → [예약 이어서] → [저장]) | 위와 같음 |
| 처음 온 손님 | 번호·이름을 손으로 적지 않는다 | 글에 번호·이름이 있음 |

- **같은 것을 두 번 적지 않는다**: 아는 고객이면 아이·지난번 메뉴·소요가 채워져 있다(4.2).
- **빈칸을 내보내지 않는다**: 못 읽은 칸은 초안 화면에서 `못 읽었어요 · 골라 주세요` 로 묻고, [예약 이어서]는 폼의 그 칸에서 연다. 채운 값은 전부 고칠 수 있고, 앱이 채운 값에는 `짐작`·`지난번처럼` 표시가 붙는다.
- **읽은 글을 고칠 수 있다**: 초안 화면에 읽은 글이 접힌 채 있고, 펴서 고친 뒤 [다시 읽기]를 누르면 다시 해석한다(캡처에서 글자를 잘못 읽었을 때의 길).

# 1부 — 글에서 예약 초안 (네이버 예약 글 포함)

## 3. 목표와 하지 않는 것

**목표**

- 네이버 예약 알림 글(톡톡·문자·스마트플레이스 앱의 예약 내용)을 **붙여넣거나 공유하면** 지금의 초안 화면이 채워진다. 새 화면을 만들지 않는다.
- **아는 고객이면 번호로 찾아 아이와 지난번 메뉴까지 채운다.** 네이버가 주지 않는 반려동물 정보를 매장의 기록이 메운다.
- **처음 보는 번호면** 글의 이름·번호로 새 고객 등록 칸을 미리 채우고, **문진표 링크 보내기를 바로 권한다**(⑪).
- 같은 예약을 두 번 넣지 않게 **넣기 전에 알린다**.
- 예약에 "네이버로 들어옴"을 남겨, 앱에서 바꾸거나 취소할 때 **네이버에서도 바꿔야 한다**는 것을 잊지 않게 한다.

**하지 않는 것**

| 항목 | 까닭·때 |
|---|---|
| 네이버 예약 정식 연동(자동 등록·변경·취소 반영) | 제휴 조건·비용·심사를 모른다. 외부 서비스 연결이다. 5.4 의 "확인할 것"을 푼 뒤 따로 설계한다. |
| 안드로이드 알림을 읽어 자동으로 초안 만들기 | 알림 접근 권한은 스토어 정책 위험이 크다(2026-09-22 메시지 수집 아이디어에서 정리한 것). |
| 받은 주소를 서버가 열어 보기 | 외부 호출 없음. 주소(`public.url`)는 여전히 받지 않는다 — 로그인이 필요한 페이지라 열어도 쓸 것이 없다. |
| 초안을 자동으로 저장 | 지금 규칙 그대로다 — 사람이 확인한 뒤 저장한다(공통 2절). |
| 취소·변경 알림 글로 예약을 자동으로 고치기 | 예약의 취소는 사람이 누른다. 그 날의 예약을 보여 주기만 한다(4.5). |
| 인스타그램 DM 등 다른 창구의 전용 규칙 | 견본이 없다. 일반 글은 지금 해석기로 읽힌다. |
| 창구별 매출 통계 | 칸만 남긴다(4.6). 통계는 필요하다는 말이 나오면 ⑧에 더한다. |

**이렇게 되면 실패다**: 네이버 글의 "보낸 날짜"를 예약 날짜로 읽는다 · 취소 알림을 붙여넣었더니 새 예약이 생긴다 · 예약 확정 글의 "취소·변경은 …" 안내 때문에 모든 글이 취소 알림으로 뜬다 · 안심번호가 고객 번호로 저장된다 · 견본 없이 지어낸 형식 규칙이 실제 글과 달라 틀린 날짜를 "짐작 아님"으로 보인다 · 글이나 번호가 로그에 남는다.

## 4. 무엇을 만드나

### 4.1 견본 없이 하는 것과 견본이 오면 더할 것

**실제 네이버 예약 알림 글의 모양을 나는 모른다. 지어내지 않는다.** 그래서 둘로 나눈다.

| | 견본 없이 (이번) | 견본이 오면 (더한다) |
|---|---|---|
| 출처 알아보기 | 글에 `네이버 예약`·`네이버예약`·`스마트플레이스` 가 있으면 네이버 글로 본다 | 실제 머리말·꼬리말로 굳힌다 |
| 날짜 | 지금 것에 더해 `YYYY.MM.DD`, `YYYY-MM-DD`, `YYYY년 M월 D일`, `MM.DD`(뒤에 요일 괄호가 붙어도) | 보낸 날짜·신청 일시 줄을 지우는 규칙 |
| 시각 | 지금 것 그대로(`오후 2:00`, `14:00`, `2시`) | `14:00~15:30` 같은 범위에서 소요를 읽기 |
| 이름표 줄 | `이름표 : 값` / `이름표: 값` 꼴의 줄을 읽는다. 이름표 사전은 작게 — 예약자·예약자명·이름·성함 / 연락처·전화번호·휴대폰 / 예약일시·이용일시·일시·날짜·시간 / 상품·예약상품·메뉴 / 요청사항 | 실제 이름표로 사전을 고친다 |
| 누구 | 전체 번호(8자리 이상 숫자, 하이픈 포함)와 이름으로 후보 찾기 — 지금 그대로. **안심번호는 쓰지 않는다**(4.3) | 네이버가 안심번호를 주는지 확인한다 |
| 메뉴 | 매장 메뉴표의 이름이 글에 있으면 고른다 — 지금 그대로. 없으면 지난번 메뉴(4.2) | 네이버 상품 이름 → 매장 메뉴 대응 |
| 취소·변경 알림 | 좁은 꼴만, 늘 짐작(4.5) | 실제 취소·변경 글의 머리말로 굳힌다 |
| 예약 번호 | 읽지 않는다 | 읽어서 중복 막기에 쓴다(4.4) |

- 이름표 줄에서 읽은 날짜·시각은 본문에서 읽은 것보다 **앞선다**. 이름표 사전에 없는 줄은 지금처럼 본문으로 읽는다.
- **견본 없이 읽은 네이버 글의 날짜·시각은 늘 "짐작"으로 표시한다**(이름표 줄에서 읽었어도). 견본으로 규칙을 굳힌 뒤에 짐작 표시를 뗀다.
- 이름표 사전은 일반 양식의 흔한 말이지 네이버의 실제 말이 아니다 — 맞는지는 견본으로만 안다.
- 새 날짜 꼴과 ③-A3 가 미룬 `N일 뒤` 오독("3일 뒤" → 3일) 고치기는 **네이버와 무관하게 필요한 보강**이다. 네이버 예약을 쓰지 않는 매장에도 들어간다.

### 4.2 아는 고객 — 아이와 지난번 메뉴까지 채운다

- 후보가 **한 가족으로 좁혀지면** 초안 응답에 그 가족의 아이들과, 아이마다의 지난번 메뉴·소요(`visits/defaults` 와 같은 값)를 싣는다.
- 아이 고르기: 글에 아이 이름이 있으면 그 아이 → 아이가 한 마리면 그 아이 → 여럿이고 글에 이름이 없으면 **고르지 않고 묻는다**(`어느 아이인가요?` — 틀린 아이를 채우는 것보다 한 번 묻는 것이 낫다).
- 메뉴 고르기: 글에서 읽은 메뉴 → 없으면 그 아이의 지난번 메뉴와 소요(`지난번처럼` 표시) → 그것도 없으면 매장의 기본 메뉴(지금 폼의 규칙 그대로).
- 후보가 여럿이면 지금처럼 고르게 하고, 고른 뒤에 위의 채우기를 한다.
- 채운 값은 전부 초안 화면과 폼에서 고칠 수 있다.

### 4.3 처음 온 손님

- 초안 응답에 **글에서 읽은 연락처**(`contact: {name|null, phone|null, phone_kind}`)를 싣는다. 이름은 이름표 줄(`예약자`류)에서만, 번호는 전체 번호 하나만 읽는다. 카카오톡 글에서도 전체 번호가 있으면 번호는 실린다.
- **안심번호는 채우지 않는다.** `050` 으로 시작하는 번호(0502~0508 등)는 `phone_kind: "relay"` 로 표시하고, 후보 찾기와 새 고객 등록 미리 채움에 쓰지 않는다. 초안 화면에 `안심번호라서 채우지 않았어요 · 실제 번호를 여쭤봐 주세요` 를 보인다. 안심번호가 고객 번호로 저장되면 알림톡·콜아이디·번호 조회가 전부 틀어진다. (050 이 안심번호 대역이라는 것은 내가 아는 사실이다 — **구현 전에 대역을 다시 확인한다.**)
- 후보가 없으면 초안 화면에 두 가지를 권한다.
  1. **[새 고객 등록]** — ①(번호)·②(보호자 이름)에 미리 채운다. **미리 채움은 ⑪ 이 만든 고객 등록 미리 채움 형을 쓴다**(새 형을 만들지 않는다 — 공통 11절). 반려동물 정보는 채우지 않는다(글에 있는지 모른다).
  2. **[문진표 보내기]** — ⑪ 의 새 손님용 서류 링크를 만들어 보낼 것 묶음(공통 4절)에 문진표 토막으로 싣는다. 보호자가 적어 보내면 ⑪ 의 "받은 문진표"로 들어온다. 네이버가 주지 않는 아이 정보를 여기서 받는다.
- 고객을 등록하지 않고 예약만 잡을 수는 없다(지금 규칙). 그래서 순서는 [새 고객 등록] → 예약 저장 → 보낼 것 묶음(접수 안내 + 문진표 링크)이다.
- 이 값은 요청으로 온 글에서 나온 것이라 새로 드러나는 정보가 아니다. 그래도 로그·오류 응답에 싣지 않는다.

### 4.4 같은 예약을 두 번 넣지 않기

- **넣기 전에 알린다.** 후보가 한 가족으로 좁혀지고 날짜를 읽었으면, 응답에 그 가족의 **그 날 살아 있는 예약**(`same_day_visits: [{visit_id, starts_at, pet_names}]`)을 싣는다. 초안 화면이 날짜 줄 아래에 `이 날 예약이 이미 있어요 · 14:00 콩이` 를 보이고, 누르면 그 방문 상세로 간다. [예약 이어서]는 그대로 눌린다(막지 않는다 — 하루에 두 번 올 수도 있다).
- **넣을 때 막는다.** 같은 아이·같은 시각이면 지금의 409 `VISIT_DUPLICATE` 가 막는다. 고치지 않는다.
- **예약 번호로 막기는 견본 뒤다.** 번호의 꼴을 알아야 읽는다. 그때 `visits` 에 바깥 예약 번호 칸을 더하고 매장 안에서 유일하게 한다.

### 4.5 취소·변경 알림 — 낱말 하나로 판정하지 않는다

- `취소` 라는 낱말이 있다고 취소 알림으로 보지 않는다. 예약 확정 글에도 "취소·변경은 …에서" 같은 안내가 들어 있을 수 있다.
- 취소 알림으로 **짐작하는** 꼴은 좁다: 네이버 글이고, `예약이 취소`·`취소되었`·`취소됐`·`취소 완료`·`예약 취소 안내` 가운데 하나가 있다. `취소·변경`·`취소 시`·`취소 규정`·`취소 수수료`·`취소는` 처럼 **안내에 쓰이는 꼴만 있으면 취소 알림이 아니다.**
- 견본 전에는 이것도 **짐작**이다: 응답에 `notice: "cancel"` 과 `guessed.notice: true` 를 싣고, 초안 화면 맨 위에 `취소 알림일 수도 있어요 · 아래 예약을 확인해 주세요` 와 4.4 의 그 날 예약을 보인다.
- **[예약 이어서]를 그대로 누르지 못한다.** 누르면 한 번 더 묻는다 — `취소 알림 같아요. 새 예약으로 넣을까요?` [그 날 예약 보기](앞) / [새 예약으로 넣기]. 그 날 예약이 없거나 날짜를 못 읽었어도 묻는다.
- 앱은 아무것도 스스로 취소하지 않는다. `변경` 알림은 견본 뒤에 다룬다.

### 4.6 들어온 창구를 남긴다

- 방문에 **창구**(`channel`) 한 칸. 값은 `naver` 하나뿐이고 나머지는 비어 있다(카카오톡·전화·직접은 가르지 않는다 — 사람이 고르게 하면 입력이 는다).
- 초안이 네이버 글이었으면 예약 폼이 저장할 때 `channel: "naver"` 를 함께 보낸다. 초안 화면에 `네이버 예약` 한 줄이 보이고 [아니에요]로 뗄 수 있다(글에 "네이버 예약"이라는 말만 있었던 경우). 반대로 방문 상세의 창구 줄에서 **나중에 붙이거나 뗄 수 있다**(붙여넣지 않고 손으로 옮겨 적은 네이버 예약).
- 보이는 곳은 **방문 상세 한 곳**, 맨 아래 줄이다(공통 8절): `네이버 예약으로 들어왔어요`. **달력 칸·하루 목록·피드의 줄에는 표시하지 않는다**(공통 7절).
- 그 방문을 수정·옮기기·취소·노쇼로 바꾸면 끝난 뒤 `네이버 예약에서도 바꿔 주세요` 를 스낵바로 한 번 보인다(연동이 없으니 사람이 해야 한다 — 이 한 줄이 이 칸의 쓸모다).
- **반복 예약(⑭)과의 관계**: 네이버 글에서 시작해 반복으로 잡으면 **모든 회차에 `channel` 이 붙는다.** `이후 전부` 를 한꺼번에 바꾸거나 취소하면 스낵바는 **한 번만** 뜬다(회차마다 뜨지 않는다).
- 공개 알림장·보호자 웹·알림톡·내 기록 가져가기(⑮)에 싣지 않는다.

### 4.7 화면에서 바뀌는 것

1. 예약 등록 맨 위의 [카톡 붙여넣기] → **[글 붙여넣기]**(카카오톡만이 아니게 됐다. 자리는 공통 8절).
2. 초안 화면: 읽은 글(접힘·고치기·[다시 읽기]), `네이버 예약` 줄(4.6), 그 날 예약 줄(4.4), 취소 안내(4.5), 아이·메뉴의 `지난번처럼` 표시(4.2), 안심번호 안내와 [새 고객 등록]·[문진표 보내기](4.3), 못 읽은 칸의 물음(2.5).
3. 새 고객 등록: ⑪ 의 미리 채움 형으로 채운 번호·이름(4.3).
4. 방문 상세: 맨 아래 창구 한 줄(4.6).
5. 공유 받기의 글 경로는 바꾸지 않는다 — 네이버 톡톡·문자 앱의 [공유]가 글을 넘기면 지금 경로로 온다. 스마트플레이스 앱이 글을 넘기는지 주소를 넘기는지는 **실기기에서 본다**(주소만 넘기면 붙여넣기나 캡처를 쓴다).

## 5. 어떻게 — 정해 둔 것

### 5.1 백엔드

- 해석은 지금 자리 `visit/domain/services/draft_parser.py` 에 더한다. `DraftParse` 에 `source`(`naver`|없음), `notice`(`cancel`|없음), `contact_name`, `contact_phone`, `contact_phone_kind` 를 더한다. 순수 함수이고 표 기반 테스트로 검증한다. `VisitDraftParserPort` 의 모양이 따라 바뀐다.
- `ParseVisitDraftInteractor` 가 후보가 하나이면 (가) 날짜가 있을 때 visit 저장소에서 그 가족의 그 날 살아 있는 방문을, (나) 그 가족 아이들의 지난번 메뉴·소요를 읽는다(읽기, 잠금 없음, 질의 수 고정 — 아이 수만큼 돌지 않는다). 지난번 값은 `visits/defaults` 가 쓰는 조회를 다시 쓴다.
- 응답 `VisitDraftSchema` 에 `source`, `notice`, `contact`, `same_day_visits`, `pets: [{pet_id, name, last_menus, last_duration}]`, `picked_pet_id|null` 을 더한다. 옛 앱은 모르는 칸을 버린다. `guessed` 에 `notice` 가 더해진다(네이버 글이면 `date`·`time`·`notice` 가 늘 true).
- `visits.channel varchar(16) null`(CHECK `channel = 'naver'`). 등록 요청에 `channel` 선택 칸, 상세 응답에 `channel`, 방문 수정에 `channel` 을 붙이고 떼는 칸. 반복 등록(⑭)은 모든 회차에 같은 값을 적는다.
- 마이그레이션은 계획 때 head 다음 번호를 잡는다(공통 11절 — 묶음 순서대로라 ⑮ 뒤다).
- 글·낱말·읽은 이름·번호를 로그·DB·오류 응답에 남기지 않는다(V9 그대로). 새 로그를 더하지 않는다.
- 권한은 그대로 `reservation:write`. 검색되는 글에 닿지 않으므로 `SearchSourceChanged` 는 해당 없다(`channel` 은 검색 문서에 넣지 않는다).

### 5.2 앱

- `VisitDraft` 에 새 칸, `VisitPrefill` 에 `channel`. 연락처는 `VisitPrefill` 에 새 칸을 만들지 않고 **⑪ 의 고객 등록 미리 채움 형**으로 넘긴다. 서버의 `source`·`notice`·`phone_kind` 문자열은 `fromJson` 에서 enum 으로 한 번만 바꾸고 모르는 값은 없는 것으로 본다.
- 새 고객 등록에 미리 채우기는 `visit → customer` 방향이라 허용된다. [문진표 보내기]는 ⑪ 이 정한 자리(서류 링크 만들기·보낼 것 묶음)를 부른다 — ⑪ 의 기능 폴더가 `customer` 가 아니면 `core/plugs` 에 자리를 둔다(계획에서 ⑪ 의 실제 자리를 보고 정한다).
- 공유 확장·안드로이드 인텐트의 글 경로와 채널은 손대지 않는다(이미지 경로는 3부).

### 5.3 테스트와 검증

- 도메인 단위(표 기반): 새 날짜 꼴, 이름표 줄이 본문을 앞서는 것, 네이버 글의 짐작 표시, **`취소·변경은 …` 안내만 있는 글은 취소 알림이 아니다**, 좁은 꼴의 취소 알림과 짐작 표시, 연락처 읽기, **050 번호는 `relay` 이고 후보 찾기에 쓰이지 않는다**, `N일 뒤`, **카카오톡 글의 기존 표가 그대로 통과**하는 것.
- 통합: 그 날 예약이 다른 매장 것을 싣지 않는다, 익명화한 고객의 예약·아이는 싣지 않는다, 지난번 메뉴가 그 아이 것이다, 아이가 여럿이고 글에 이름이 없으면 `picked_pet_id` 가 비어 있다, `channel` 저장·읽기·붙이고 떼기, 응답과 로그에 글이 없다.
- 앱: 초안 화면의 줄들, 읽은 글 고치기와 [다시 읽기], 취소 알림의 되묻기, 안심번호 안내, 미리 채운 등록 폼, 상세의 창구 줄과 스낵바(`이후 전부` 는 한 번). 골든은 초안 화면 둘(아는 고객·처음 온 손님).
- 흐름 스크립트 `check_visit_flow.sh` 에 판정 몇 줄(네이버 꼴 글 → `source`·짐작 → 등록 → 상세의 `channel`). 앱 흐름은 2.5 의 누르는 횟수를 센다.
- **실기기**: 네이버 톡톡·문자·스마트플레이스 앱에서 공유했을 때 무엇이 넘어오는지.

### 5.4 정식 연동을 하려면 먼저 확인할 것 (이번에 하지 않음)

네이버가 예약 정보를 바깥 프로그램에 주는 길(제휴 CRM 연결)이 있다는 것만 안다(2026-05 스마트플레이스가 일부 CRM 을 연결했다는 기사 — 검색 요약). 아래는 **모른다**: 신청 자격(사업자·법인·규모), 비용, 심사 기간, 받는 정보의 범위(번호가 안심번호인지), 반려동물 업종의 칸, 매장마다의 동의 절차. 공식 문서와 제휴 창구로 확인한 뒤 따로 설계한다.

# 2부 — 전화 올 때 고객 표시 (콜아이디)

## 6. 목표와 하지 않는 것

**목표**

- 매장 고객의 번호로 전화가 오면 받기 전에 **`보호자 이름 · 아이 이름`** 이 보인다. **iOS 에서도 된다**(경쟁사가 4년째 못 준 것).
- 앱은 **통화를 보지도 듣지도 않는다.** 번호와 이름표의 목록을 기기에 미리 넣어 둘 뿐이다.
- 고객 번호 목록이 기기에 내려가는 일이므로, **켠 사람·켠 기기가 서버에 남고, 끄면 지워진다.**

**하지 않는 것**

| 항목 | 까닭 |
|---|---|
| 통화 녹음, 통화 내용 요약, 전화를 받는 콜봇 | 확정된 제외. |
| 통화 기록 읽기, 부재중 전화 목록, 통화 뒤 "예약 잡을까요" 띄우기 | 통화 기록 권한은 스토어의 제한 권한이다. 통화를 보지 않는다는 약속과 어긋난다. |
| 이름표에 주의 고객·노쇼 횟수·메모·지병 넣기 | 7.2 — 까닭을 적고 고정으로 둔다(16절의 물을 것 1). |
| 기기 주소록에 고객을 써 넣기 | 7.4 — 다른 앱이 읽는다. |
| 다른 앱 위에 뜨는 창(오버레이) | 7.4. |
| 모르는 번호의 스팸 판정·차단 | 다른 일이다. |
| 거는 전화에 표시 | 받는 전화만. |
| 매장 전화(유선)와의 연동 | 휴대전화로 받는 매장만 해당한다. |

**이렇게 되면 실패다**: 직원이 그만둔 뒤에도 그 사람 전화기에 고객 이름이 계속 뜬다 · 직원 허용을 껐는데 직원 전화기에 계속 뜬다 · 잠금 화면에 주의 사유가 뜬다 · 다른 매장의 고객이 뜬다 · 익명화한 고객의 이름이 계속 뜬다 · 고객 번호가 로그에 남는다 · 카카오톡 같은 다른 앱이 고객 번호를 읽어 간다.

## 7. 무엇을 만드나

### 7.1 켜고 끄기 — 설정 화면

자리는 **매장 설정**이다(공통 8절). 설정 화면의 규칙(공통 3절)대로 줄 이름이 곧 설명이고, 결과를 먼저 보인다.

- 줄 이름: **`전화 올 때 고객 이름 보기`**. 기기마다 켜고, 기본은 꺼짐이다.
- 줄 아래에 **전화가 올 때 보이는 모습**을 그림으로 보인다 — 전화 화면의 번호 아래에 `김보호 · 콩이`(이 매장의 실제 고객 한 명으로, 없으면 본보기 이름으로). iOS 와 안드로이드의 실제 모양이 달라 플랫폼마다 그림이 다르다.
- 그 아래 한 줄: **`이 전화기에 매장 고객의 번호와 이름이 저장돼요. 끄면 지워져요.`** 켤 때 확인을 한 번 더 받지 않는다(줄 아래에 이미 적혀 있다) — iOS 는 시스템 설정에서 켜는 단계가, 안드로이드는 역할을 고르는 시스템 창이 뒤따른다.
- 켠 뒤에 보이는 것: 어느 매장의 목록인지, 고객 몇 명, 마지막으로 동기화한 때, **[지금 동기화]**, 이름표 모양 고르기(7.2).
- **한 기기에 한 매장.** 켠 순간 고른 매장의 고객만 내려간다. 다른 매장으로 화면을 바꿔도 목록은 그대로이고, 설정에 어느 매장 것인지 보인다. 다른 매장으로 바꾸려면 그 매장에서 켠다(앞의 목록은 지워진다고 알린다). **두 매장 것을 섞지 않는다 — 고정이다**: 전화가 올 때 어느 매장의 손님인지 이름표로 가를 수 없고, 다른 매장의 고객이 뜨는 사고를 구조로 막는다.
- **사장만이 기본이고, 매장 설정에서 직원에게 열 수 있다**(공통 9절). 줄 이름: `직원 전화기에서도 고객 이름 보기`, 아래 한 줄 `직원의 개인 전화기에 고객 번호와 이름이 저장돼요`. 기본 꺼짐.
- **직원 허용을 끄면 이미 켜 둔 직원 기기가 꺼진다**: 그 트랜잭션에서 직원으로 켠 기기 행을 전부 끄고(8.1), 그 기기들은 다음 동기화에서 거절당해 목록을 지운다. 끄기 전에 `직원 전화기 N대의 목록이 지워져요` 를 보인다.
- 매장 설정에 **켜 둔 기기 목록**(멤버 이름·기기 종류·마지막으로 동기화한 때)과 기기마다 [끄기]. 사장만 본다.

### 7.2 이름표

- 기본 꼴: **`{보호자 이름} · {아이 이름}`**. 아이가 둘이면 `콩이·두부`, 셋 이상이면 `콩이·두부 외 1`. 아이가 없으면 보호자 이름만. 무지개다리를 건넌 아이는 뺀다. 40자에서 자른다.
- **모양은 기기에서 고를 수 있다**: `보호자 · 아이`(기본) / `아이 · 보호자` / `보호자만`. 고르면 7.1 의 그림이 바로 바뀐다. 고른 값은 그 기기에만 적는다.
- 보호자 이름이 비어 있는 고객은 이름표가 비지 않게 `고객 · {번호 뒷자리 4자리}` 로 적는다(빈칸 금지).
- **주의 고객 표시·노쇼 횟수·메모·지병은 넣지 않는다 — 고정이다.** 까닭: 전화가 오는 화면은 잠금 화면에도 뜨고 옆 사람도 본다. 주의 사유는 사람에 대한 평가이고 매장 안에서만 보이게 돼 있다. 표시만(`주의`) 넣는 것도 손님 앞에서 전화기가 울릴 수 있어 하지 않는다. 전화를 받은 뒤 앱에서 본다. 고를 수 있게 열지는 16절의 물을 것 1 이다.
- `phone` 과 `phone_alt` 둘 다 싣는다. 한 번호가 두 고객에 걸리면(`phone_alt` 는 유일하지 않다) `phone` 이 그 번호인 고객이 앞서고, 그래도 겹치면 고객 ID 가 작은 쪽이다.
- 익명화한 고객은 빠진다.

### 7.3 iOS

- **Call Directory Extension**(CallKit 의 `CXCallDirectoryProvider`). 앱이 번호 → 이름표 목록을 시스템에 넘겨 두면, 전화가 올 때 시스템이 번호 아래에 이름표를 보인다. 확장은 통화를 받지 않고 통화 때 실행되지도 않는다.
- 사용자가 **설정 앱에서 한 번 켜야 한다**(전화 → 차단 및 발신자 확인 쪽). 앱은 상태를 읽어 `설정에서 켜 주세요` 와 설정으로 가는 버튼을 보인다.
- 번호는 나라 번호를 붙인 정수(`010…` → `8210…`)로, **오름차순·겹침 없이** 넘긴다. 나라 번호는 82 다(국내 번호만 — 고객 번호 칸이 국내 번호 11자까지다).
- 넘기는 길: 본체가 목록을 App Group 의 파일로 적고 확장을 다시 읽게 한다 → 확장이 시스템에 넘긴다 → **본체가 파일을 지운다.** 기기에 남는 것은 시스템이 쥔 목록뿐이다. 끄기·로그아웃은 빈 목록으로 다시 읽게 하는 것이다.
- **기기 주소록에 있는 번호는 주소록 이름이 뜬다**(시스템의 순서). 이름표 앞에 시스템이 앱 이름을 붙여 보인다.
- App Group 은 ③-A3 의 것(`group.com.chagocnote.app`)을 쓴다. 새 확장 타깃 하나가 는다. 과금 없음(개발자 계정은 이미 필요하다).
- **구현 전에 공식 문서로 다시 확인**: 설정 메뉴의 정확한 자리와 이름, 확장의 메모리 한도와 항목 수(수천 건이면 문제없을 것으로 보지만 수치는 확인하지 않았다), 바뀐 것만 넘기는 방식을 쓸지, 이름표가 보이는 꼴, 시뮬레이터에서 확인할 수 있는지(전화를 받을 수 없어 실기기가 필요하다고 본다).

### 7.4 안드로이드 — 방식 고르기

| 방식 | 필요한 것 | 위험 | 판단 |
|---|---|---|---|
| **통화 선별 역할**(`CallScreeningService`, Android 10+) | 사용자가 "발신자 확인 앱"으로 고른다. 전화가 오면 시스템이 번호를 서비스에 준다 | 역할은 한 앱만 가진다(다른 스팸 차단 앱을 쓰면 하나를 골라야 한다). 스토어 심사에서 용도를 설명해야 할 수 있다 | **고른다** |
| 전화 상태·통화 기록 권한으로 듣기 | `READ_PHONE_STATE` + `READ_CALL_LOG` | 통화 기록은 스토어의 제한 권한 — 기본 전화 앱이 아니면 신청·심사 대상이고 거절될 수 있다 | 버린다 |
| 다른 앱 위에 창 띄우기 | `SYSTEM_ALERT_WINDOW` | 권한 설명이 무겁고, 잠금 화면·제조사마다 다르게 군다 | 버린다 |
| 기기 주소록에 고객을 써 넣기 | `WRITE_CONTACTS` | **주소록을 읽는 다른 앱이 고객 번호를 가져간다**(카카오톡 친구 자동 추가 등). 구글 계정으로 올라갈 수 있다. 지우기가 불완전하다 | 버린다 |

- 고른 방식에서 표시는 **전화가 울리는 동안의 알림 하나**다(머리 위 알림). 오버레이를 쓰지 않는다. 알림 권한(Android 13+)이 필요하다. 전화가 끝나면 알림을 지운다.
- 알림을 누르면 그 고객의 반려동물 상세(아이가 없으면 고객)로 간다. iOS 에는 이 길이 없다.
- 목록은 **앱 전용 저장소**에 둔다. 번호는 설치마다 다른 소금을 친 해시로 적는다(평문 목록을 두지 않으려는 것 — 번호의 가짓수가 적어 완전한 보호는 아니라는 것을 적어 둔다). 이름표는 평문이다.
- 서비스는 전화마다 목록의 **받은 때**를 본다. **14일 넘게 동기화하지 못한 목록이면 아무것도 보이지 않는다 — 고정이다**(그만둔 직원의 기기가 앱을 열지 않아도 2주 뒤에는 멎게 하는 안전 기한이라 매장이 늘릴 수 없다).
- 통화를 막거나 거절하거나 기록하지 않는다 — 늘 "그대로 통과"로 답한다.
- **구현 전에 공식 문서로 다시 확인**: 역할을 받는 조건과 스토어 정책의 지금 문구, 제조사(삼성) 전화 앱에서 서비스가 불리는지, 알림이 전화 화면 위에 실제로 보이는지, 번호가 `+82` 꼴로 오는지. 에뮬레이터는 걸려 오는 전화를 흉내 낼 수 있어 흐름의 일부는 자동으로 본다.

### 7.5 동기화

- **통째로 다시 받는다.** 바뀐 것만 받는 방식은 두지 않는다 — 매장 하나의 고객은 수백에서 수천이고, 판(version)이 같으면 본문 없이 끝난다.
- 저절로 하는 때: 켠 순간 · 앱이 앞으로 올 때 마지막 동기화에서 6시간이 넘었으면 · 이 기기에서 고객·반려동물을 등록·수정·삭제·익명화한 직후. 다른 기기에서 바꾼 것은 다음에 앱을 열 때 온다(푸시가 없다).
- **손으로 하는 길**: 설정의 [지금 동기화]. 마지막으로 동기화한 때가 그 옆에 보인다. (6시간이라는 값은 사람이 고를 설정으로 두지 않는다 — 고르게 해도 달라지는 것이 없고, 급하면 [지금 동기화]가 있다.)
- **고객을 고친 직후의 동기화는 `lib/core/plugs/` 에 자리를 둔다.** `features/customer` 는 콜아이디 기능을 모른다 — customer 가 "고객 목록이 바뀌었다"를 plug 에 알리고, 콜아이디 쪽이 그 자리에 구현을 꽂는다(`care_marks_plug.dart` 와 같은 방식).
- iOS 의 백그라운드 새로 고침은 **되면 좋은 것**으로만 둔다(시스템이 돌려 줄 때만 돈다 — 기대지 않는다).
- 서버가 거절하면(꺼진 기기·직원 허용 꺼짐·멤버 아님) 앱이 목록을 지우고 설정을 끈 뒤 까닭을 한 줄로 알린다.

### 7.6 지우기 — 그리고 못 하는 것

| 때 | 하는 일 |
|---|---|
| 설정에서 끔 | 기기의 목록을 지우고 서버에 알린다 |
| 로그아웃, 세션이 끝남(갱신 실패) | 지운다 |
| 사장이 내보냄, 회원 탈퇴 | 서버가 그 트랜잭션에서 기기 행을 끈다(8.1) → 다음 동기화가 거절된다 → 앱이 지운다 |
| 사장이 그 기기를 [끄기], 직원 허용을 끔 | 위와 같다 |
| 사장에서 직원으로 역할이 바뀜(직원 허용 꺼짐) | 다음 동기화에서 거절된다 → 앱이 지운다 |
| 고객 익명화 | 다음 동기화에서 빠진다 |
| 앱 삭제 | 시스템이 확장·저장소와 함께 지운다 |

**못 하는 것을 적어 둔다.** 서버는 기기의 목록을 멀리서 지울 수 없다. 내보낸 직원이 앱을 다시 열지 않으면 — 안드로이드는 14일 뒤 멎지만, **iOS 는 시스템이 쥔 목록이 앱을 열거나 지울 때까지 남는다.** 그래서 직원 허용은 기본 꺼짐이고, 켜 둔 기기 목록을 사장에게 보인다. 기기를 잃어버렸을 때는 기기 잠금이 막는 것이 전부다(주소록과 같다). 이 한계는 `직원 전화기에서도 고객 이름 보기` 줄 아래의 더 보기에 그대로 적는다.

## 8. 어떻게 — 정해 둔 것

### 8.1 백엔드

- **customer 스포크**에 둔다(번호와 이름은 customer 의 사실이다).
- `GET /v1/shops/{id}/caller-directory` — 헤더 `X-Device-Id`(설치 때 만든 무작위 값). 응답 `{version, entries: [{phone, owner_name, pet_names, open_pet_id|null}]}`, `Cache-Control: no-store`. 요청의 `If-None-Match` 가 지금 판과 같으면 304. 판은 목록 내용의 해시다. **이름표 글은 앱이 만든다**(모양을 기기에서 고르므로) — 번호 바꾸기(`010…` → `8210…`)와 겹침 없애기·정렬은 서버가 한다.
- `PUT /v1/shops/{id}/caller-directory/devices/{device_id}`(켜기, 본문 `{platform}`) · `DELETE` 같은 경로(끄기 — 본인 것 또는 사장) · `GET /v1/shops/{id}/caller-directory/devices`(사장) · `PUT /v1/shops/{id}/caller-directory/settings`(직원 허용, 사장).
- 새 표 둘, 둘 다 customer 스포크의 것이다.
  - `caller_directory_devices(shop_id, device_id, member_id, enabled_as_owner, platform, enabled_at, last_synced_at, revoked_at)` — 켠 기기와 마지막으로 내려받은 때. 이것이 "누가 번호 전체를 가져갔는가"의 기록이다(공통 9절).
  - `caller_directory_settings(shop_id, staff_allowed)` — 직원 허용. **customer 의 표에 두는 까닭**: 끌 때 직원 기기 행을 같은 트랜잭션에서 꺼야 하기 때문이다.
- **권한(공통 9절)**: 새 권한 `customer:caller_directory` 를 사장 역할에 준다. 역할 시드는 전 매장 공통이라 매장별 직원 허용을 권한으로 표현할 수 없다 — 그래서 경로는 `get_shop_context` 로 받고 **유스케이스가 본다**: 권한이 있거나, `staff_allowed` 가 켜져 있다. 목록 읽기는 여기에 더해 **등록된, 꺼지지 않은 기기**만 된다. 통과하지 못하면 403 이고 앱이 지운다.
- **읽을 때의 판정이 진실이다.** 내보낸 멤버는 매장 가드에서 걸리고, 직원으로 바뀐 사람은 유스케이스에서 걸린다. 기기 행의 `revoked_at` 은 사장에게 보이는 목록을 맞추는 장부다.
- **직원 허용을 끄는 유스케이스**는 같은 트랜잭션에서 `enabled_as_owner = false` 인 살아 있는 기기 행을 전부 끈다. 직원으로 켠 뒤 사장이 된 사람의 기기도 꺼진다(다시 켜면 된다 — 받아들인 한계).
- **멤버가 빠질 때 기기를 끄는 길 — 새 허브 포트가 필요하다.** tenancy 는 customer 를 import 할 수 없다. `hub/app/ports/caller_directory_lifecycle_port.py` 에 `CallerDirectoryLifecyclePort`(구현: customer, 사용: tenancy) 를 두고 메서드는 `revoke_for_member(shop_id, member_id) -> int` 하나다.
  - 부르는 곳: `RemoveMemberInteractor`(내보냄), `ApplyWithdrawalInteractor`(탈퇴 — 소속마다), `ChangeMemberRoleInteractor`(사장 → 직원).
  - `ApplyWithdrawalInteractor` 는 **인증 프로세스에서 돈다** — `auth_main.py` 에도 customer 의 구현을 꽂아야 한다(`GuardianLifecyclePort` 가 같은 선례다). tenancy 의 `dependencies/hub_ports.py` 에 자리를 두고 진입점 둘이 꽂는다.
  - 스스로 매장을 나가는 유스케이스는 지금 없다. 생기면 같은 포트를 부른다.
  - 포트가 빠져도 읽을 때의 판정이 막는다 — 포트는 사장의 기기 목록을 제때 맞추는 것이다. 그래도 한 트랜잭션에서 한다.
- **잠금 순서**(공통 10절): 유저 행 → 매장 행 → 멤버 행 → 매장 초대 행 → **콜아이디 기기 행**. `CLAUDE.md` 의 잠금 문단에 이 줄만 더한다.
- 매장 범위 저장소 메서드는 `ShopContext` 가 첫 인자다. 목록은 그 매장의 살아 있는 고객뿐이다.
- 로그는 `shop_id`·`member_id`·건수·결과뿐이다. **번호·이름·기기 ID 를 로그·오류 메시지에 남기지 않는다.** 응답 본문을 접근 로그에 찍지 않는다.
- 로그인 없는 경로·보호자 경로·공개 스키마는 건드리지 않는다. 허용 목록 테스트가 그대로 통과해야 한다.

### 8.2 앱

- 네이티브는 **직접 쓴다**(③-A3 와 같은 판단 — 패키지에 기대지 않는다). 채널 `com.chagocnote.app/caller_directory`: `status`(꺼짐·설정 필요·켜짐), `apply(entries)`, `clear`, `openSettings`.
- iOS: 새 타깃 `CallDirectoryExtension`, 본체 쪽 플러그인은 `AppDelegate.swift` 의 기존 플러그인 옆. 안드로이드: `CallScreeningService` 하나와 알림 채널 하나.
- Dart: 이름표 만들기(세 모양·자르기·빈 이름)는 순수 함수다. 모양을 바꾸면 내려받은 것을 다시 받지 않고 **동기화를 한 번 더 돌려** 다시 넘긴다(기기에 원본 목록을 두지 않기 때문이다).
- 켜고 끄는 화면은 매장 설정 안의 한 화면. 로그아웃·세션 종료의 지우기는 세션 컨트롤러의 로그아웃 경로에 건다.
- 고객을 고친 직후의 동기화는 `lib/core/plugs/` 의 새 plug 로 잇는다(7.5).
- 내려받은 목록을 Dart 메모리나 로그에 남기지 않는다. `print` 금지는 지금 그대로다.

### 8.3 테스트와 검증

- 백엔드 통합: 첫 테스트는 **다른 매장의 고객이 목록에 없다**. 익명화한 고객이 없다, 무지개다리 아이가 없다, 번호 겹침의 앞섬, 직원 허용 꺼짐이면 직원은 403, **직원 허용을 끄면 직원 기기 행이 꺼지고 사장 기기는 남는다**, 꺼진 기기는 403, 304, **내보냄·탈퇴·역할 낮춤이 기기를 끈다**(포트), 로그에 번호가 없다. 인증 프로세스의 조립 테스트에 새 포트 자리.
- 앱 단위: 이름표 세 모양·자르기·빈 이름, 동기화의 때(6시간·고친 직후·[지금 동기화]), 403 에 지우기와 까닭 한 줄, 로그아웃에 지우기. 골든은 설정 화면(꺼짐·켜짐).
- **설정 줄의 이름만 떼어 처음 보는 검토자에게 "켜면 무슨 일이 생기나"를 맞히게 한다**(공통 3절의 확인). 틀리면 이름을 고친다.
- **자동으로 못 보는 것**: 실제로 전화가 올 때 뜨는지. iOS 는 실기기 두 대(거는 쪽·받는 쪽)가 필요하다. 안드로이드는 에뮬레이터의 전화 흉내로 한 번, 실기기(삼성)로 한 번.
- 실기기 확인 표: 잠금 화면에서의 모습 · 주소록에 있는 번호 · 끈 뒤 사라지는지 · 로그아웃 뒤 사라지는지 · 고객 2,000명에서 넘기는 시간.

# 3부 — 화면 캡처에서 예약 초안

## 9. 목표와 하지 않는 것

**목표**

- 글을 골라 복사하기 번거로울 때, **화면 캡처 한 장을 공유하거나 고르면** 기기 안에서 글자를 읽어 지금의 초안 화면이 채워진다. 네이버 예약 화면에도, 카카오톡 대화에도 같이 쓴다.
- **이미지는 기기 밖으로 나가지 않는다.** 읽은 글만 지금의 초안 경로(1부)로 간다 — 붙여넣기와 똑같이 서버는 저장하지 않는다.
- 글자를 잘못 읽을 수 있으므로 **읽은 값은 전부 "짐작"으로 보이고 사람이 확인한다.**

**하지 않는 것**

| 항목 | 까닭 |
|---|---|
| 이미지를 서버·외부 서비스로 보내 읽기 | 매장의 글을 밖으로 보내지 않는다. 과금·외부 연결도 없다. |
| 이미지를 저장하기(서버·기기) | 읽고 나면 임시 파일을 지운다. 예약에 붙이지 않는다. |
| 사진첩 전체를 훑어 예약 캡처를 찾기 | 사람이 고른 한 장만 읽는다. 사진 접근 권한을 받지 않는다(시스템의 사진 고르기를 쓴다). |
| 손글씨·사진 속 글자 읽기 | 화면 캡처의 인쇄체만 대상이다. |
| 여러 장을 이어 읽기 | 한 장만. 길면 읽은 글을 고쳐 쓴다. 필요하다는 말이 나오면 더한다. |
| 웹뷰로 글자 읽기 | 앱은 네이티브다. |

**이렇게 되면 실패다**: 화면 맨 위의 시계(상태 표시줄)를 예약 시각으로 읽는다 · 카카오톡 말풍선 옆의 보낸 시각을 예약 시각으로 읽는다 · 잘못 읽은 번호가 "짐작" 표시 없이 채워진다 · 이미지나 읽은 글이 기기·서버·로그에 남는다 · 안드로이드의 글자 읽기 도구가 이미지를 밖으로 보낸다.

## 10. 무엇을 어떻게

### 10.1 들어오는 길 둘

1. **공유 받기** — 다른 앱(사진 앱·스크린샷 미리 보기·카카오톡·네이버)에서 이미지를 차곡노트로 공유한다. iOS 공유 확장이 이미지 한 장을, 안드로이드가 `ACTION_SEND` `image/*` 를 받도록 넓힌다. 지금의 글 경로는 그대로다.
2. **앱 안에서 고르기** — 예약 등록 맨 위 [글 붙여넣기] 옆의 **[캡처에서 읽기]**. 시스템의 사진 고르기(iOS `PHPicker`, 안드로이드 Photo Picker)를 연다 — 둘 다 **사진 접근 권한 없이** 고른 한 장만 준다(안드로이드 옛 판의 동작은 **구현 전에 공식 문서로 다시 확인**).

### 10.2 글자 읽기 — 네이티브, 기기 안에서

- 채널 `com.chagocnote.app/text_recognition`: `recognize(path) -> {lines: [{text, top, left, height}], image_height}`. 네이티브를 직접 쓴다.
- **iOS**: Vision 의 `VNRecognizeTextRequest`(정확도 우선, 언어 한국어·영어). 운영체제에 들어 있고 기기 안에서 돈다. 과금 없음. **구현 전에 공식 문서로 다시 확인**: 한국어를 지원하는 최소 iOS 판(앱의 최소 지원 판과 견준다), 시뮬레이터에서 도는지.
- **안드로이드**: 운영체제에 공통으로 들어 있는 글자 읽기 API 는 없다(내가 아는 한). 쓸 수 있는 것은 Google 의 ML Kit 글자 인식(한국어 모델)이다 — 기기 안에서 돌고 무료라고 알고 있다. **이것은 Google 의 라이브러리를 앱에 넣는 일이다.** 아래를 **구현 전에 공식 문서로 다시 확인**한다.
  - 이미지가 기기 밖으로 나가지 않는다는 것, 그리고 **사용 통계 같은 것을 Google 로 보내는지**(보낸다면 무엇을 — 이미지·읽은 글이 들어 있으면 쓰지 않는다)
  - 이용 약관·라이선스와 상업 서비스에서의 조건, 과금이 없다는 것
  - 모델을 앱에 넣는 방식(앱 크기가 는다)과 Google Play 서비스로 내려받는 방식(첫 사용 때 내려받기가 필요하고 Play 서비스가 없는 기기에서는 안 된다)의 차이 — 권하는 것은 앱에 넣는 방식이다(네트워크 없이 바로 돈다)
  - 이 확인에서 걸리면 **안드로이드에는 캡처 읽기를 넣지 않고** 붙여넣기·글 공유만 둔다(16절의 물을 것 2).
- 읽은 뒤 임시 파일을 지운다. 이미지와 읽은 글을 Dart 로그·네이티브 로그에 남기지 않는다.

### 10.3 읽은 줄을 글로 바꾸기 (Dart 순수 함수)

캡처에는 예약과 상관없는 글자가 섞여 있다. 해석기에 넣기 전에 거른다.

- 줄을 위에서 아래로, 같은 높이면 왼쪽에서 오른쪽으로 잇는다.
- **맨 위 띠를 버린다**: 이미지 높이의 위쪽 6% 안에 있는 줄(상태 표시줄의 시계·배터리). (6% 는 내가 정한 값 — 실기기 캡처로 맞춘다.)
- **보낸 시각만 있는 줄을 버린다**: 줄 전체가 `오전|오후 H:MM` 꼴이고 글자 높이가 본문 줄의 중앙값보다 작으면 말풍선 옆의 시각으로 보고 버린다. 본문에 적힌 `오후 2:30` 은 크기가 본문과 같아 남는다.
- 1,000자에서 자른다(초안 경로의 한도). 잘렸으면 초안 화면에 `글이 길어 앞부분만 읽었어요` 를 보인다.
- 남은 글을 `POST …/visit-drafts` 에 `via: "capture"` 와 함께 보낸다. 서버는 `via` 가 `capture` 이면 **읽은 값 전부를 짐작으로** 표시한다(`guessed` 의 모든 칸이 true). 번호는 한 글자만 틀려도 다른 사람이므로, 캡처에서 읽은 번호로 찾은 후보에는 `번호를 확인해 주세요` 를 붙인다.
- 초안 화면의 읽은 글(2.5)이 여기서 가장 쓸모 있다 — 잘못 읽은 글자를 고치고 [다시 읽기].
- 한 글자도 못 읽었으면 초안 화면으로 가지 않고 `글자를 읽지 못했어요 · 글을 복사해 붙여넣어 주세요` 를 보인다.

### 10.4 백엔드에서 바뀌는 것

- 초안 요청에 `via`(`text` 기본 | `capture`) 선택 칸 하나. 응답 모양은 1부와 같다. 저장하는 것이 없고 로그도 그대로다(V9).
- 그 밖에는 없다. 이미지를 받는 경로를 만들지 않는다.

### 10.5 테스트와 검증

- Dart 단위(표 기반): 줄 잇기, 맨 위 띠 버리기, 보낸 시각 줄 버리기와 본문의 시각 남기기, 1,000자 자르기, 빈 결과.
- 백엔드: `via: capture` 이면 `guessed` 가 전부 true, 후보의 번호 확인 표시.
- 네이티브 채널은 가짜로 바꿔 화면·흐름을 본다(읽은 줄을 정해 준다). 앱 흐름은 2.5 의 누르는 횟수를 센다.
- **자동으로 못 보는 것**: 실제 캡처를 얼마나 잘 읽는지. 실기기에서 카카오톡 대화 캡처·네이버 예약 화면 캡처·문자 캡처를 각각 몇 장 읽어 표로 남긴다(견본은 사용자의 것이 필요하다 — 이름·번호를 가린 캡처도 된다). iOS 시뮬레이터에서 Vision 이 돈다면 저장소의 본보기 이미지(지어낸 대화)로 흐름 하나를 자동으로 본다.

## 11. 2부는 언제 만드나 — 조건

2부(콜아이디)는 **아래 가운데 하나가 참일 때** 계획을 쓴다. 그 전에는 설계만 둔다.

- 입점 매장(또는 입점을 의논하는 매장)이 전화로 예약을 받는다고 말한다.
- 첫 매장 사장님이 필요하다고 말한다.
- 스토어에 올린 뒤 같은 요청이 들어온다.

만들 때의 걸림돌을 미리 적는다 — 실기기가 있어야 검증된다(지금까지 미룬 실기기 확인이 먼저다), 스토어 심사에서 용도 설명이 필요할 수 있다, iOS 는 사용자가 설정에서 켜는 한 단계가 있다.

## 12. 위험과 막는 법

| | 위험 | 막는 법 |
|---|---|---|
| N1 | 지어낸 네이버 형식 규칙이 틀린 날짜를 확신으로 보인다 | 견본 전에는 네이버 글의 날짜·시각을 늘 "짐작"으로 표시한다. 형식 규칙은 견본으로만 더한다. |
| N2 | 취소 알림이 새 예약이 된다 / 확정 글이 취소 알림으로 뜬다 | 좁은 꼴만 취소로 짐작하고 안내 꼴은 뺀다(4.5). 짐작이라고 보이고, [예약 이어서]는 한 번 더 묻는다. 저장은 여전히 사람이 한다. |
| N3 | 기존 카카오톡 해석이 깨진다 | 기존 표 기반 테스트를 그대로 두고 통과시킨다. 이름표 줄은 사전에 있는 이름표만 읽는다. |
| N4 | 글·번호·이름이 로그에 남는다 | 새 로그 없음. 응답과 로그에 글이 없다는 통합 테스트(V9 를 넓힌다). |
| N5 | 앱에서 바꾼 예약이 네이버에는 그대로다 | `channel` 과 바꾼 뒤의 한 줄 안내. 연동이 없다는 것을 숨기지 않는다. |
| N6 | 안심번호가 고객 번호로 저장된다 | 050 번호는 `relay` 로 표시하고 후보 찾기·미리 채움에 쓰지 않는다. |
| N7 | 틀린 아이·틀린 메뉴가 채워진다 | 아이가 여럿이고 글에 이름이 없으면 고르지 않고 묻는다. 채운 값에 `지난번처럼` 표시. 전부 고칠 수 있다. |
| C1 | 그만둔 직원의 기기에 고객 이름이 남는다 | 직원 허용 기본 꺼짐, 기기 목록과 [끄기], 내보냄·탈퇴·역할 낮춤·직원 허용 끄기가 기기를 끔, 안드로이드 14일 기한. iOS 의 남는 구간은 7.6 에 적은 한계다. |
| C2 | 다른 앱이 고객 번호를 읽는다 | 주소록에 쓰지 않는다. iOS 는 시스템 목록, 안드로이드는 앱 전용 저장소. |
| C3 | 잠금 화면에 평가가 뜬다 | 이름표는 이름뿐이다. 주의·노쇼·메모를 넣지 않는다(응답 칸을 테스트가 고정). |
| C4 | 다른 매장의 고객이 뜬다 | 한 기기 한 매장, 매장 범위 저장소, 첫 통합 테스트. |
| C5 | 번호 전체를 내려받는 경로가 남용된다 | 공통 9절 — 사장만이 기본, 직원은 매장 설정으로, 유스케이스가 본다. 등록된 기기만, 기기 표에 기록, `no-store`. ⑮ 의 기록 내보내기(`tenancy.shop_export_logs`)와 같은 원칙이고 기록하는 표만 다르다. |
| C6 | 스토어 심사에서 걸린다 | 제한 권한(통화 기록·오버레이·주소록 쓰기)을 쓰지 않는다. 구현 전에 정책을 다시 읽는다. |
| O1 | 상태 표시줄의 시계·말풍선의 보낸 시각을 예약 시각으로 읽는다 | 맨 위 띠와 보낸 시각 줄을 버린다(10.3). 캡처에서 읽은 값은 전부 짐작이다. |
| O2 | 글자를 틀리게 읽어 다른 사람·다른 날이 된다 | 전부 짐작 표시, 후보에 `번호를 확인해 주세요`, 읽은 글을 고치고 [다시 읽기]. 저장은 사람이 한다. |
| O3 | 안드로이드의 글자 읽기 도구가 무언가를 밖으로 보낸다 | 구현 전에 공식 문서로 확인한다. 걸리면 안드로이드에는 넣지 않는다. |
| O4 | 이미지·읽은 글이 남는다 | 임시 파일을 읽은 뒤 지운다. 서버는 이미지를 받지 않는다. 로그 없음. |

## 13. 나누기와 순서

- **⑯-1 글에서 예약 초안 보강** — 백엔드(해석기·응답·`channel`)와 앱(초안 화면·등록 미리 채움·상세)을 한 계획으로. 작다. 새 날짜 꼴·`N일 뒤`·아는 고객 채우기·안심번호는 네이버와 무관하게 쓸모 있다. 견본이 오면 4.1 의 오른쪽 칸을 같은 계획 안의 후속 작업으로 더한다. ⑪ 뒤에 만든다(미리 채움 형·문진표 링크·보낼 것 묶음을 쓴다).
- **⑯-2 화면 캡처에서 읽기** — iOS 먼저(Vision), 안드로이드는 10.2 의 확인 뒤. ⑯-1 뒤(초안 화면의 읽은 글 고치기를 쓴다).
- **⑯-3 콜아이디 백엔드** — 목록·기기·권한·허브 포트. 11절의 조건 뒤.
- **⑯-4 콜아이디 앱** — iOS 확장 → 안드로이드 서비스 → 설정 화면 → 실기기 확인. 11절의 조건 뒤.

## 14. 만드는 사람에게 맡기는 것

- 문구의 마지막 다듬기, 초안 화면 새 줄들의 여백, 설정 화면의 그림(기존 설정 화면의 톤을 따른다).
- 응답 칸의 정확한 이름, 이름표 사전의 낱말(견본이 오면 바꾼다), 판(version)의 계산법.
- 폴더 이름은 작명 규칙을 따른다(실제 그 패턴일 때만 패턴 이름).
- 결정 기록은 `_docs/decisions/019-…` 다(공통 11절). 1부·3부를 만들 때 쓰고, 2부는 만들 때 절을 더한다.

## 15. 아직 가정인 것 (공통 12절)

| 가정 | 답이 다르면 |
|---|---|
| 첫 매장이 네이버 예약을 쓰는지 모른다 → ⑯ 은 여섯 묶음의 맨 뒤다 | 쓴다고 하면 실제 알림 글 견본 두세 개(이름·번호는 가리고)를 받아 ⑯-1 을 앞당기고 4.1 의 오른쪽 칸까지 한 번에 만든다 |
| 전화 예약이 많은 매장이 아직 없다 → 콜아이디는 계획을 쓰지 않는다 | 11절의 조건이 차면 ⑯-3·⑯-4 의 계획을 쓴다 |
| 직원의 개인 전화기에는 기본으로 내리지 않는다(사장이 열 수 있다) | 공통 9절이 바뀌면 따른다 |

## 16. 사용자에게 물을 것

1. **전화 올 때 이름표에 `주의` 표시를 넣을 수 있게 열까요?** 지금은 넣지 않는 것으로 고정했습니다 — 전화 화면은 잠금 화면에도 뜨고 손님이나 옆 사람이 볼 수 있어서입니다. 열면 "기본은 꺼짐, 켜면 이름 뒤에 표시 하나"가 됩니다.
2. **안드로이드의 화면 캡처 읽기에 Google 의 글자 인식 라이브러리를 써도 될까요?** 기기 안에서 돌고 무료라고 알고 있지만, 무엇을 Google 로 보내는지는 구현 전에 공식 문서로 확인해야 합니다. 쓰지 않으면 캡처 읽기는 아이폰에서만 되고 안드로이드는 붙여넣기·글 공유만 됩니다.
3. **실제 캡처 견본을 몇 장 주실 수 있나요?** 카카오톡 예약 대화와 (쓰신다면) 네이버 예약 화면을 이름·번호를 가려서요. 없으면 제가 지어낸 본보기로만 맞추게 되어, 맨 위 띠·보낸 시각을 버리는 규칙이 실제 화면과 어긋날 수 있습니다.
