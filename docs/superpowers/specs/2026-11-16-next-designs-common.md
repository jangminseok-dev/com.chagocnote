# ⑪~⑯ 공통 기준

- 날짜: 2026-11-16
- 대상: ⑪ 동의서·문진표, ⑫ 보호자 기록·리뷰 주소, ⑬ 미용 주기·달력 표시, ⑭ 정기권·반복 예약, ⑮ 가격·내보내기·예약금, ⑯ 들어오는 예약
- 이 문서는 여섯 설계가 함께 따르는 기준이다. 묶음의 설계와 어긋나면 **이 문서가 앞선다.** 만드는 순서는 ⑪ → ⑫ → ⑬ → ⑭(반복 예약 먼저) → ⑮ → ⑯ 이다.

## 1. 편의 기준 (합격선)

사용자(2026-11-16)의 기준이다. 묶음마다 "편의 기준" 절을 두고, 시뮬레이터 흐름·웹 e2e 로 확인한다.

**사장님**
- 설정 없이 첫날부터 쓴다. 먼저 만들어 둬야 쓸 수 있는 것(가격표·정기권 종류·동의서 문안)은 두지 않는다 — 기본값이 채워져 있다.
- 자주 하는 일(예약 잡기, 완료하고 기록 적기, 알림장 보내기, 다음 예약 잡기)은 누르기 세 번 안에 끝난다.
- 같은 것을 두 번 적지 않는다. 한 번 적은 값은 다음에 미리 채워져 있다.
- 한 예약에 보낼 글은 공유 한 번으로 나간다(4절).

**보호자**
- 앱 설치·회원가입·초대 코드 없이 링크 하나로 끝난다(알림장 보기, 동의서 서명, 문진표 적기).
- 서명과 문진표는 1분 안에 끝나는 길이다. 한 번 적은 것은 다시 묻지 않는다.
- 사진·영상은 원본 그대로 받는다. 광고가 없다.

**간편함이 빼면 안 되는 것**
- 핵심 기능과 핵심 설명을 빼지 않는다. 줄이는 것은 누르는 횟수다.
- **기본값은 채워 두되 모든 값은 바꿀 수 있다.** "고정이다·매장이 못 바꾼다"로 정하지 않는다. 그렇게 정해야 할 까닭(돈의 등식, 보안, 남의 개인정보)이 있으면 까닭을 적고 "사용자에게 물을 것"에 올린다.
- 자동으로 채운 값은 언제든 고칠 수 있다.
- **빈칸을 내보내지 않는다.** 채울 근거가 없으면 그 자리에서 묻는다. 보호자에게 나가는 글에 들어갈 값이 비어 있으면 보내기 전에 그 칸만 묻는다.

## 2. 자동화의 원칙

- 앱이 미리 준비해 두고 사장은 확인 한 번만 누른다.
- 끝까지 사람이 누르는 것: 돈이 움직이는 일, 보호자에게 나가는 글, 고객에게 주의 표시를 다는 일, 예약의 취소, 문진표를 고객 정보에 반영하는 일.
- 보호자에게 저절로 가는 것(알림톡)은 실발송을 붙인 뒤다. 그때까지는 준비된 글을 공유 시트로 한 번 눌러 보낸다.

## 3. 설정 화면과 말

- 줄 이름이 곧 설명이다 — 일어나는 일로 쓴다(`예약 전날 보호자에게 알려 주기`).
- 켜고 끄는 줄 아래에 보호자가 받게 될 글·화면을 그대로 보인다.
- 한 줄에 고를 것 하나. 깊이는 두 단계까지.
- 쓰는 자리에서 바꾼다. 처음 쓸 때 그 자리에서 한 번 묻고 기억하고, 같은 값을 설정 화면에서도 고칠 수 있다.
- **널리 쓰는 말은 그대로 쓴다**: 템플릿, 차감, 동기화, 리마인드, 정기권, 예약금, 노쇼. 풀어 쓰는 것은 개발 용어(토큰·큐·색인)뿐이다.
- "AI"·"법적 효력"이라는 말을 쓰지 않는다.

## 4. 한 번에 보내기 — 예약의 보낼 것 묶음 (⑪ 이 만든다)

한 예약에 보호자에게 보낼 것이 여럿이면 글 하나로 묶어 공유 한 번에 보낸다.

- 묶음에 들어가는 것: 예약 접수 안내(날짜·시간·메뉴), 서류 링크(⑪), 예약금 안내(⑮). 뒤의 묶음은 자기 토막을 더한다.
- ⑪ 이 조립하는 자리(백엔드의 조립 함수와 앱의 미리 보기 시트)를 만든다. 토막은 `{kind, text}` 의 목록이고 앱은 모르는 kind 도 글 그대로 싣는다.
- 보내기 전에 미리 보기에서 글을 고칠 수 있고 토막을 뺄 수 있다.
- 알림톡 실발송이 붙으면 같은 토막이 알림 종류로 간다(나중).

## 5. 하루 마무리 (⑬ 이 만든다)

그날의 남은 일(결제 안 적음, 알림장 안 보냄, 정리 안 된 예약)을 한 화면에 모아 차례로 넘기며 처리한다. 하루 머리의 숫자를 누르면 열린다.

## 6. 돈을 가르는 순서 (함수는 하나다 — 정기권 장부와 예약금 가운데 먼저 만드는 쪽이 만들고 뒤의 쪽이 넓힌다)

완료 방문의 총액은 **전체 요금**이다. 그 안에서 차례로 가른다.

1. 정기권 몫 = 기록의 `pass_amount`(매출로 잡는 몫. 잔액에서 빠진 금액 `pass_face_amount` 와 다를 수 있다 — 덤을 준 권)
2. 예약금 몫 = `min(받은 예약금, 총액 − 정기권 몫)`
3. 나머지 = `총액 − 정기권 몫 − 예약금 몫` → 기록의 결제 수단(카드·현금·계좌)

- 기록 화면의 `오늘 받을 돈` = 나머지.
- 결제 수단별 집계: `정기권` 줄 = 정기권 몫, 예약금 몫은 `계좌`(코드 값 `transfer`, ⑮ 가 "이체"라 부른 것과 같다)에 더한다, 나머지는 기록의 수단. 합은 늘 매출과 같다 — 등식 테스트에 "정기권 + 예약금 + 나머지" 사례를 넣는다.
- 예약금이 `총액 − 정기권 몫` 보다 크면 넘는 돈은 `돌려줄 예약금` 으로 방문 상세에 남는다(사장이 [돌려줌]을 누른다).
- **`paid`(결제 완료)** = 총액이 있고, (나머지가 0 이거나 결제 수단이 있다). ⑬ 이 이 정의를 쓴다.
- **횟수권 1회는 그날의 미용 한 번을 덮는다**: 추가 항목(`is_extra`)이 아닌 메뉴 값 전부가 정기권 몫으로 들어가고, 추가 항목만 나머지다. 매출로 잡는 값은 그 방문의 메뉴 값이 아니라 **회당 금액(받은 돈 ÷ 횟수)** 이다 — 이중 계산·덜 계산을 막는다. 0원으로 준 권도 같은 규칙이다. (내가 정한 것 — 히스하우스의 실제 방식 확인 필요)
- 받았지만 매출이 되지 않은 돈(끝낸 권의 남은 돈, 환불의 위약 차이, 돌려주지 않은 예약금)은 매출 탭에 `쓰지 않고 끝난 돈` 한 줄로 보인다. 매출 숫자에는 넣지 않는다. 먼저 만드는 묶음이 자기 구역에 두고, 둘 다 생기면 예약 구역의 한 줄로 합친다.
- 추가 항목 표시(`service_menus.is_extra`)와 알림장에 보이기(`report_visible`)는 ⑮ 의 칸이다. 정기권 장부가 먼저 만들어지면 그쪽이 `is_extra` 를 먼저 만든다.
- 가족이 같은 날 함께 잡은 방문들의 예약금은 **그 묶음에** 받는다. 한 마리가 취소돼도 남은 방문의 총액에서 빠진다. 전부 취소되면 돌려줌/돌려주지 않음을 고른다.

## 7. 줄·칸의 상태 표시 (⑬ 이 정한다)

- 원칙: **남은 일**은 확인할 것(③-B 연쇄)의 항목과 하루 머리의 숫자로, **끝낸 일**은 줄의 낱말로.
- `marks` 코드(줄의 낱말, 이 순서): `paid` 결제 완료 · `report_sent` 알림장 보냄 · `pass_used` 정기권 · `deposit_received` 예약금 받음.
- `consent_*` 는 `marks` 에 없다 — ⑪ 은 확인할 것의 `consent` 항목에 상태를 싣는다.
- `예약금 기다리는 중` 은 남은 일이다 — 하루 머리의 숫자와 방문 상세의 줄로만 보이고 줄의 낱말로는 두지 않는다.
- 창구(`channel`, ⑯)는 줄·칸에 표시하지 않는다. 방문 상세 한 줄뿐이다.
- 달력 칸에는 새 표시를 더하지 않는다. 이미 있는 작은 숫자(정리 안 된 예약의 수)의 뜻을 **그날의 남은 일의 수**(결제 안 적음, 알림장 안 보냄, 정리 안 된 예약)로 넓힌다 — 지난 날·오늘만이다. 앞날의 확인할 것은 고른 날의 카드에 글로 보인다(노령·지병 아이 때문에 숫자가 날마다 뜨는 것을 막는다).

## 8. 화면의 자리 (위에서 아래)

| 화면 | 순서 |
|---|---|
| 방문 상세 | 이름 카드(상태 낱말) → 확인할 것(동의서 상태·버튼은 `consent` 항목 안) → 예약금 줄 → 보호자 줄 → 정기권 줄 → 반복 묶음 줄 → 창구 줄 |
| 반려동물 상세 · 정보 탭 | 지금 것 → 동의 줄([서명 보기]) → 주기 줄 |
| 반려동물 상세 · 보호자 탭 | 노쇼 → 주의 → 정기권 → 보호자 연결(`· 가족 N명`) → 다가오는 예약 → `문진표 다시 받기` |
| 기록 화면 | … 총액 → 예약금 줄 → 정기권 줄 → `오늘 받을 돈` → 결제 수단 → 메모 |
| 예약 등록 | [글 붙여넣기] → 고객·아이 → 메뉴(추가 칩) → 날짜·시간 → 반복 줄(회차 목록) → 예상 금액 → 보낼 것 묶음 |
| 매출 탭 | 요약 → 결제 수단별 → 정기권 구역 → 예약 구역(예약금 줄, `쓰지 않고 끝난 돈`) → 지난 아이 → 내보내기 |
| 설정 | 알림장 설정(리뷰 주소·정기권 잔여 보이기) / 예약 설정(예약금) / 서류 설정(동의서 문안·문진표 항목) / 매장 설정(내 기록 가져가기·콜아이디) |

해당하는 것이 없으면 줄이 없다(정기권 줄은 정기권이 있는 고객에게만).

## 9. 고객 번호 전체가 나가는 길

- 원칙: **사장만이 기본이고, 매장 설정에서 직원에게 열 수 있다.** 권한(`data:export`, `customer:caller_directory`)은 사장 역할에 준다. 역할 시드는 전 매장 공통이라 권한만으로는 매장별 허용을 못 하므로 매장의 설정 칸을 본다. 그 칸을 어디에 두고 누가 보는지(⑮ 는 `tenancy` 가 요청마다 권한 묶음에 더하는 안, ⑯ 은 유스케이스가 자기 스포크의 설정 표를 보는 안)는 **먼저 계획을 쓰는 ⑮ 가 코드를 읽고 하나로 정하고 ⑯ 이 따른다.**
- 내려받은 사실을 남긴다: ⑮ 는 `tenancy.shop_export_logs`, ⑯ 은 `customer.caller_directory_devices`. 내용은 로그에 남기지 않는다.
- 받은 문진표(⑪)를 읽는 것은 고객 정보를 보는 일과 같은 권한(`customer:write`)이다 — 한 건씩이라 이 절의 대상이 아니다.

## 10. 잠금 순서 (여섯 묶음을 합친 모양)

- 고객·방문 쪽: 고객 행 → 서류 요청 행(⑪) → 방문 행(ID 오름차순) → 정기권 행(⑭) → 알림 행
- 잇기·탈퇴 쪽: 유저 행 → 매장 행 → 멤버 행 → 매장 초대 행 → 콜아이디 기기 행(⑯) → 보호자 기본 연결 행 → 가족 초대 행(⑫) → 가족 연결 행(⑫)
- 익명화: 고객 행 → 서류 요청·서명·문진표 지우기(⑪) → 보호자 연결 행
- ⑫ 의 "초대 행"은 **가족 초대 행**이라 부른다(매장 초대 행과 가른다). 가족이 스스로 끊을 때도 기본 연결 행을 먼저 잡는다.
- 각 묶음은 `CLAUDE.md` 의 잠금 문단에 자기 줄만 더한다.

## 12. 기본값은 업계에서 흔한 방식, 매장이 자기 가게에 맞게 고른다 (2026-11-16 사용자 결정)

히스하우스의 답을 기다리지 않는다. **기본값은 경쟁 서비스들이 흔히 하는 방식으로 두고, 매장이 고르고 고쳐 자기 가게에 맞춘다**(사용자의 말로는 "개인화"). 이 절이 묶음 문서의 "답 뒤에 만든다"·"가정"보다 앞선다.

| 무엇 | 기본값(업계에서 흔한 방식) | 매장이 바꿀 수 있는 것 |
|---|---|---|
| 정기권의 종류 | 횟수권과 금액권 둘 다. 덤을 줄 수 있다 | 팔 때 금액·횟수·기간·덤을 자유롭게, 자주 파는 조건을 저장 |
| 횟수권 1회가 덮는 것 | 그날의 미용 한 번 전체(추가 항목만 따로) | 매장 설정에서 `회당 금액까지만 덮고 차액을 받기` 로 바꿀 수 있다. 판 권은 팔 때의 방식을 지닌다 |
| 가격이 갈리는 기준 | 견종과 몸무게 둘 다(그루머노트의 방식) | 어림은 둘 다 쓴다. 가격표를 넣는 매장은 견종만·몸무게만·둘 다 가운데 자기 방식으로 넣는다 |
| 견종 적기 | 목록에서 고르고, 없으면 직접 적는다(비슷한 이름이 있으면 그것을 권한다) | 직접 적은 견종은 그 매장의 목록에 남는다 |
| 네이버 예약 | 견본을 기다리지 않고 만든다(읽은 값은 "짐작") | 견본이 오면 보강한다 |

고정으로 두는 것과 까닭(바꾸려면 사용자에게 묻는다):

- 가족 초대는 하루·한 번·3명까지 — 초대 주소가 엉뚱한 사람에게 갔을 때의 피해를 줄인다.
