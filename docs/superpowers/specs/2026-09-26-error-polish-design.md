# 차곡노트 — 오류 화면 다듬기 설계

- 작성일: 2026-09-26
- 상태: 사용자 검토 대기
- 범위: Flutter 앱만. 오류 원인 분류와 문구, 화면 본문 틀 `AsyncBody`(얇은 띠·인터넷 복귀 자동 다시 불러오기·당겨서 새로고침), 업로드 대기열의 멈춤, 스플래시 오류, 앱 문구 해요체 전환. 서버는 바꾸지 않는다.
- 앞선 문서: `docs/superpowers/specs/2026-09-24-record-media-design.md` 14절(④-2 뒤 작은 계획)·10.2(업로드 대기열), `_docs/decisions/007-record-media.md`
- 다음 단계: 이 문서가 승인되면 구현 계획 하나를 쓴다(참조 트리에서 먼저 검증).

---

## 1. 목표

지금 앱은 오류를 이렇게 다룬다.

- `core/error/error_messages.dart`의 `messageFor()`가 코드로 문구를 고른다. 원인 구분은 `NETWORK` 하나뿐이고, 서버 5xx 는 공통 문구로 떨어진다.
- `AppErrorRetry`(가운데·`inline`·`row`)를 27곳이 쓴다. 새로 불러오다 실패하면 `.when(error:)` 때문에 이미 보이던 데이터가 오류 화면으로 통째로 바뀐다.
- 인터넷 복귀 신호 `networkWatcherProvider`는 업로드 대기열만 쓴다.
- 당겨서 새로고침이 한 곳도 없다.
- 대기열은 모든 실패를 끝없이 다시 시도한다. 한도 초과처럼 다시 해도 안 되는 실패도 "대기 중"으로만 보인다.

이 문서가 끝나면:

1. 오류는 원인(인터넷 없음·서버·권한·없음·그 밖)별 문구와 원인에 맞는 행동을 보인다.
2. 이미 받은 데이터는 그대로 두고 위에 얇은 띠를 띄운다. 인터넷이 돌아오면 보이는 화면이 스스로 다시 불러온다.
3. 목록·상세 화면은 당겨서 새로고침을 한다.
4. 대기열은 다시 해도 안 되는 실패에서 멈추고, 이유와 [다시 시도]·[올리기 취소]를 보인다.
5. 앱 문구는 해요체다.

유명 앱(인스타그램·유튜브·슬랙·구글 드라이브·카카오톡·토스)의 공통 방식을 따랐다: 잠깐의 실패는 조용히 기다렸다 스스로 잇고, 다시 해도 안 되는 실패는 그 자리에서 멈춰 이유와 다음 행동을 준다.

## 2. 오류 원인과 문구

`core/error/`에 원인 enum `ErrorKind`와 분류 함수 `kindOf(Object error)`를 둔다. 기준은 `ApiException`의 `code`와 `statusCode`만이다.

| 원인 | 기준 | 화면 문구 | 행동 |
|---|---|---|---|
| `offline` | `code == 'NETWORK'`(연결 실패·시간 초과) | 인터넷에 연결되지 않았어요. 연결되면 다시 불러올게요. | [다시 시도] + 복귀 때 자동 |
| `server` | `statusCode >= 500`, 또는 `HTTP_ERROR`(형식 없는 응답 — 게이트웨이 502·503 등) | 서버에 잠시 문제가 있어요. 잠시 뒤 다시 시도해 주세요. | [다시 시도] |
| `denied` | 403 | 코드별 기존 문구(해요체) | 뒤로 갈 수 있으면 [돌아가기], 없으면 문구만 |
| `gone` | 404 | 코드별 기존 문구(해요체) | 뒤로 갈 수 있으면 [돌아가기], 없으면 문구만 |
| `other` | 그 밖(400·409·422 업무 오류, `ApiException`이 아닌 오류) | 코드별 기존 문구, 모르면 공통 문구 | [다시 시도] |

- `CANCELLED`는 오류가 아니다(기존 규칙). `UNAUTHENTICATED`는 지금처럼 라우터가 로그인으로 보낸다. 둘 다 분류 대상이 아니다.
- `messageFor(error)`는 그대로 쓰는 이름이다. 안에서 `offline`·`server`는 원인 문구를, 나머지는 코드별 문구를 고른다.
- 스낵바(저장 실패 등)는 "다시 불러올게요"가 맞지 않으므로 `offline`일 때 "인터넷에 연결되지 않았어요. 연결을 확인해 주세요."를 쓴다. 화면 본문과 스낵바를 가르는 인자 하나를 둔다(`messageFor(error, forAction: true)` 꼴 — 이름은 계획에서 정한다).
- [돌아가기]는 `Navigator.canPop`(go_router `canPop`)이 참일 때만 보인다. 탭 화면은 문구만.

### 2.1 해요체

앱이 쓰는 문구를 해요체로 바꾼다.

- `core/error/error_messages.dart` 문구 전부(약 50개)
- `l10n/app_strings.dart`의 합니다체 문구(약 17개) — 예: "저장했습니다" → "저장했어요", "되돌릴 수 없습니다" → "되돌릴 수 없어요", "준비 중입니다" → "준비 중이에요"
- 코드 안의 대체 문구(`api_exception.dart`·`api_client.dart` 등 10개 남짓 중 화면에 닿는 것)
- "~해 주세요"·"~할까요?"는 이미 해요체라 그대로 둔다.
- 서버 `message`는 바꾸지 않는다(앱이 모르는 코드일 때만 드물게 보인다).
- 문구가 찍힌 골든은 그만큼 갱신한다.

## 3. 화면 틀 `AsyncBody`

`core/error/async_body.dart`에 Riverpod 을 아는 위젯 `AsyncBody<T>`를 둔다. `design/widgets`는 Riverpod 을 모르는 모양 위젯만 두는 규칙이라 여기 둔다.

입력: `AsyncValue<T>`, `onRetry`(다시 불러오기 — 보통 `ref.invalidate`/`refresh`), `builder(T data)`, 선택 `onRefresh`(당겨서 새로고침을 켤 때), 선택 레이아웃(`AppErrorRetry`의 가운데·`inline`).

| 상태 | 보이는 것 |
|---|---|
| 처음 불러오는 중(값 없음) | 가운데 로딩 |
| 실패, 값 없음 | `AppErrorRetry` — 원인 문구 + 원인 행동(2절) |
| 값 있음 + 새로 불러오기 실패 | `builder(data)` 그대로 + 본문 맨 위 `AppErrorBanner` |
| 값 있음(성공) | `builder(data)`, 띠 없음 |

- **자동 다시 불러오기**: `AsyncBody`가 화면에 붙어 있는 동안 `networkWatcherProvider.restored`를 듣고, 지금 상태가 오류이고 원인이 `offline`이면 `onRetry`를 한 번 부른다. 안 보이는 화면은 위젯이 없으니 듣지 않는다.
- **당겨서 새로고침**: `onRefresh`가 있으면 `RefreshIndicator`로 감싼다. 당기는 동안 데이터는 그대로이고, 실패하면 띠가 뜬다. 켜는 곳: 피드, 고객 목록(가족 카드), 하루 예약 목록, 반려동물 [기록] 탭(`PetRecordsView`), 방문 상세, 반려동물 상세. (고객 상세는 따로 된 화면이 없고 고객 목록의 가족 카드다.)
- **다음 쪽 실패**(피드·고객 목록): 목록 끝의 `AppErrorRetry.row`는 그대로 두고 문구만 원인별로. 원인이 `offline`이면 인터넷 복귀 때 다음 쪽을 한 번 다시 부른다.
- **폼 화면**(예약·고객·반려동물 수정, 기록, 설정): 불러오기만 `AsyncBody`로. 저장 실패는 지금처럼 스낵바 — 쓰던 내용을 지우지 않는다.

### 3.1 `AppErrorBanner`

`design/widgets/app_error_banner.dart`. 모양만 담당한다(Riverpod 모름).

- 본문 위 한 줄, 불투명(떠 있는 조작 계층이 아니므로 글래스 아님 — `glass_boundary_test` 규칙).
- 작은 아이콘 + 문구 + 선택 [다시 시도](`server`·`other`에만. `offline`은 스스로 잇는다).
- 문구: `offline` "인터넷에 연결되지 않았어요 · 이전 내용이에요", 그 밖은 원인 문구.
- 나타나고 사라질 때 짧게 미끄러진다.

### 3.2 규칙 테스트

`test/design/`에 구조 테스트를 더한다: `lib/features/**/screens/`가 `AppErrorRetry(`를 `.when(`의 `error:`나 `hasError` 분기 안에서 직접 만들지 않는다 — 불러오기 오류는 `AsyncBody`로. 예외(다음 쪽 실패 `row`, 사진 크게 보기의 원본 실패 등 `AsyncValue`가 아닌 곳)는 목록으로 둔다.

## 4. 업로드 대기열의 멈춤

`features/visit/state/upload_queue.dart`의 실패 처리를 원인으로 나눈다.

| 원인 | 동작 |
|---|---|
| `offline`·`server` | 지금과 같다 — "대기 중", 1·2·4… 최대 5분 간격 재시도, 인터넷 복귀 때 바로 한 번 |
| `denied`·`gone`·`other` | 자동 시도를 멈추고 이유 코드를 항목에 남겨 기기에 저장한다 |

- 예외: `MEDIA_NOT_FOUND`이고 이미 미디어 ID 가 있으면(서버가 붙지 않은 사진을 정리함) 지금처럼 발급부터 다시 한다 — 재시도 쪽.
- 멈춘 항목은 앱을 다시 켜도, 인터넷이 돌아와도 스스로 시작하지 않는다. 로컬 파일은 사용자가 뺄 때까지 남는다(사진이 사라지지 않는다).
- 멈춘 항목도 30장 한도에 센다.
- `UploadJob`에 선택 필드 `stoppedCode`(String?)를 더한다. 저장 JSON 에 없으면 null — 옛 항목은 그대로 읽힌다(옮기기 없음).
- 알림자 메서드 `retry(id)`: `stoppedCode`·`failures`를 지우고 대기열에 다시 태운다.

화면(기록 화면 사진 줄·방문 상세):

- 멈춘 타일은 진행 링 대신 느낌표 표시.
- 누르면 시트: 이유 한 줄(`messageFor`) + [다시 시도] · [올리기 취소].
- 대기 중 타일은 지금처럼 누르면 [올리기 취소]만.
- 버튼 이름 "빼기"를 **"올리기 취소"**로 바꾼다(`AppStrings.removeUpload`). 앨범 사진은 지우지 않는다는 것이 드러나게.

## 5. 스플래시

- 세션 복원이 `offline`으로 실패하면 "인터넷에 연결되지 않았어요. 연결되면 다시 시도할게요." + [다시 시도], 인터넷이 돌아오면 스스로 복원을 다시 한다.
- `server`·`other`는 원인 문구 + [다시 시도].
- 저장된 로그인이 없거나 만료됐으면 지금처럼 로그인 화면.
- 오프라인으로 앱에 들어가지는 않는다 — 서버 데이터를 기기에 두지 않으니 들어가도 보일 것이 없다.

## 6. ④-0에서 모양이 바뀐 세 곳

고객 목록 더 불러오기, 스플래시, 반려동물 상세 [보호자] 탭. 셋 다 이번에 `AsyncBody`·해요체로 옮기므로 모양이 다시 바뀐다. 옛 모양으로 되돌리지 않고 새 규칙의 모양을 골든 기준으로 삼는다.

## 7. 검증

- `flutter analyze` 0, `flutter test` 전부 통과. 골든은 의도한 것(문구·오류 화면·띠)만 갱신.
- 새 테스트: `kindOf` 분류 표, `messageFor` 원인·스낵바 갈래, `AsyncBody` 네 상태·복귀 자동 다시 불러오기(오류가 `offline`일 때만)·당겨서 새로고침·[돌아가기], `AppErrorBanner` 골든, 대기열 멈춤·`retry`·재시작 뒤에도 멈춤·옛 JSON 읽기·`MEDIA_NOT_FOUND` 예외, 피드·고객 목록 다음 쪽 실패와 복귀, 스플래시 복귀, 구조 테스트(3.2).
- 시뮬레이터 흐름 하나: 게이트웨이 멈춤(또는 비행기 모드) → 띠 → 복구 → 띠 사라짐.
- 서버 변경 없음. 백엔드 테스트 불필요.

## 8. 이번에 하지 않는 것

- 서버 데이터를 기기에 저장해 두는 오프라인 모드
- 앱 전체 오프라인 띠(화면별 띠로 정함)
- 서버 문구 해요체 전환
- 멈춘 PUT 감시(④-2a에서 미룸 — 성격이 달라 따로)
