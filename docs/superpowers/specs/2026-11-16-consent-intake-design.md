# ⑪ 전자 동의서 + 첫 방문 문진표 — 설계

2026-11-16. ③-B 설계(`2026-11-14-visit-checks-design.md`)가 "하지 않는 것"으로 미뤄 둔 전자 동의서와, 경쟁 조사(`.superpowers/research/reports/펫미용 앱 경쟁 기능 비교.md` 1순위)가 권한 첫 방문 문진표를 한 묶음으로 만든다. 둘 다 **보호자가 로그인 없이 웹에서 적어 보내는 서류**다. 여섯 묶음이 함께 따르는 기준은 `2026-11-16-next-designs-common.md`(아래 "공통")이고, 어긋나면 그쪽이 앞선다. 공통 4절 "한 번에 보내기"는 이 묶음이 만든다(3.5).

사용자의 기준(2026-11-16): 자동화할 수 있는 것은 자동화한다 · 사장님과 보호자 모두 경쟁사보다 압도적으로 편해야 한다 · 그렇다고 핵심 기능·설명·바꿀 수 있는 길을 빼지 않는다(빈칸·고정값 금지) · 널리 쓰는 말은 그대로 쓴다. **아래의 문안·항목·기준값·화면 자리는 내가 정한 것이고**, 사용자만 답할 수 있는 것은 10절에 모았다.

## 1. 왜

- 지금 미용 동의는 "받았다"는 표시뿐이다(`pets.grooming_consent_on`). 종이나 말로 받은 것을 사장이 적는다. 무엇을 읽고 동의했는지가 남지 않는다.
- 새 손님의 정보는 카카오톡으로 주고받은 것을 사장이 다시 친다. 첫 매장은 이 일을 별도 신청서 웹으로 하고 있다.
- 경쟁사: 그루머노트는 카카오톡 서명 동의서를 월 12,900원 구간에, 포들리는 동의서를 팀 플랜에(문안 고치기는 준비 중인 상위 플랜에) 두고, 반짝은 내용을 편집해 작성 요청을 보내고, 티피는 매장이 템플릿을 직접 만들어야 하며 예약과 동시에 서명 요청이 나간다(리뷰: "너무 불편하고 복잡해요 … 교육 들어야 된다고"). 드러난 단점은 셋이다 — **먼저 만들어야 쓸 수 있다, 유료 구간이다, 예약마다 다시 서명한다.** **근거가 약하다**: 리뷰 표본이 앱스토어 수십 건이고, 본인 인증·서명본 보관 방식은 어느 제품에서도 확인하지 못했다.

## 2. 목표와 하지 않는 것

**목표**

- **만들어 둘 것이 없다.** 기본 문안과 기본 문진표 항목이 채워져 있어 첫날부터 보낸다. **그리고 전부 바꿀 수 있다** — 문안 전체, 문진표의 항목과 질문, 링크 기간, 보내는 글.
- 예약을 잡으면 그 예약에 필요한 서류 링크가 **보낼 것 묶음에 이미 들어 있다.** 공유 한 번이다.
- 보호자는 **한 번 서명하면 기한(365일) 동안 다시 서명하지 않는다.** 노령이 되거나 지병이 더해졌을 때 **바뀐 토막만** 다시 읽고 서명한다.
- 첫 방문은 **링크 하나**에서 문진표와 동의서가 끝난다. 매장에 와 있는 보호자는 **사장 폰에서 바로** 서명한다.
- 서명한 것이 남는다 — 읽은 문안의 판, 그때 보인 사실(아이 이름·지병 이름), 적은 이름, 손가락 서명, 시각.
- 새 손님이 문진표를 적어 보내면 사장은 **확인만** 하고 등록한다. 다시 치지 않는다. 0원이다.

**하지 않는 것**

| 항목 | 까닭·때 |
|---|---|
| 본인 인증(휴대폰·카카오 인증) | 유료 외부 서비스다. 서명한 사람이 누구인지 증명하지 않는다. |
| "법적 효력"이라는 말 | 화면·문서·알림 어디에도 쓰지 않는다. 기본 문안은 법률 검토를 받지 않았다(10절). |
| 알림톡으로 저절로 보내기 | 실발송을 붙인 뒤다. 그때까지는 준비된 묶음을 공유 시트로 한 번 눌러 보낸다(공통 2절). |
| 문진표의 답을 저절로 고객 정보에 반영 | 사람이 확인한다(공통 2절). 앱은 번호가 같은 고객을 찾아 **연결만 미리** 해 둔다. |
| 예방접종 증명, 사진 첨부(원하는 스타일 사진) | 로그인 없는 경로에 파일 올리기를 열지 않는다. 글로만 받는다. 요청이 나오면. |
| 호텔·유치원용 동의서, 마취·의료 행위 동의 | 범위 밖이다. 매장이 기본 토막의 글을 고쳐 넣을 수는 있다. |
| 토막이 붙는 기준(10살)·기한(365일)을 매장이 바꾸기 | ③-B 의 판정과 한 몸이라 이 묶음만으로 바꿀 수 없다(10절 질문 2). |
| 서명한 접속 주소(IP)·기기 정보 저장 | 개인정보를 더 쌓지 않는다. 횟수 제한에만 쓰고 버린다. |
| 히스하우스 신청서 옮기기 | 별도 프로젝트다. 건드리지 않는다 — 나중에 이 문진표로 옮길 수 있다. |
| 받은 문진표 알림(푸시) | 푸시가 없다. 고객 탭을 열 때 보인다. |

**이렇게 되면 실패다**: 링크를 주운 사람이 매장의 다른 고객 정보를 본다 · 내부 메모·지병 메모·주의 사유가 서류 화면에 실린다 · 익명화한 고객의 서명 그림·이름·문진표가 남는다 · 서명했는데 `consent` 가 그대로다 · 지병이 더해진 뒤 옛 서명이 새 지병까지 덮는다 · 문진표가 사람 확인 없이 고객을 만들거나 고친다 · 빈칸이 든 글이 보호자에게 나간다 · 잘못 보낸 링크를 끊을 길이 없다 · 토큰이 로그에 남는다.

## 3. 무엇을 만드나

### 3.1 서류 링크 — 둘이 함께 쓰는 틀

- 서류 요청 하나가 링크 하나다. 알림장 링크와 같은 모양이다 — DB 에는 `public_id`(16바이트)만 있고 토큰은 `base64url(public_id ‖ HMAC)[43글자]` 로 그때마다 계산한다. 주소는 `{REPORT_WEB_BASE_URL}/f/{토큰}`.
- 키는 `REPORT_LINK_KEY` 를 그대로 쓰되 **서명 대상 앞에 `form:` 을 붙인다**. 알림장 토큰을 서류 경로에 넣어도, 그 반대도 맞지 않는다. 새 비밀값이 없다.
- 웹 서버가 백엔드를 부를 때 토큰은 헤더 **`X-Form-Token`** 에 싣는다(알림장의 `X-Report-Token` 과 같은 규칙 — 경로·질의에 두지 않고, 로그·문서·커밋에 남기지 않는다).
- **기간은 기본 14일이고 매장이 바꾼다**(1~30일, 서류 설정). 알림장보다 짧은 기본값인 까닭: 서류는 곧 할 일이고 문진표는 전화번호를 받는 창구다. 30일을 넘기지 않는 까닭도 같다.
- **한 번 내면 닫힌다**(문진표만 `다른 아이도 적기` 로 이어 낼 수 있다 — 3.4). 낸 뒤 같은 링크를 열면 "보냈어요"와 낸 날만 보인다(낸 내용은 다시 보이지 않는다). 닫힌 이유(끊음·기간·매장 정지)는 가르지 않는다.
- **매장이 끊을 수 있고, 끊는 자리가 화면에 있다**(3.6 의 `보낸 서류`). 같은 대상에 살아 있는 요청이 있으면 [보내기]는 **같은 링크**를 돌려준다(다시 공유). 기간이 지난 줄은 발급이 먼저 닫는다.
- 횟수 제한은 알림장의 것(접속 주소당 조회 수, 서명이 틀린 토큰의 실패 수 차단)을 같은 규칙·**다른 이름 공간**으로 쓴다. 제출은 접속 주소당 10분에 10번을 넘으면 429. 카카오톡 미리보기 수집기의 조회도 이 수에 든다 — 웹은 미리보기와 본문이 한 요청에서 백엔드를 한 번만 부른다.

### 3.2 동의서 — 문안

**토막 셋이고, 기본 글이 채워져 있고, 매장이 글 전체를 고친다.** 아이의 지금 사실로 필요한 토막만 이어 붙인다.

| 토막 | 붙는 조건 | 기본 글의 요지(글자는 계획에서 굳힌다) |
|---|---|---|
| `basic` 미용 안내 | 늘 | 미용 중 생길 수 있는 일(피부 자극·작은 상처, 엉킨 털은 짧게 밀 수 있음, 낯선 환경의 스트레스) · 아이가 힘들어하면 미용을 멈추거나 줄일 수 있음 · 건강 상태를 사실대로 알렸음 · 응급 때 보호자에게 연락하고 가까운 동물병원으로 옮길 수 있음 |
| `senior` 노령 | 10살 이상(③-B 의 `age_on`·`SENIOR_AGE`) | 나이가 많은 아이는 미용의 부담이 크고 숨은 질환이 드러날 수 있음 · 서 있기 힘들어하면 마무리가 고르지 않을 수 있음 |
| `condition` 지병 | `pet_conditions` 가 하나라도 있음 | 알려 주신 지병 때문에 미용 중·뒤에 상태가 나빠질 수 있음 · 수의사와 상의했는지는 보호자가 확인 |

- **지병의 이름 목록은 글 밖에서 늘 따로 그린다**(`알려 주신 지병: 심장 · 피부`). 매장이 `condition` 의 글을 어떻게 고쳐도 무엇에 동의하는지가 빠지지 않는다.
- **매장의 글**: 토막마다 2,000자까지. 고치면 **새 판**이 쌓이고(옛 판은 지우지 않는다 — 옛 서명을 그 글자로 다시 보여야 한다) **그 뒤의 서명부터** 새 글이다. 이미 받은 동의를 다시 받게 하지 않는다. [기본 글로 되돌리기]가 있다. 글을 비워 저장할 수 없다(빈칸 금지 — 비우려면 기본 글로 되돌린다).
- 기본 글도 판이 있다(코드 상수, `customer/domain/services/consent_text.py`). 매장이 고치지 않은 토막은 기본 글의 최신 판을 쓴다.
- **문안은 열 때 조립한다**(발급 때가 아니다). 보낸 뒤 지병이 더해졌으면 보호자는 더해진 것을 읽는다.

### 3.3 동의서 — 서명과 기한

**무엇을 다시 묻나**(③-B 의 규칙을 넓힌다 — 지금 코드: 판정은 노령이거나 지병이 있을 때만 뜨고, 기한은 받은 날부터 365일, 지병 종류가 늘면 받은 날을 지운다).

- 살아 있는 동의가 **덮는 토막**을 계산한다(`customer/domain/services/consent_coverage.py`, 순수 함수).
  - 받은 날이 없거나 365일이 지났으면 덮는 것이 없다 → 필요한 토막 전부.
  - **서명으로 받은 동의**(받은 날을 찍은 서명이 있다): `basic` 은 덮였다. `senior` 는 그 서명과 그 뒤의 서명 가운데 `senior` 토막이 든 것이 있으면 덮였다. `condition` 은 지금 지병의 이름이 모두 그 서명들이 보인 지병 이름 안에 있으면 덮였다.
  - **손으로 적은 동의**([받았어요] — 종이·말): 무엇을 읽었는지 기록이 없으므로 토막을 가르지 않는다. 지금처럼 지병이 늘면 받은 날을 지우고, 받은 날에는 노령이 아니었는데 지금 노령이면 덮지 않은 것으로 본다 → 전체를 다시.
- **지병이 늘 때**: 서명으로 받은 동의면 받은 날을 **지우지 않는다**(`condition` 만 덮이지 않은 것이 된다). 손으로 적은 동의면 지금처럼 지운다.
- 확인할 것의 `consent` 항목은 "필요한 토막 − 덮인 토막"이 남으면 뜬다. 상태는 `missing`(덮인 것 없음)·`expired`(기한 지남)·**`partial`(바뀐 토막만 남음)** 셋이고, 남은 토막을 싣는다.
- **보호자가 읽는 것은 남은 토막뿐이다.** `partial` 이면 화면 위에 `지난번(2026년 3월 2일)에 동의하신 내용에 더해 바뀐 부분만 확인해 주세요` 한 줄.
- **부분 서명은 받은 날을 옮기지 않는다.** 기한은 처음 전체를 받은 날부터 365일이다 — 가장 오래된 토막이 365일을 넘지 않는다. 기한이 지나면 전체를 다시 받는다.

**서명**

- 적은 이름(1~50자, 필수) + 손가락 서명(필수) + `위 내용을 읽었고 동의합니다` 체크.
- **서명 그림**: 논리 크기 600×240 으로 고정해 그린다(화면 배율을 곱하지 않고 CSS 로만 늘린다). 검은 선의 PNG 는 보통 5~20KB 다. 64KB 를 넘으면 웹·앱이 300×120 으로 다시 그려 보내고, 그래도 넘으면 `서명을 조금 간단하게 다시 적어 주세요`. 서버는 PNG 머리와 폭·높이(600×240 이하), 크기만 본다.
- **낼 때 다시 견준다.** 열 때 서버가 보여 준 것의 지문(`doc_digest` — 아이마다 이름·남은 토막·토막의 판·지병 이름 목록을 정한 순서로 이어 해시)을 웹이 그대로 돌려보낸다. 서버는 고객 행을 잠근 뒤 다시 계산해 **하나라도 다르면 409** — 지병이 하나에서 둘이 돼도, 아이 이름이 바뀌어도, 매장이 그 사이 글을 고쳐도 다르다. 웹은 `내용이 바뀌었어요. 다시 읽어 주세요` 와 새 문안을 그린다. 서명은 저장하지 않는다.
- **서명이 남기는 것**: 아이마다 토막과 그 판, 그때 보인 아이 이름·지병 이름들(글자 그대로의 사본), 적은 이름, 서명 그림, 서명 시각, 받은 길(`link`·`in_shop`), 보낸(받은) 멤버.
- **서명하면** 전체 서명일 때 `pets.grooming_consent_on` 이 그날(매장 시간대)로, `grooming_consent_by_member_id` 가 보낸 멤버로, `grooming_consent_signature_id` 가 그 서명으로 찍힌다. 부분 서명은 받은 날을 두고 덮는 토막만 는다. 손으로 [받았어요]를 누르면 `grooming_consent_signature_id` 가 비워진다.
- **가족이 함께 오면 한 번에.** 동의서 요청 하나가 같은 가족의 아이 여럿을 담는다. 문안은 아이별 구역으로 보이고(같은 토막의 글은 한 번만, 아이 이름과 지병 목록은 아이마다) 이름과 서명은 한 번이다(10절 질문 3).
- 노령도 지병도 아닌 아이에게도 보낼 수 있다(`basic` 만). 막지 않는다 — ③-B 와 같다.
- 무지개다리를 건넌 아이·익명화한 고객에게는 보낼 수 없고, 살아 있던 링크는 닫힌 것으로 읽힌다. 보호자만의 방문에는 동의서가 없다.

**매장에서 바로 서명**: `consent` 항목의 [여기서 서명]을 누르면 앱이 같은 문안·이름 칸·서명 칸을 **네이티브 화면**으로 띄운다(웹뷰가 아니다). 폰을 보호자에게 건네고, 낸 뒤에는 `보냈어요` 한 장에서 사장이 [닫기]를 눌러야 앱으로 돌아간다 — 서명 화면에서 뒤로 가도 매장의 다른 화면이 보이지 않게 그 화면만 떠 있다. 링크가 없으니 서류 요청 행도 없다.

### 3.4 문진표

- **보내는 곳 셋**: (가) 새 손님 — 고객 탭. (나) 등록된 고객의 **새 아이** — 고객 상세. (다) 이미 있는 아이의 정보를 **다시 받기** — 반려동물 상세.
- **기본 항목**(내가 정한 것 — 등록 요청 스키마 `PetFieldsSchema`·DB 의 길이에 맞췄다). 글자를 치는 칸은 필수 기준 넷뿐이고 나머지는 고르는 칸이다.

| 묶음 | 칸 | 필수 | 뺄 수 있나 |
|---|---|---|---|
| 보호자 | 이름(50자), 전화번호 | (가)에서 필수. (나)·(다)에서는 묻지 않는다 | 아니오 — 누구의 답인지 알 수 없다 |
| 아이 | 이름(50자) | 필수 | 아니오 |
| 아이 | 종(강아지·고양이), 품종(자주 쓰는 품종 고르기 + 직접 적기), 성별, 중성화 | 필수 — 고르는 칸 | 예 |
| 아이 | 생일 또는 태어난 해 또는 `몰라요` | 필수(셋 중 하나) | 예 |
| 아이 | 몸무게 또는 **`모르겠어요`** | 필수(둘 중 하나) | 예 |
| 건강 | 지병 칩(`pet_condition_types` 의 목록 + 기타 한 줄 30자) 또는 `없어요`. **고른 지병마다 알려 줄 것 한 줄(100자)** | `없어요` 나 하나 이상 | 아니오 — 동의서 토막이 이것으로 정해진다 |
| 성격 | 싫어하는 것·조심할 것(200자) — 예: 발 만지기, 드라이기 소리 | 아니오 | 예 |
| 스타일 | 원하는 스타일(200자) | 아니오 | 예 |
| 매장이 더한 질문 | 질문마다 답 한 줄(200자) | 매장이 정한다 | — |
| 안내 | 개인정보 수집·이용 안내(항목·목적·보관 기간)와 동의 체크 | 필수 | 아니오 |

- **매장이 바꾸는 것**(서류 설정): 뺄 수 있는 항목을 켜고 끄기, 질문 더하기(최대 5개, 질문 글 100자, 필수 여부). 보호자·아이 이름·지병·안내는 끌 수 없다(까닭은 표).
- **빈칸을 두지 않는다.** 매장이 끈 항목이나 보호자가 `모르겠어요` 를 고른 몸무게처럼 등록에 꼭 있어야 하는 값(품종·성별·중성화·몸무게는 `pets` 의 NOT NULL 이다)이 비면, **등록할 때 그 칸만 사장에게 묻는다.** 지어내거나 0 으로 채우지 않는다.
- 한 링크에 아이 한 마리다. 낸 뒤 화면에 `다른 아이도 적기` 가 있어 같은 링크로 한 마리씩 더 낸다(보호자 칸은 다시 묻지 않는다) — 링크는 마지막 답을 낸 뒤 [다 적었어요]나 기간으로 닫힌다.
- **(다) 다시 받기**는 아이 이름만 보이고 칸은 비어 있다(`바뀐 것만 적어 주세요`). 지금 값을 공개 화면에 싣지 않는다 — 링크를 주운 사람이 본다.
- **문진표 끝에서 동의서까지**: 답으로 보아 노령(생일·태어난 해로 10살 이상)이거나 지병을 골랐으면, 같은 화면 아래에 그 답으로 조립한 동의서 토막과 이름·서명 칸이 나타난다. 그렇지 않은 아이에게는 나타나지 않는다(③-B 가 묻지 않는 아이에게 일을 더하지 않는다). 서류 설정의 `첫 방문 문진표에서 모든 아이에게 동의서 받기`(기본 꺼짐)를 켜면 늘 나타난다(`basic`).
  - 이 서명은 **아이 없이 맡아 둔다.** 사장이 등록·반영을 저장할 때 그 아이에게 옮겨 붙고 받은 날이 찍힌다.
  - 사장이 등록하면서 답과 다르게 고쳤으면(지병을 더했다) 덮는 토막 계산이 남은 것을 알아서 `partial` 로 남긴다 — 맡아 둔 서명은 **자기가 보인 지병 이름만** 덮는다.
- **낸 것은 "받은 문진표"다.** 고객·반려동물 표를 건드리지 않는다.
  - **번호가 같은 고객을 미리 찾아 둔다.** (가)의 답을 받을 때 서버가 그 매장에서 전화번호가 같은 고객을 찾아 답에 적어 둔다. 받은 문진표에 `등록된 고객 · 김OO 님의 새 아이로` 가 미리 골라져 있다. 사장이 `새 고객으로` 로 바꿀 수는 없다(번호는 매장 안에서 유일하다) — 다른 사람이면 번호를 고쳐 등록한다.
  - **[이대로 등록]** — 답이 다 차 있으면 한 장의 요약(보호자·아이·지병·메모 초안)을 보고 한 번 눌러 끝난다. 줄을 누르면 그 칸을 고친다. 빈 필수 칸이 있으면 그 칸을 먼저 묻는다. 저장은 기존 유스케이스(`register_customer`·`add_pet`·`update_pet`)다.
  - **[지우기]**.
- "성격"·"스타일"·매장이 더한 질문의 답은 반려동물 메모(`pets.memo`, 500자) 초안에 `조심할 것: … / 원하는 스타일: … / {질문}: …` 로 들어가고 사장이 고친다. **500자를 넘으면 자르지 않는다** — 요약 장에 넘친 글자 수를 보이고 줄여야 저장된다. (다)에서 기존 메모가 있으면 덮지 않고, 기존 글과 답을 나란히 보여 사장이 고른다. 지병마다의 한 줄은 그 지병의 메모(`pet_conditions.note`, 100자)로 들어간다. **글은 기존 쓰기를 거쳐 들어가므로 `SearchSourceChanged` 가 그대로 나가고 기록 검색에 걸린다** — 문진표 표 자체는 검색 원본이 아니다.
- 등록·반영이 끝나거나 지우면 **받은 문진표의 답은 지운다**(요청 줄만 남는다). 답을 지우는 것은 **반려동물을 저장하는 요청 하나**(`register_customer`·`add_pet`·`update_pet`)다 — 지병은 그 요청의 `conditions` 로 함께 간다.
- **확인하지 않은 답은 기본 30일 뒤 지운다**(7~90일, 서류 설정). API 프로세스의 주기 작업(`customer/app/services/form_sweeper.py`, 하루 한 번, `system_context`)이 지우고, 그 전이라도 읽을 때는 없는 것으로 친다. 새 손님의 답은 고객과 이어지지 않아 익명화로는 지워지지 않으므로 이 작업이 유일한 길이다 — 운영자가 손으로 돌리는 것에 맡기지 않는다. 맡아 둔 서명도 함께 지운다.

### 3.5 한 번에 보내기 — 예약의 보낼 것 묶음 (공통 4절)

- 예약을 저장하면 앱이 **보낼 것 시트**를 띄운다. 그 예약에 보호자에게 보낼 것이 토막으로 들어 있다.
  - `reservation` 예약 접수 안내(날짜·시간·메뉴) — `visit` 이 만든다.
  - `consent` 동의서 링크 — 그 예약의 아이들 가운데 `consent` 가 뜬 아이가 있으면. **링크는 이때 만들어져 있다**(살아 있는 요청이 있으면 그것). 사장이 만들 것이 없다.
  - `intake` 문진표 링크 — 기본은 빠져 있고, 시트의 `문진표도 보내기` 로 더한다(등록할 때 사장이 이미 적은 손님에게 또 묻지 않는다).
  - 뒤의 묶음이 자기 토막을 더한다(⑮ `deposit`).
- **토막은 `{kind, text}` 의 목록이다.** 앱은 모르는 `kind` 도 글 그대로 싣는다(서버가 토막을 더해도 옛 앱이 죽지 않는다).
- 시트에서 **글을 고칠 수 있고 토막을 뺄 수 있다.** [보내기]는 공유 시트 한 번이다. 보내지 않고 닫아도 예약은 저장돼 있고, 방문 상세의 [보호자에게 보내기]로 다시 연다.
- **빈칸이 든 글은 나가지 않는다.** 토막에 들어갈 값(매장 이름 등)이 비어 있으면 시트가 그 칸만 먼저 묻는다.
- 토막의 기본 글(템플릿)은 매장이 고친다(서류 설정의 `보호자에게 보내는 글`). 주소가 들어갈 자리(`{링크}`)는 지울 수 없다.
- 알림톡 실발송이 붙으면 같은 토막이 알림 종류로 간다(나중).
- **서명이 안 된 채 예약 전날이 되면** `consent` 가 확인할 것에 그대로 남아 하루 목록의 `확인 N` 에 세어진다(③-B 그대로). 항목에 `동의서를 보냈어요 · 서명 전` 과 [다시 공유]·[여기서 서명]이 있다.

### 3.6 화면

톤은 지금 그대로다(무채색, 잉크색 글자, 가는 선). "AI"·"법적 효력"이라는 말이 없다. 화면의 자리는 공통 8절을 따른다.

**앱** (`features/customer`·`features/visit`, 쓰기는 `CustomerCommands`)

1. **보낼 것 시트**(3.5) — 예약 저장 뒤, 방문 상세의 [보호자에게 보내기].
2. **방문 상세·예약 등록의 `consent` 항목**(확인할 것 안) — 상태 한 줄(`노령 · 지병 — 동의서가 필요해요` / `바뀐 부분만 다시 받아요` / `동의서를 보냈어요 · 서명 전`)과 [동의서 보내기]·[여기서 서명]·[받았어요](종이·말). 서명되면 항목이 사라진다.
3. **반려동물 상세 · 정보 탭의 동의 줄** — `미용 동의 · 2026년 11월 16일에 서명 받음`(손 표시면 `받았다고 적음`)과 [서명 보기]. [서명 보기]는 그 판의 글자·보인 사실·적은 이름·서명 그림·시각·받은 길 한 장이고 `링크를 받은 분이 적은 서명이에요` 가 적혀 있다. 지난 서명이 여럿이면 날짜 목록.
4. **고객 탭** — 받은 문진표가 있을 때만 목록 위에 `받은 문진표 2`. 누르면 목록(아이 이름·보호자 이름·받은 날·`등록된 고객` 표시) → 한 장(답 전부, [이대로 등록], [지우기]). 고객 등록의 첫 화면에 `문진표 링크 보내기`. 고객 상세에 `새 아이 문진표 보내기`, 반려동물 상세 · 보호자 탭 맨 아래에 `문진표 다시 받기`.
5. **보낸 서류**(고객 탭의 `보낸 서류 3` — 살아 있는 요청이 있을 때만) — 종류·대상(새 손님용은 `새 손님 · 11월 16일에 보냄`)·남은 날, 줄마다 [다시 공유]·**[링크 끊기]**. 잘못 보낸 링크를 여기서 끊는다. `consent` 항목과 동의 줄의 `⋯` 에도 [링크 끊기]가 있다.
6. **서류 설정**(공통 3절·8절 — 줄 이름이 곧 설명이고, 줄 아래에 **보호자가 받는 모습**이 그대로 보인다). `shop:update`(사장).
   - `동의서에 적힌 글` → 토막 셋. 토막마다 언제 붙는지 한 줄(`10살 이상인 아이에게 보여요`)과 글 편집, [기본 글로 되돌리기], 미리 보기.
   - `문진표에서 물어볼 것` → 항목 켜고 끄기, 질문 더하기, 미리 보기.
   - `보호자에게 보내는 글` → 토막별 템플릿.
   - `링크를 열 수 있는 기간` 14일 · `확인하지 않은 문진표를 지우는 때` 30일 · `첫 방문 문진표에서 모든 아이에게 동의서 받기`.
   - 아무것도 건드리지 않아도 기본값으로 돈다.
7. 서명 그림은 앱이 받은 바이트를 그대로 그린다(네이티브 이미지). 현장 서명 칸은 `CustomPainter` 다. 웹뷰가 없다.

**웹** (`web/`, 경로 `app/f/[token]/page.tsx` · 제출 `app/f/[token]/submit/route.ts`)

8. **동의서** — 매장 이름, 아이 이름(들), 지병 목록, 남은 토막들, 이름 칸, 서명 칸(손가락·마우스, [다시 쓰기]), 체크, [동의하고 보내기]. 서명 칸은 `'use client'` 다. 자바스크립트를 끈 브라우저에는 `서명하려면 자바스크립트를 켜 주세요` 한 줄.
9. **문진표** — 3.4 의 칸. 한 화면 세로 스크롤. 고르는 칸은 칩·토글이다. 조건이 되면 아래에 동의서 구역이 이어진다. 폭 320 에서 가로로 넘치지 않는다.
10. **낸 뒤·닫힘·없음·잠시 후** — 알림장의 화면 넷과 같은 규칙(200·404 뿐, 닫힌 이유를 가르지 않는다). 낸 뒤는 `보냈어요. {매장 이름}에서 확인할게요.`
11. 제출은 폼 POST → 경로 핸들러 → 303 으로 같은 주소다. `Sec-Fetch-Site` 가 있고 `same-origin` 이 아니면 403. 응답 헤더 셋(`noindex`·`no-store`·`no-referrer`)이 그대로 붙는다. 미리보기(og)는 `{매장 이름}` 과 "미용 동의서"/"문진표"뿐이다 — 아이 이름·지병을 싣지 않는다.

### 3.7 권한

새 권한을 만들지 않는다. 보내기·끊기·현장 서명·등록·반영·지우기는 `require_permission("customer:write")`(사장·직원). 서명 보기·받은 문진표 읽기는 매장 멤버(`get_shop_context`) — 한 건씩 보는 일이라 고객 정보를 보는 것과 같다(공통 9절). 서류 설정은 `shop:update`(사장 — 알림장 설정·예약 설정과 같다). 보낸 사람은 `ShopContext.member_id`.

## 4. 편의 기준 (공통 1절 — 이 묶음의 합격선)

| 누가 | 일 | 기준 | 확인 |
|---|---|---|---|
| 사장 | 첫날 동의서 보내기 | 설정을 한 번도 열지 않고 된다 | 흐름: 새 매장에서 설정 없이 발급·서명 |
| 사장 | 예약에 필요한 서류 보내기 | 예약 저장 뒤 누르기 2번([보내기] → 받는 사람) | 시뮬레이터 흐름이 누른 수를 센다 |
| 사장 | 매장에서 서명 받기 | 누르기 1번([여기서 서명])으로 서명 화면 | 시뮬레이터 흐름 |
| 사장 | 받은 문진표 등록 | 답이 다 찼으면 누르기 2번(줄 → [이대로 등록]). 다시 치는 칸 0 | 시뮬레이터 흐름 |
| 사장 | 같은 것을 두 번 | 링크를 다시 만들지 않는다(같은 링크), 문진표의 글을 다시 치지 않는다 | 통합·흐름 |
| 보호자 | 동의서 | 설치·가입 없음. 글자를 치는 칸 1(이름) + 서명 + 누르기 2. 1분 안 | 웹 e2e 가 칸 수를 고정 |
| 보호자 | 문진표 | 필수로 글자를 치는 칸 4 이하(보호자 이름·번호·아이 이름·품종 직접 적기), 나머지는 고르기 | 웹 e2e 가 필수 칸 수를 고정 |
| 보호자 | 다시 묻지 않기 | 기한 안에는 서명을 다시 받지 않는다. 바뀌면 바뀐 토막만 | 통합(`partial`) |
| 둘 다 | 빈칸 | 빈 값이 든 글·화면이 나가지 않는다 | 단위·흐름 |

설정 줄의 이름은 구현 때 "이름만 보고 무슨 일이 생기는지 맞히기" 검토를 돌린다.

## 5. 어떻게 — 정해 둔 것

### 5.1 어디에 사는가

- **서류는 전부 `customer` 스포크다.** 동의의 사실과 등록이 여기 있다. **보낼 것 묶음의 조립은 `visit`** 이다(예약 접수 안내가 visit 의 것이고 ⑮ 의 예약금도 visit 이다) — 서류 토막은 허브 포트로 받는다.
- **허브 포트 하나를 더한다**: `GuardianFormPort.consent_links(ctx, pet_ids) -> list[FormLink]`(customer 구현 — 그 아이들에게 살아 있는 요청이 있으면 그것, 없으면 만든다. 가족이면 한 요청). visit 의 `dependencies/hub_ports.py` 가 자리로 받고 `main.py` 가 꽂는다.
- **스포크 사이에 나눠 써야 하는 것 셋을 올린다**(알림장의 것은 `visit` 안에 있어 `customer` 가 import 할 수 없다). 이름과 동작은 그대로다.
  - 토큰 만들기·읽기 `visit/domain/services/report_token.py` → `core/`(순수 함수). 서명 대상에 붙일 앞말(`b""` / `b"form:"`)을 인자로 받는다.
  - 접속 주소 `visit/dependencies/public_client.py` 와 횟수 제한(`PublicReportLimiterPort`·Redis 어댑터) → `core/`. 이름 공간을 인자로 받는다.
  - `visit/app/services/public_context.py` → `hub/app/dtos/shop_context.py` 의 `public_context`(`system_context` 옆).
- **`CLAUDE.md` 의 문장을 고친다**(공통 11절). 지금 글은 "둘 다 권한이 비어 있고 포트 읽기에만 쓴다"인데, 서류 제출은 로그인 없는 경로가 고객 스포크의 본표를 쓰는 첫 사례다. 고칠 글: 가드 없이 `ShopContext` 를 만드는 곳은 `hub/app/dtos/shop_context.py` 의 `public_context`·`system_context` 둘뿐 / `public_context` 는 읽기와 **공개 서류 제출이 쓰는 표**(`customer_forms`·`consent_signatures`·`intake_answers`, 그리고 서명이 찍는 `pets` 의 동의 칸 셋)에만 쓴다. 고객·반려동물의 다른 칸은 쓰지 않는다.

### 5.2 자료 모양 (마이그레이션 0018 부터 — 공통 11절)

- `customer_forms` — 서류 요청. `id`, `shop_id`, `kind`(`consent`·`intake`), `public_id bytea(16) unique`, `customer_id null`, `intake_pet_id null`((다)의 아이), `expires_at not null`, `revoked_at`, `submitted_at`, `created_by_member_id`, `created_at`.
  - `customer_form_pets(form_id, pet_id)` — 동의서가 담는 아이들.
  - "아이 하나에 살아 있는 동의서 요청은 하나"는 색인이 아니라 발급 유스케이스가 고객 행을 잠근 안에서 지킨다(요청이 아이 여럿을 담아 부분 유일 색인으로 쓸 수 없다). (다)의 문진표는 `(intake_pet_id) WHERE kind='intake' AND revoked_at IS NULL AND submitted_at IS NULL` 부분 유일.
- `shop_consent_texts` — 매장이 고친 글. `id`, `shop_id`, `part`(`basic`·`senior`·`condition`), `version int`, `body varchar(2000)`, `created_by_member_id`, `created_at`. 쌓기만 한다. `(shop_id, part, version)` 유일. [기본 글로 되돌리기]는 `body null` 인 판을 하나 쌓는다.
- `shop_form_settings` — `shop_id` PK, `link_days smallint`(1~30), `intake_keep_days smallint`(7~90), `consent_for_all bool`, 문진표에서 끈 항목(`intake_hidden_fields`), 보내는 글의 템플릿. 행이 없으면 기본값이다.
  - `shop_intake_questions(id, shop_id, position, label varchar(100), required bool, removed_at)` — 지운 질문도 받은 답이 가리키므로 행은 남긴다.
- `consent_signatures` — 한 번의 서명. `id`, `shop_id`, `form_id null unique`(현장 서명은 없다), `intake_answer_id null`(맡아 둔 서명), `customer_id null`, `channel`(`link`·`in_shop`), `signer_name varchar(50)`, `signature_png bytea`(CHECK `octet_length <= 65536`), `signed_at`, `by_member_id`.
  - `consent_signature_pets(id, signature_id, pet_id null, shown_pet_name)` — 맡아 둔 서명은 `pet_id` 가 비어 있다가 등록 때 채워진다.
  - `consent_signature_parts(signature_pet_id, part, text_source('default'·'shop'), text_version)`.
  - `consent_signature_conditions(signature_pet_id, position, label)` — 그때 보인 지병 이름(사본).
- `pets` 에 `grooming_consent_signature_id bigint null`.
- `intake_answers` — 받은 문진표. `id`, `shop_id`, `form_id`, `matched_customer_id null`, 3.4 의 칸들(등록 화면의 형·길이와 같게, 몸무게는 null = 모르겠어요), `submitted_at`.
  - `intake_answer_conditions(answer_id, type_code, custom_label, note varchar(100))` · `intake_answer_extras(answer_id, question_id, body varchar(200))`.
  - 등록·반영·지우기·주기 작업에서 행을 지운다(`customer_forms` 줄은 남는다).
- 서명 그림은 DB 에 둔다. 미디어 스포크(S3)를 거치지 않는다 — 로그인 없는 경로에 업로드 발급을 열지 않고, 64KB 이하의 그림 한 장이다.

### 5.3 API (모양은 계획에서 굳힌다)

**매장** (`/v1/shops/{id}/…`)

- `POST …/consent-forms` 본문 `{pet_ids}` → `{url, expires_on, sent_at}`(살아 있으면 같은 것) · `GET …/forms`(보낸 서류 — 살아 있는 요청) · `DELETE …/forms/{form_id}`(끊기 — 동의서·문진표 모두).
- `GET …/pets/{pet_id}/consent-document` → 현장 서명용(남은 토막·글자·`doc_digest`) · `POST …/pets/{pet_id}/consent-signatures`(현장 서명 — 본문은 공개 제출과 같다).
- `GET …/pets/{pet_id}/consent-signatures` → 목록 · `GET …/consent-signatures/{id}` → 한 장(그 판의 글자 포함) · `GET …/consent-signatures/{id}/image` → `image/png`.
- `POST …/intake-forms` 본문 `{customer_id: int|null, pet_id: int|null}` → `{url, expires_on}`.
- `GET …/intake-answers`(목록·개수) · `GET …/intake-answers/{id}` · `DELETE …/intake-answers/{id}`. 등록·반영은 `register_customer`·`add_pet`·`update_pet` 요청 본문의 선택 칸 `intake_answer_id` — 같은 트랜잭션에서 맡아 둔 서명을 옮기고 답을 지운다.
- `GET`·`PUT …/form-settings`(전체 교체) · `GET …/consent-texts`(토막별 지금 글과 기본 글) · `PUT …/consent-texts/{part}`.
- `POST …/visits/{visit_id}/send-bundle`(visit) → `{parts: [{kind, text}]}`. 서류 링크가 없으면 이때 만든다(멱등). 응답의 주소는 로그에 남기지 않는다.
- 반려동물 상세 응답에 동의의 길(`signature`·`manual`)과 마지막 서명의 유무. 고객 목록 응답에 받은 문진표 수·보낸 서류 수.
- **`visit` 이 읽는 것**(공통 11절 — 허브 DTO 에 칸을 더한다): `PetCareFact` 에 `consent_uncovered: tuple[str, ...]`(필요한데 덮이지 않은 토막 — customer 가 계산한다)와 `consent_form_sent_on: date | None`. **`consent_form_sent_on` 은 살아 있는 요청(끊지 않았고, 내지 않았고, 기간 안)이 있을 때만 값이 있다** — 끊거나 기간이 지난 요청으로 "보냈어요 · 서명 전"이 뜨지 않는다. `visit_checks._consent` 는 `consent_uncovered` 로 `partial` 을 낸다. 공통 7절대로 `marks` 에는 싣지 않는다.

**공개** (`/v1/public/…`, 로그인 없음 — `route_inspection._PUBLIC_ROUTES` 와 프로세스별 목록 테스트에 더한다)

- `GET /v1/public/form` — 헤더 `X-Form-Token`. `{kind, state(open·submitted), shop: {name}, …}`. 동의서면 아이별 `{pet_name, conditions: [label], parts: [part]}`, 토막의 글자, 지난 동의 날(`partial` 일 때), `doc_digest`. 문진표면 켜진 항목·매장 질문·지병 종류 목록·품종 고르기 목록·토막의 글자(끝의 동의서 구역용)와 (다)일 때 아이 이름.
- `POST /v1/public/form/consent` — `{doc_digest, signer_name, signature_png(base64)}` → 204 / 409(내용 바뀜) / 410 / 404 / 429.
- `POST /v1/public/form/intake` — 3.4 의 칸 + 선택 `consent: {signer_name, signature_png, parts}` → 204 / 422 / 410 / 404 / 429. 동의서 구역이 나타나야 하는 답인데 서명이 없으면 422.
- **공개 스키마는 매장용과 따로 쓰고 칸을 하나하나 적는다.** 싣지 않는 것: 지병 메모, 반려동물 메모, 내부 메모, 주의 표시, 노쇼, 전화번호, 고객·반려동물·매장의 ID, 다른 가족의 아이, (다)의 지금 값.

### 5.4 잠금·트랜잭션 (공통 10절)

- 동의서 발급·끊기·서명(링크·현장): **고객 행(`pets.lock_owner`) → 서류 요청 행**. 서명은 그 안에서 사실을 다시 읽어 지문을 견주고, 서명 행을 쓰고, 받은 날을 찍고, 요청을 닫는다 — 한 트랜잭션. 묶음 조립(`send-bundle`)이 서류를 만들 때도 visit 이 먼저 잡은 고객 행 안에서 포트를 부른다(고객 행 → 서류 요청 행 → 방문 행의 순서를 거스르지 않는다 — 묶음 조립은 방문 행을 잠그지 않는다).
- (가)의 문진표는 고객이 없으니 요청 행만 잠근다(번호가 같은 고객은 잠그지 않고 읽어 적어 둘 뿐이다). (나)·(다)는 고객 행 → 요청 행.
- 등록·반영에서 맡아 둔 서명을 옮기는 것은 그 유스케이스의 트랜잭션 안이다(고객 행을 이미 쥐고 있다).
- 익명화(`delete_customer`): **고객 행 → 서류 요청·서명·문진표 지우기 → (기존) 보호자 연결 행**. 그 고객의 서명 행(그림·이름), 받은 문진표(`matched_customer_id` 가 그 고객인 것 포함), 맡아 둔 서명을 지우고 살아 있는 요청을 끊는다. 루트 `CLAUDE.md` 의 잠금 문단에는 이 묶음의 줄("고객 행 → 서류 요청 행")만 더한다.
- 반려동물 삭제·무지개다리: 살아 있는 요청에서 그 아이를 뺀다(남은 아이가 없으면 끊는다). 서명 기록은 남는다(무지개다리) / 지운다(삭제).
- 잠금을 쥔 채 외부 HTTP 를 부르지 않는다(부를 것이 없다).

### 5.5 로그

- 토큰·주소·서명 그림·적은 이름·문진표의 글·전화번호·매장이 고친 문안을 로그·오류 메시지·예외 문자열에 남기지 않는다. 로그는 `shop_id`·`form_id`·종류·결과뿐이다. 주기 작업은 지운 수만 적는다.
- 웹은 요청 본문·토큰을 `console.*` 에 넣지 않는다(지금 규칙 그대로).

### 5.6 나누기

- **⑪-1 백엔드** — 올리기 셋과 `CLAUDE.md` 고치기(5.1), 표·마이그레이션, 기본 글과 조립·덮는 토막 계산·지문, ③-B 판정 넓히기(`partial`), 매장·공개 경로, 서류 설정, 묶음 조립과 허브 포트, 주기 작업, 익명화·삭제 잇기, 흐름 스크립트 `check_forms_flow.sh`.
- **⑪-2 웹** — `/f/[token]` 동의서·문진표(+끝의 동의서 구역)·낸 뒤·닫힘, 서명 칸, 제출 핸들러, `check:server`·e2e.
- **⑪-3 앱** — 보낼 것 시트, `consent` 항목의 버튼 셋, 현장 서명 화면, 서명 보기, 받은 문진표 목록·요약 장·[이대로 등록], 보낸 서류, 서류 설정, 미리 채움 형(아래), 시뮬레이터 흐름.
- **미리 채움 형**: 문진표의 답으로 등록·수정 화면을 채우는 형(`features/customer` 의 `CustomerPrefill` — 보호자 이름·번호, 아이의 칸들, 빈 필수 칸의 목록)을 여기서 만든다. ⑯ 의 글 붙여넣기는 이 형을 그대로 쓴다(공통 11절).

## 6. 위험과 막는 법

| | 위험 | 막는 법 |
|---|---|---|
| F1 | 링크를 주운 사람이 아이의 지병을 본다 | 추측 불가 토큰 + 기본 14일 + 한 번 내면 닫힘 + **끊는 화면**(보낸 서류). 싣는 것은 아이 이름과 지병 **이름**뿐(메모 없음). 미리보기에 싣지 않는다. 받아들인 한계: 링크를 받은 사람은 본다. |
| F2 | 남이 대신 서명한다 | 본인 인증이 없다 — **받아들인 한계**다. 그래서 "법적 효력"을 말하지 않고, 서명 보기에 `링크를 받은 분이 적은 서명이에요` 를 적는다. |
| F3 | 옛 서명이 새 지병을 덮는다 | 열 때 조립 + 낼 때 지문(지병 이름 목록·아이 이름·판 포함)을 다시 견줘 409. 서명 뒤 지병이 늘면 덮는 토막 계산이 `condition` 을 남긴다(손 표시는 받은 날을 지운다). |
| F4 | 문진표로 쓰레기·대량 제출 | 접속 주소당 제한, 칸마다 길이 제한, 본문 크기 제한(웹·백엔드 둘 다), 한 링크에서 아이는 10마리까지. |
| F5 | 서명 그림에 이상한 파일 | PNG 머리 바이트·폭·높이·크기만 보고 서버는 풀지 않는다. `image/png` 로만 내주고 `nosniff`. |
| F6 | 익명화 뒤 서명·문진표가 남는다 | 같은 트랜잭션에서 지운다. 테스트가 행 수를 본다. 확인 안 한 답과 맡아 둔 서명은 주기 작업이 지운다. |
| F7 | 알림장 토큰과 서류 토큰이 섞인다 | 서명 앞말이 다르다. 테스트: 서로의 경로에서 404. |
| F8 | 공개 응답에 매장용 칸이 샌다 | 공개 스키마를 따로 쓰고 테스트가 칸 목록을 고정한다. |
| F9 | 문진표가 기존 고객을 덮어쓴다 | 저절로 반영하지 않는다. 연결만 미리 해 두고 요약 장에서 사람이 누른다. (다)는 기존 글을 덮지 않고 나란히 보인다. |
| F10 | 올리기(5.1)가 알림장을 깨뜨린다 | 동작을 바꾸지 않는 옮기기다. 알림장의 단위·통합·흐름·e2e 가 그대로 통과해야 한다. |
| F11 | 매장이 고친 글이 핵심을 뺀다 | 지병 이름 목록·아이 이름·체크 문장은 글 밖에서 늘 그린다. 빈 글은 저장되지 않는다. 미리 보기가 받는 모습을 그대로 보인다. 받아들인 한계: 글의 내용은 매장의 책임이다. |
| F12 | 현장 서명 중에 보호자가 매장의 화면을 본다 | 서명 화면만 떠 있고, 낸 뒤 [닫기]는 사장이 누른다. 받아들인 한계: 폰을 건넨 동안의 일은 막지 못한다. |
| F13 | 맡아 둔 서명이 다른 아이에게 붙는다 | 서명은 자기가 보인 이름·지병만 덮고, 옮길 때 답(`intake_answer_id`)으로만 찾는다. 답과 다르게 등록하면 `partial` 로 남는다. |
| F14 | ③-B 판정이 바뀌어 받은 동의가 사라진다 | 손 표시의 규칙은 그대로 두고 서명에만 토막 계산을 더한다. ③-B 의 단위·통합·흐름이 그대로 통과해야 한다. |

## 7. 테스트와 검증

- **백엔드 단위**: 토막 조립(나이 9/10살, 지병 0/1/2개, 무지개다리), 덮는 토막(서명·손 표시·부분 서명·노령 진입·지병 더함·기한), 지문(지병 하나→둘이면 다르다, 이름·판이 바뀌면 다르다), 매장 글의 판, 요청의 상태, 문진표 칸 검증(길이·`모르겠어요`), 묶음 조립(토막의 유무·빈칸). **통합**: 발급이 같은 링크 · 동시 발급 하나 · 서명이 받은 날을 찍고 `consent` 가 사라진다 · 지병이 하나 더해진 뒤 옛 지문으로 409 · `partial` 서명이 받은 날을 옮기지 않는다 · 두 번 내기 410 · 끊은 링크 404 · 다른 매장의 요청 404 · 익명화가 지운다 · 공개 응답의 칸 목록 · 허용 목록 테스트 · 등록이 맡아 둔 서명을 옮기고 답을 지운다 · 번호 연결 · 주기 작업 · 가족 한 서명 · 로그에 토큰·이름이 없다.
- **웹**: 컴포넌트(토막의 유무, 서명 칸과 크기 줄이기, 끝의 동의서 구역, 낸 뒤·닫힘), `check:server`(상태 코드·헤더 셋·미리보기에 아이 이름이 없음·다른 출처 POST 403·기록에 토큰 없음·백엔드 호출 수), e2e(동의서 서명, 문진표 + 서명, 내용 바뀜, 닫힌 링크, 폭 320, **필수 칸 수**).
- **앱**: 보낼 것 시트(고치기·빼기·빈칸 묻기), 버튼 셋, 현장 서명, 서명 보기, [이대로 등록], 보낸 서류의 끊기, 서류 설정, 골든. 시뮬레이터 흐름(iOS·안드로이드): 예약 → 시트 → (준비 스크립트가 웹 서버로 서명) → 항목이 사라짐 → 서명 보기 → 지병 더하기 → `바뀐 부분만` → 현장 서명 → 받은 문진표 → [이대로 등록] → 링크 끊기. **누른 수가 4절의 기준 안인지 흐름이 센다.**
- 흐름 스크립트: 발급 → 공개 읽기 → 서명 → 받은 날 → 지병 더하기 → `partial` → 문진표(+서명) → 등록 → 익명화 뒤 없음.

## 8. 만드는 사람에게 맡기는 것

- 기본 문안의 마지막 글자(요지는 3.2), 개인정보 안내의 글자, 화면 문구의 다듬기.
- 올린 것들의 `core/` 안 정확한 자리와 파일 이름(폴더 작명 규칙을 따른다).
- 서명 칸의 선 굵기, 품종 고르기 목록의 내용.
- 요약 장의 배치, (다)에서 답과 기존 값이 다를 때의 표시.
- 결정 기록은 `_docs/decisions/014-consent-intake.md`.

## 10. 사용자가 정한 것과 남은 것 (2026-11-16)

- **가족이 함께 예약하면 서명 한 번으로 여러 아이의 동의를 받는다** — 사용자 승인.
- **기본 문안**은 차곡노트의 기본 글(미용 동의서에 흔히 드는 항목)로 내보내고 매장이 고친다(공통 12절). 법률 검토를 받지 않았다는 사실은 그대로이고 화면에서 "법적 효력"을 말하지 않는다.
- **노령 기준(10살)과 동의 기한(365일)은 기본값이고 매장이 바꿀 수 있다**(공통 12절). 이 묶음이 ③-B 의 판정(`visit_checks`)이 매장 설정을 읽도록 넓힌다 — 서류 설정에 두 줄, `PetCareFact` 를 만드는 쪽이 매장의 값을 받는다. 값이 없으면 지금의 10·365 다. 본문에서 "③-B 에서 고정이라 하지 않는다"고 적은 곳은 이 줄이 앞선다.

남은 질문은 없다.
