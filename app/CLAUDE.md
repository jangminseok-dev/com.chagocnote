# CLAUDE.md — 차곡노트 앱 (Flutter)

저장소 루트의 `CLAUDE.md` 를 먼저 읽는다. 여기는 앱에만 해당하는 규칙이다.

## 꼭 지킬 것

- **웹뷰 방식 금지.** 웹뷰 패키지를 넣지 않고, 어떤 화면도 인앱 웹뷰로 만들지 않는다. 소셜 로그인도 네이티브 경로다(Apple 버튼은 iOS 만).
- 폴더는 `lib/core/{config,proxy,storage,router,error,time,plugs}` · `lib/design/{tokens,bridge,widgets}` · `lib/features/<기능>/{screens,state,api}` · `lib/l10n` 다. 기능 폴더(`lib/features/<기능>/`) 안은 `screens/` · `state/` · `api/` 세 층만 둔다. 리포지토리·유스케이스·엔티티 계층을 만들지 않는다.
- **기능 폴더 사이의 import 는 방향이 하나다**(`test/design/feature_imports_test.dart`가 잡는다). `auth`는 공용(세션·`selectedShopIdProvider` 등 매장 선택 값·`runShopScoped`)이라 누구나 import 한다. `home`은 조립 껍데기라 다른 기능을 import 하고 아무도 `home`을 import 하지 않는다. `visit → customer`만 허용한다(예약 ①의 고객 검색 재사용). 그 밖은 금지 — 반대 방향이 필요하면 `lib/core/plugs/`에 자리를 두고 `app.dart`의 `buildRoot`가 채운다(지금은 반려동물 상세의 [기록] 탭 `petRecordsPlugProvider` ← visit 의 `PetRecordsView`, 그 탭을 다시 읽는 `petRecordsRefreshPlugProvider` ← `petRecordsRefresher`). 여러 기능이 함께 쓰는 것(시각·날짜 도우미 `core/time`, 오늘 날짜)은 `lib/core/`에 둔다. 화면·상태는 소유하는 기능 폴더에 둔다(메뉴·일정·알림장·알림톡 설정은 `visit/screens/settings/`).
- **매장 범위 화면**은 세션 전체(`sessionControllerProvider`)를 watch 하지 않는다. `auth/state/shop_selection.dart`의 파생 프로바이더(`selectedShopIdProvider`·`isOwnerProvider`·`shopNameProvider`·`shopCountProvider`·`currentUserIdProvider`)만 watch 한다. 매장 선택 전(account·auth 화면: 로그인·스플래시·초대·매장 선택·계정)은 세션 전체를 봐야 하므로 이 규칙 밖이다.
- 플러그인은 `lib/core/proxy/`의 프로바이더로만 부른다 — 클립보드 `clipboardProvider`, 사진 고르기·찍기 `mediaPickerProvider`, 렌디션(리사이즈·EXIF 제거) `photoRenditionMakerProvider`, 인터넷 복귀 신호 `networkWatcherProvider`, 업로드 폴더 `uploadsDirProvider`, 서명 URL 사진 보이기와 원본 받기 `mediaImagesProvider`, 앨범에 저장 `photoAlbumProvider`(확장자 `.mp4`면 영상으로), 영상 고르기·찍기 `MediaPicker.pickVideo`·`takeVideo(maxSeconds:)`, 영상 압축·포스터 `videoTranscoderProvider`(네이티브 `ios/Runner/VideoTranscoder.swift`·`android/app/src/main/kotlin/com/chagocnote/chagocnote/VideoTranscoder.kt` — 채널 `chagocnote/video_transcoder`의 `transcode({source, outDir, maxSeconds})` → `{video, thumb, width, height, durationSeconds, trimmed}`, `cancel()`, 실패 코드 `UNSUPPORTED`·`TOO_SHORT`·`CANCELLED`, 진행률은 이벤트 채널로 0…1), 영상 재생 `videoPlaybackFactoryProvider`(재생 추상 `VideoPlayback`은 `design/widgets/video_playback.dart`, 구현은 `core/proxy/video_playback.dart`), 큰 파일(영상 원본) 임시 받기 `mediaFilesProvider`, 음성 인식 `speechRecognizerProvider`(네이티브 `ios/Runner/SpeechRecognizer.swift`·`android/app/src/main/kotlin/com/chagocnote/chagocnote/SpeechRecognizer.kt` — 채널 `chagocnote/speech`의 `availability()` → `{supported, reason: device|locale}`, `requestPermission()` → `granted|denied`(마이크·음성 인식 둘 다), `start({locale})`·`stop()`·`cancel()`·`openSettings()`, 이벤트 채널 `chagocnote/speech/events`로 `{type: partial|final|ended|error, text?, code?}` — 오류 코드 `denied`·`unsupported`·`noSpeech`·`failed`, 시작 전 실패도 `error`+`ended` 이벤트로 온다), 공유 시트 `shareSheetProvider`(네이티브 `ios/Runner/ShareSheet.swift`·`android/app/src/main/kotlin/com/chagocnote/chagocnote/ShareSheet.kt` — 채널 `chagocnote/share_sheet`의 `shareText({text, x, y, width, height})`. 글자(주소)만 넘기고 결과(보냈는지·취소했는지)는 받지 않는다 — 시트를 띄우면 곧바로 끝난다. 사각형은 누른 버튼의 화면 자리다 — 아이패드는 공유 시트가 말풍선이라 붙일 자리가 꼭 필요하다. iOS 는 시트 머리에 보일 것(주소의 호스트)을 네이티브가 직접 준다 — 맡겨 두면 iOS 가 머리를 그리려고 그 주소를 받아 온다. Android 는 선택기에서 자기 앱을 뺀다. 채널 오류는 그대로 던지고 화면이 `on Exception`으로 잡아 스낵바로 알린다. 대역은 `test/support/fake_share_sheet.dart` — `CustomerTestSetup.shareSheet`에 기본으로 꽂혀 있다). 화면은 `Clipboard`·`ImagePicker`·`Image.network`를 직접 부르지 않는다. **화면(`lib/features`)과 모양 위젯(`lib/design`)은 플러그인 패키지를 직접 import 하지 않고, 모양 위젯은 `core`를 import 하지 않는다**(`test/design/plugin_imports_test.dart` — 방향은 core → design 하나). 테스트는 프로바이더를 override 한다(`test/support/upload_fakes.dart`). 서명 URL 업로드는 `core/proxy/upload_client.dart`(인증 헤더 없음·진행률·재시도 없음)로 하고, 사용자가 취소한 업로드는 `ApiException`의 `CANCELLED`라 문구를 띄우지 않는다.
- **서버에서 읽는 화면 본문은 `core/error/async_body.dart`의 `AsyncBody`로 그린다**(`test/design/async_body_usage_test.dart`). 불러오는 중·처음 실패(원인 문구와 [다시 시도], 권한·없음은 뒤로 갈 수 있으면 [돌아가기])·받은 데이터 위 띠·인터넷 복귀 때 스스로 다시 불러오기·`onRefresh`의 당겨서 새로고침을 한 곳에서 한다. 화면은 `AppErrorRetry`의 가운데·inline 모양을 직접 만들지 않는다(한 줄 `AppErrorRetry.row`는 다음 쪽 실패 같은 좁은 자리에만). 오류 문구는 누른 일이면 `messageFor`, 화면을 불러오지 못했으면 `loadMessageFor`(원인은 `core/error/error_kind.dart`의 `kindOf`). 앱 문구는 해요체다(`test/design/copy_tone_test.dart`).
- **사진 올리기는 업로드 대기열(`features/visit/state/upload_queue.dart`)로만 한다.** 화면은 `uploadQueueProvider.notifier`의 `addPhotos`·`remove`·`retry`만 부르고, 다시 해도 안 되는 실패(`stopsUpload`)로 멈춘 항목은 스스로 다시 하지 않는다 — 사용자가 [다시 시도]하거나 [올리기 취소]한다. 대기 중인 사진은 `visitUploadsProvider(visitId)`로 본다. 대기열이 발급 → 올리기 셋 → 확인 → 덧붙이기를 하고 기기에 남긴다(설계 10.2). 기록 전체 교체(`saveRecord`)는 이미 붙은 사진만 보낸다 — 409 `RECORD_VERSION_CONFLICT`면 다시 읽어 새 사진을 더해 한 번 더 보낸다(`record_screen.dart`).
- **영상은 대기열의 `addVideo`로 넣는다**(④-3a). 네이티브가 1080p(짧은 변 1080·긴 변 1920 안, 키우지 않음) H.264·AAC mp4 와 1초 지점 포스터(긴 변 300)를 만들고, 60초가 넘으면 **앞 60초만** 올린다 — `addVideo`의 반환값 `VideoAddOutcome.trimmed`로 화면이 한 번 안내한다(대기열 항목에 `trimmed` 칸은 없다). 압축은 **한 번에 하나**(뒤 것은 차례를 기다린다), 한도는 사진 30장·영상 3편을 따로 센다. 크게 보기의 재생은 서명 URL 을 그대로 스트리밍하고 **기기에 캐시하지 않는다**. 원본 저장은 mp4 를 임시 파일로 받아 앨범에 넣고 지운다.
- **말로 기록하기는 기록 화면의 케어 메모·내부 메모에만 있다**(④-3b). 칸 제목 줄의 마이크(`AppMicButton`)가 토글이고, 인식은 **기기 안에서만**(iOS `requiresOnDeviceRecognition`, 안드로이드 API 31+ `createOnDeviceSpeechRecognizer`) **한국어(`ko-KR`)**로 한다 — 온디바이스가 안 되는 기기는 미지원 안내만 하고 서버 인식으로 넘어가지 않는다. 받아쓰기 세션(`features/visit/state/dictation.dart`의 `Dictation`)이 커서 자리에 넣는다: 진행 중 구간은 회색(`DictationTextEditingController`), 확정되면 검게 굳고 구절 사이에 띄어쓰기 하나. **무음 10초는 Dart 가 잰다**(네이티브가 먼저 끝내면 10초 안에서는 다시 시작해 이어 듣는다). 손으로 고치거나 길이 상한에 닿으면 끝낸다. **한 번에 한 칸만 듣는다** — 다른 칸의 마이크·다른 칸 포커스·화면 나감·앱이 뒤로 감은 듣던 세션을 `stop`이 아니라 `cancel`한다(stop 뒤 네이티브의 늦은 결과가 다음 칸에 섞이지 않게, 회색 글은 굳혀 둔다). 미지원·권한 거부([설정 열기])·못 알아들음·실패는 스낵바로 알린다.
- **사진을 보이는 순서는 대표 규칙이다**(`features/visit/state/photo_edits.dart`의 `galleryOrder` — 후 → 전 → 영상, 첫 장이 대표). 크게 보기의 전/후 바꾸기·대표로·삭제는 `applyPhotoEdit` + `recordInputOf`로 기록 전체 교체 한 번이고, 409 `RECORD_VERSION_CONFLICT`면 다시 읽어 같은 바꾸기를 한 번 더 보낸다.
- **알림장(⑤-3)의 보내기는 `ReportCommands.send`(`features/visit/state/report_commands.dart`)로만 한다.** 서버의 `hidden_media_ids`는 "뺄 것 전부"라 낡은 화면이 그대로 보내면 다른 기기에서 뺀 사진이 되살아난다 — 미리보기 화면은 **이번에 누른 것**(`Map<int, bool>` — 미디어 ID → 뺄지)만 들고, `send`가 직전에 미리보기를 다시 읽어 서버의 지금 상태 위에 누른 것만 덮는다(`report_rules.dart`의 `hiddenIdsOf`). 눌렀다가 되돌린 타일은 누르지 않은 것으로 친다. **보낼 사진 고르기의 저장은 `send(onlyIfLive: true)`** — 그 사이 링크가 닫혔으면 만들지 않고 "이미 닫힌 알림장이에요."로 끝낸다(화면은 알리고 닫는다). **[다시 공유]는 서버를 부르지 않는다** — 방문 상세가 읽은 `report.url`을 그대로 공유 시트에 넘긴다(PUT 을 다시 부르면 뺀 표시를 건드린다). '보냄'은 링크를 만든 시점이고 공유 시트의 결과는 모른다 — 공유 시트가 실패해도 미리보기는 닫히고 스낵바로 알린다. **링크 주소에는 토큰이 들어 있다** — 로그·테스트 출력·스크린샷 설명에 남기지 않는다(테스트의 주소는 가짜다 — `reportLinkJson`. 시뮬레이터 흐름은 같다·다르다와 길이만 보고, 링크를 열지 못해도 주소를 찍지 않는다). 보내기·끊기·설정 바꾸기는 성공하든 실패하든 읽는 쪽을 무효화한다(보내기·끊기 — 방문 상세·하루 목록·피드·미리보기, 설정 — 설정·미리보기). 기록이 없는 완료 방문에는 [알림장 보내기]가 없다. **알림장 설정은 [저장] 없이 누르면 바로 다섯 칸 전체 교체다** — 낙관적으로 그리지 않고 다시 읽은 서버 값으로 그리며, 보내는 중·다시 읽는 중에는 누름을 받지 않는다. 바꾸는 것은 사장만이고 직원에게는 읽기 전용으로 열린다(`isOwnerProvider`). 하루 목록 묶음의 "알림장 보냄" 표시(`DayGroup.reportSent`)는 **완료한 방문이 하나 이상이고 그 전부가 보냈을 때만** 뜬다.
- **알림톡(⑥-2)의 쓰기는 `NotificationCommands`(`features/visit/state/notification_commands.dart`)로만 한다.** **설정은 [저장] 없이 누르면 바로 아홉 칸 전체 교체다**(`NotificationOverview.settingsBody` — 설정 여덟 칸에 채널의 `sms_fallback_enabled`) — 낙관적으로 그리지 않고 다시 읽은 한눈에 보기로 그리며, 보내는 중·다시 읽는 중·읽기 실패 중에는 누름을 받지 않는다. 연동·설정·발신번호 쓰기는 성공하든 실패하든 `notificationOverviewProvider`를 무효화한다. 연동·설정은 사장만이고 직원에게는 읽기 전용이다(`isOwnerProvider`). **채널 검색 아이디·관리자 번호·카테고리는 화면 상태에만 둔다**(서버도 저장하지 않는다 — 인증번호를 받고 연동할 때 다시 보낸다). 발신번호 인증을 마치면 다시 읽기가 끝난 값 위에 문자 대체를 켠다. 템플릿 문구는 `status`로만 고른다(반려 사유는 읽지 않는다). **방문 상세의 알림톡 블록**(`screens/visit_notifications_block.dart`)은 내역을 상세와 따로 읽되 **상세를 따라 다시 읽는다**(`visitNotificationsProvider`가 `visitDetailProvider`를 watch — 예약 변경·취소·당겨 새로고침에 따라온다). 읽는 중·실패면 블록만 없고, 취소된 줄과 **모르는 종류·상태의 줄은 뺀다**(`NotificationMessage.tryFromJson`). 단추는 그 종류의 가장 최근 줄에만 — 일시 실패 [다시 보내기](직원도), 영구 실패 [다른 방법으로 보내기](`share_text`를 공유 시트에). 실패 사유 문구는 `error_kind`로만 고른다. **알림장 보내기 뒤에는 알림톡 결과를 최대 10초 기다린다**(`awaitReport`, 1초 간격 열 번 — 기다림은 `notificationPollWaitProvider`, 테스트가 바꿔 끼운다): 보내기 **전에** 읽어 둔 알림장 줄 ID(`reportRowIds`) 밖의 새 줄만 이번 보내기의 결과로 친다(끊고 다시 보낼 때 옛 '보냄' 줄을 새 발송으로 알리지 않게). 새 줄이 없거나 취소됐으면 지금처럼 공유 시트, 나갔으면 "알림톡으로 보냈어요.", 실패면 알리고 `share_text`(없으면 링크)로 공유 시트, 10초가 지나도 보내는 중이면 닫고 알린다. 기다리는 동안 뒤로 가기는 막지 않고, 닫고 나갔으면 아무것도 띄우지 않는다. 보낼 사진 고르기의 저장은 알림톡을 보지 않는다. **전화번호·인증번호·`share_text`(알림장 주소가 들 수 있다)를 로그·테스트 출력·스크린샷 설명에 남기지 않는다.**
- **보호자 계정 연결(⑦-3)은 반려동물 상세 [보호자] 탭의 한 줄이다**(`features/customer/screens/guardian_link_row.dart` — 노쇼 횟수 아래, 다가오는 예약 위). 고객 상세와 **따로 읽는다**(`guardianLinkProvider`) — 읽는 중·읽지 못함·이어지지 않음이면 줄이 없고 실패를 알리지 않는다(탭의 본문이 아니다). 다시 읽기가 실패했을 때도 없다 — `AsyncValue.value`는 실패해도 이전 값을 들고 있으니 `hasError`를 먼저 본다. 이어져 있으면 "보호자 계정 연결됨 · 11월 13일"(이은 날의 월·일, 날짜를 읽지 못하면 날짜 없이)과 `···` → [연결 끊기] → 확인 시트. 끊기는 `CustomerCommands.endGuardianLink`로만 하고 **성공하든 실패하든 그 고객의 연결을 다시 읽는다**(보호자가 먼저 끊었으면 404 — "이미 끊긴 연결이에요."를 알리고 줄이 사라진다). 끊는 동안 `···`는 눌리지 않는다. **직원도 끊는다**(`customer:write` — 사장만 보이게 가리지 않는다). **보호자가 누구인지는 받지도 그리지도 않는다** — 매장용 응답은 여부와 이은 날뿐이다. 다른 기능 폴더를 import 하지 않는다.
- **매출 탭(⑧-2)은 새 기능 폴더 `features/sales` 다** — `auth` 만 import 하고, 하루 화면으로는 라우터 경로(`/visits/day/…`)로 간다. 요약 하나(`salesSummaryProvider` — 매장·기간·anchor)를 읽어 한 화면을 그린다. **사장만 본다** — 직원에게는 "매출은 사장님만 볼 수 있어요."만 보이고 서버를 부르지 않는다(`isOwnerProvider`). **문장·기간 이동·숫자 표기는 `state/sales_rules.dart` 의 순수 함수**다(비교 문장, 목표, `canGoNext`, 처음 고를 칸 — 방문이 없는 날은 고르지 않는다). 화면은 그것을 부르기만 한다. **톤**: 색은 사진에서만 온다 — 색 카드 격자·도넛·그라데이션·이모지·초록빨강 증감 표시를 쓰지 않고, 비교는 문장으로 쓴다. 막대·진행선은 직접 그린다(차트 패키지 없음). 고른 날 카드는 스크롤되는 본문 안이라 글래스가 아니라 `AppCard` 다. 조정 줄에는 사진 칸이 없고, 사진 없는 날의 막대 위에는 아무것도 띄우지 않는다. 비율·막대 폭은 0~1 로 자른다(요약의 합이 한 번 어긋나도 죽지 않게). 메뉴는 다섯 줄까지지만 조정 줄은 늘 보인다. **앱으로 돌아올 때와 당겨서 새로고침할 때 `todayProvider` 를 무효화한다** — 켜 둔 채 자정을 넘겨도 어제의 기간에 갇히지 않게. 홈의 모든 탭은 자기 머리를 그리고 `+` 는 어느 탭에서나 예약 등록이다 — 매출 탭에서는 캘린더에서 고른 날이 아니라 **오늘로** 연다.
- **매출 탭에서 이어지는 화면(⑧-3)** — 방문 목록 `/sales/visits?span=&anchor=&filter=&menu_id=&menu=`(`SalesVisitsScreen`)와 다시 올 때가 지난 아이 `/sales/due-pets`(`DuePetsScreen`). 둘 다 `screens/sales_paged_list.dart` 의 뼈대(머리 + `AsyncBody` + 줄 + [더 보기])와 `state/sales_paged.dart` 의 쪽 나눔(`SalesPagedController` — 피드와 같은 규칙: 세대 번호로 옛 쪽을 버리고, 다음 쪽이 실패하면 보인 줄은 두고 [다시 시도])을 쓴다. **주소는 `sales_rules.dart` 의 `visitsPath`(요약의 기간을 그대로 싣는다 — 지난 달에서 누르면 지난 달의 목록)가 만들고 `visitsQueryOf` 가 읽는다** — 깨진 질의는 기본값(이번 달·금액을 적지 않은 방문)이다. 매출 탭에서 누를 수 있는 것: 메뉴 줄(조정 줄은 아니다), 다섯을 넘는 메뉴의 [모두 보기](그 자리에서 편다), 노쇼·취소(0 건이면 눌리지 않는다), `다시 올 때가 지난 아이 N마리`, `금액을 적지 않은 완료 방문 N건`, 목표 줄, [요약 공유]. **이어진 화면에서 돌아오면 요약(목록 화면은 목록)을 다시 읽는다** — 상세에서 금액을 적거나 예약을 잡았을 수 있다. 목록은 `invalidate` 가 아니라 `reload()`(불러온 만큼을 처음부터 다시 읽어 갈아 끼운다)로 읽는다 — 무효화하면 이어 읽은 줄이 첫 쪽으로 준다. **글자뿐인 누를 것은 `SalesTapArea` 로 감싸 누름 영역의 높이를 44 로 둔다.** **아이를 보일 수 없는 방문(`pet: null`)의 줄은 날짜가 이름이다** — 사진 칸도 "보호자만" 같은 말도 없고, 눌러서 방문으로 간다. 금액이 없는 줄에는 금액 자리에 아무것도 없다. **월 목표**는 `SalesGoalSheet`(숫자만, 아홉 자리, 빈 칸·0 은 지우기, 1억 넘으면 보내지 않고 막는다 — `parseGoal`)와 `SalesCommands.setGoal`(성공하든 실패하든 요약을 무효화)로만 쓴다. **이번 달의 월 보기에서만** 정하고 보인다(`isGoalPeriod`). 저장하는 동안 다시 누른 것은 받지 않고, 실패하면 시트가 남아 원인을 보인다. **요약 공유의 글은 `shareText` 가 만든다 — 기간·매출·방문 수·결제 수단별·메뉴별뿐이고 아이·보호자의 이름과 번호는 한 글자도 넣지 않는다**(설계 3.4, 테스트가 지킨다). 빈 기간에는 공유가 없다. 공유 시트가 실패하면 스낵바로 알린다.
- **확인할 것·미용 동의·주의 고객(③-B2)** — 판정은 서버가 한다. 앱은 `{code, scope, detail}` 을 `features/visit/api/check_models.dart` 의 `VisitCheck.tryParse` 로 한 번 읽고 **모르는 code·모양이 깨진 항목은 버린다**(나머지는 보인다). 문구와 묶기는 `state/check_rules.dart` 의 순수 함수(`checkLine`·`checkSections`·`detailSections`), 그림은 `screens/visit_checks_block.dart` 의 `VisitChecksBlock` 하나다 — 예약 등록(`VisitForm.aboveSubmit` 자리, `visitChecksProvider` 의 미리 보기)과 방문 상세(`detail.checks`)가 함께 쓴다. **알리기만 하고 막지 않는다**: 미리 보기는 읽는 중·읽기 실패면 묶음도 오류 문구도 없고 저장 버튼은 그대로다. 방문 수정 화면에는 미리 보기가 없다. **톤**: 색 딱지·경고 그림·이모지 없이 잉크색 글자와 가는 선, 버튼은 미용 동의 줄의 [받았어요] 하나(방문 상세에만 — `VisitCommands.consentReceived`). 지병 줄은 메모가 있을 때만 눌러서 편다. 하루 목록·시간표의 `확인 N` 은 `DayGroup.checkCount`(가족 묶음에서 보호자 수는 한 번만, 지병은 서버가 세지 않는다). **동의·주의의 쓰기와 화면은 `features/customer`** — `CustomerCommands` 의 넷(`setGroomingConsent`·`clearGroomingConsent`·`setCaution`·`clearCaution`)은 성공하든 실패하든 목록·상세를 무효화하고 `core/plugs/care_marks_plug.dart` 의 자리로 방문 쪽에 알린다(`app.dart` 가 방문 상세·하루 목록·미리 보기 무효화로 채운다 — customer 는 visit 를 import 하지 않는다). 기본 탭의 `GroomingConsentRow`(받은 날은 오늘로만 적는다, 무지개다리 아이에게는 없다), [보호자] 탭의 `CautionRow`(노쇼 횟수 아래·보호자 계정 연결 줄 위, 노쇼 2번부터 사유를 `노쇼 N번` 으로 채워 여는 제안 — 저절로 표시하지 않는다, [주의 표시 지우기]는 한 번 묻는다)와 `CautionSheet`(한 줄 100자, `cleanCautionReason`, 빈 글이면 저장 안 됨, 실패는 시트 안 문구), 고객 목록 머리 줄의 `주의` 두 글자. **주의 사유·지병 메모는 로그·오류 문구·테스트 출력에 싣지 않는다.**
- **기록 찾기(⑨-1b)는 새 기능 폴더 `features/search` 다** — `auth` 만 import 하고, 방문 상세·반려동물 상세로는 라우터 경로로만 간다. 화면 하나 `/search`(매장 전체)·`/search?pet_id=&pet=`(그 아이 안에서만 — `pet` 은 화면 위에 보일 이름일 뿐이다), 읽는 것은 `GET /v1/shops/{id}/search` 하나. **입력을 0.5초 쉬면 묻는다**(`core/time/search_debouncer.dart` — 한글 조합 중에는 묻지 않는다. 고객 목록·예약 ①과 함께 쓰려고 core 로 옮겼다). 검색어는 `state/search_rules.dart` 의 `cleanSearchText` 가 다듬는다(공백류를 빈칸 하나로, 2자 미만이면 묻지 않고 처음 화면, 100자에서 자름). **늦게 온 옛 결과는 `SearchController` 의 세대 번호가 버린다** — 2자 미만으로 지워도 진행 중이던 결과가 뒤늦게 나타나지 않는다. **칸을 비우면(2자 미만) 0.5초를 쉬지 않고 곧바로 처음 화면이다**(화면이 `SearchDebouncer.reset` 을 부른다 — 그 뒤 같은 검색어를 다시 쳐도 묻는다). 줄의 스크린리더 이름표는 이름·종류와 날짜·걸린 문장을 한 번씩 읽고 줄 안의 글자는 뺀다(`ExcludeSemantics`). 다시 묻는 동안에는 앞 결과를 그대로 보인다(`SearchState.display`). **줄의 문구와 갈 곳은 순수 함수**(`kindLabel`·`titleOf`·`metaLine`·`destinationOf`)다: 방문이 있으면 방문 상세, 없으면 `open_pet_id` 의 반려동물 상세(보호자 메모는 `?tab=owner` — [보호자] 탭으로 연다), 둘 다 없으면 눌리지 않고 화살표가 없다. **모르는 kind·모양이 깨진 줄은 버린다**(`SearchItem.tryParse` — 나머지는 보인다, 날짜만 깨졌으면 날짜 없이 살린다). 줄을 눌러 다녀와도 다시 묻지 않는다 — 검색어와 결과가 그대로다. **톤**: "AI"라는 말·반짝이 아이콘·색 딱지·강조 표시가 없다. 뜻으로 찾았는지(`semantic`)는 읽지도 그리지도 않는다. 서버는 맞는 글이 없어도 가까운 글을 몇 줄 주므로(결정 기록 013) 결과 위에 `가까운 기록부터 보여 드려요` 한 줄을 둔다. **검색어를 기기에 저장하지 않고**(화면을 떠나면 버린다 — 검색어 기록·추천어 없음), 검색어·걸린 문장을 로그·오류 문구·스크린샷 설명에 남기지 않는다. 들어가는 곳은 둘이다 — 캘린더 탭을 피드로 볼 때 머리의 돋보기(`visit/screens/calendar_tab.dart`), 반려동물 상세 [기록] 탭 맨 위의 `이 아이의 기록에서 찾기` 줄(`customer/screens/pet_detail_screen.dart`). 둘 다 경로로만 간다.
- 글래스는 떠 있는 조작 계층에만 쓴다(`test/design/glass_boundary_test.dart`). 예외는 피드 카드의 이름 카드 하나(④ 설계 10.1 ②) — 실제 글래스는 비쳐 보이므로 그 위 글자는 잉크색으로 쓴다.
- 서버의 상태 문자열은 `fromJson`에서 enum(`VisitStatus`·`VisitAction`)으로 한 번만 바꾼다. 화면의 `switch`는 `_ =>` 폴백 없이 완전 열거한다 — 상태·행동을 더하면 컴파일러가 빠진 곳을 찾는다.
- 서버 응답의 필드명은 변환하지 않는다. 모델은 평범한 클래스에 `fromJson` 을 직접 쓴다. 코드 생성기를 도입하지 않는다.
- `liquid_glass_widgets` 는 `lib/design/bridge/` 안에서만 import 한다. 화면은 `lib/design/widgets` 만 쓴다.
- 토큰을 로그에 남기지 않는다. `print`·`debugPrint`·dio `LogInterceptor` 를 쓰지 않는다(`avoid_print` 는 오류다).
- 리프레시 토큰 재사용에는 유예가 없다. 갱신 요청은 동시에 하나만, 실패한 갱신은 자동으로 다시 보내지 않는다. `ProviderScope` 의 `retry` 는 꺼 둔다.
- Hiss Haus 는 첫 입점 매장 이름이다. 앱 이름은 "차곡노트"다.
