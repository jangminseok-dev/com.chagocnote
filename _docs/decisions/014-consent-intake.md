# 014 — 전자 동의서·문진표 (⑪)

설계 `docs/superpowers/specs/2026-11-16-consent-intake-design.md`, 여섯 묶음의 공통 기준 `docs/superpowers/specs/2026-11-16-next-designs-common.md`. 보호자가 로그인 없이 웹에서 적어 보내는 서류다. ⑪ 은 셋으로 나눠 만든다(사용자 승인 2026-11-16) — **⑪-A 동의서** → ⑪-B 한 번에 보내기·서류 설정 → ⑪-C 문진표.

사용자의 기준(2026-11-16): 자동화할 수 있는 것은 자동화한다 · 경쟁사보다 압도적으로 편해야 한다 · 그렇다고 핵심 기능·설명·바꿀 길을 빼지 않는다 · 기본값은 업계에서 흔한 방식으로 두고 매장이 자기 가게에 맞게 고른다 · 가족이 함께 예약하면 서명 한 번으로 여러 아이의 동의를 받는다. 문안·항목·기준값·구조는 내가 정했다.

## ⑪-A 백엔드에서 정한 것 (2026-11-16)

계획 `docs/superpowers/plans/2026-11-16-consent-11a-backend.md`. 규칙은 `backend/apps/customer/CLAUDE.md`.

1. **알림장의 공개 도구 넷을 `core/`·`hub/` 로 올렸다.** 토큰(`core/link_token.py`), 접속 주소(`core/public_client.py`), 횟수 제한(`hub` 의 `PublicLimiterPort` + `core/public_redis_limiter.py`), `public_context`(`hub/app/dtos/shop_context.py`). 알림장의 동작은 그대로다 — 이미 나간 링크의 토큰이 글자 하나 다르지 않다는 것을 테스트가 고정한다.
2. **서류 토큰은 알림장 토큰과 서로의 경로에서 읽히지 않는다.** 같은 키(`REPORT_LINK_KEY`)로 서명하되 서명 대상 앞에 `form:` 을 붙인다. 새 비밀값이 없다. 헤더는 `X-Form-Token`.
3. **`public_context` 가 처음으로 쓴다.** 로그인 없는 경로가 고객 스포크의 표를 쓰는 첫 사례다 — 쓰는 표를 루트 `CLAUDE.md` 에 적었다(`customer_forms`·`consent_signatures` 와 그 아래 표, `pets` 의 동의 칸 셋).
4. **문안은 열 때 조립하고, 낼 때 지문을 다시 견준다.** 지문은 아이마다 이름·남은 토막·그 글의 출처와 판·지병 이름 목록의 해시다. 읽은 뒤 지병이 하나 더해져도 409 이고 서명이 저장되지 않는다.
5. **서명은 읽은 토막과 그때 보인 사실의 사본을 남긴다.** 그래서 뒤에 노령이 되거나 지병이 늘면 **바뀐 토막만** 다시 받는다. 부분 서명은 받은 날을 옮기지 않는다 — 기한은 처음 전체를 받은 날부터 365일이다.
6. **판정은 지금처럼 `visit` 이 방문의 날로 한다.** `customer` 는 사실만 준다 — 허브 DTO `PetCareFact` 에 `consent_cover`(서명이 덮는 것)와 `consent_form_sent_on`(살아 있는 링크를 보낸 날). 확인할 것의 `consent` 에 상태 `partial` 과 `parts`, `form_sent_on` 이 더해졌다(값이 있을 때만 칸이 있다).
7. **서명으로 받은 동의는 지병이 늘어도 받은 날을 지우지 않는다.** 손으로 적은 동의(③-B 의 [받았어요])는 지금처럼 지운다.
8. **아이 하나에 살아 있는 동의서 요청은 하나다.** 요청이 아이 여럿을 담아 부분 유일 색인으로 쓸 수 없다 — 발급이 고객 행을 잠근 안에서 지킨다. 그 아이들을 모두 담은 살아 있는 요청이 있으면 같은 링크(200), 새로 만들면 201.
9. **서명을 받으면 그 아이는 살아 있는 다른 링크에서 빠진다.** 아이가 남지 않은 링크는 끊긴다 — 같은 것을 두 번 서명받지 않는다.
10. **서명 그림은 DB 에 둔다**(64KB 이하의 PNG 한 장). 로그인 없는 경로에 업로드 발급을 열지 않는다. 서버는 그림을 풀지 않고 머리·폭·높이·크기만 본다.
11. **기준값은 `ConsentPolicy` 로 받는다**(노령 10살·기한 365일·링크 14일). 지금은 기본값뿐이고 `customer/dependencies/customer_wiring.consent_policy()` 가 준다 — 매장이 바꾼 값은 ⑪-B 가 여기서 읽는다. 다만 **`visit` 의 판정은 아직 자기 상수(10·365)를 쓴다** — ⑪-B 가 매장 설정을 읽게 할 때 두 곳을 함께 바꿔야 한다.

## 실행하면서 정한 것 (Ruling)

- **손으로 적은 동의는 노령이 돼도 다시 묻지 않는다.** 설계 3.3 은 "받은 날에는 노령이 아니었으면 전체를 다시"라 했고 F14 는 "손 표시의 규칙은 그대로"라 했다 — F14 를 따랐다(③-B 의 동작을 바꾸지 않는다). 손 표시 뒤 10살이 된 아이의 동의를 놓치는 것은 지금도 같다.
- **확인할 것의 `form_sent_on`·`parts` 는 값이 있을 때만 싣는다.** ③-B 의 테스트가 `detail` 을 통째로 견준다.
- **손 표시는 살아 있는 링크를 끊지 않는다.** 그 링크를 열면 "보냈어요"로 읽히고 내면 409 `CONSENT_UP_TO_DATE` 다. 보낸 서류 목록에는 기간까지 남는다.
- **횟수 제한의 오류 code 는 알림장과 같은 `TOO_MANY_ATTEMPTS`**, 공개 응답의 헤더도 알림장과 같은 둘이다(`Referrer-Policy` 는 웹이 붙인다).
- **익명화는 이미 낸 링크도 닫는다.** 흐름 스크립트가 잡았다 — 낸 링크가 익명화 뒤에도 "보냈어요"로 열렸다. 개인정보는 없었지만 알림장과 같게 410 으로 맞췄다.
- 라우터별 스텁 테스트는 쓰지 않고 실제 배선 통합 테스트로 덮었다. 통합 테스트 일부는 구현 뒤에 처음 돌렸고, 대신 변이 33개로 판별력을 확인했다(살아남은 둘은 테스트를 더해 잡았고, 하나는 같은 결과인 변이다).

## 최종 검토에서 고친 것 (2026-11-16)

새 맥락의 검토자가 브랜치 전체를 보았다. Critical 은 없었고 Important 넷과 Minor 하나(다시 매겨 올렸다)를 테스트 먼저 쓰고 고쳤다.

1. **문서를 예약 날로 조립할 수 있다(`for_date`).** 판정은 방문의 날로 하는데 문서는 오늘로 조립해서, 예약 날에는 기한이 지나거나 노령이 되는 아이에게 [동의서 보내기]가 409 였다(받을 것이 없다고). 발급·현장 문서·현장 서명이 선택 `for_date` 를 받고, 링크는 그날을 요청에 적어 둔다(0019). 그날로 필요한 토막을 계산하고 받은 날은 오늘로 찍는다. 지난 날은 오늘로, 기한(365일)보다 먼 날은 422.
2. **같은 링크의 규칙은 "포함"이다.** 그 아이들을 모두 담은 살아 있는 요청이 있으면 그것을 돌려준다 — 가족 링크의 한 아이만 다시 보내도 링크가 쪼개지지 않는다. 더 먼 예약 날로 다시 보내면 링크의 기준일을 그날로 맞춘다.
3. **공개 제출은 본문을 읽기 전에 크기와 횟수를 본다**(`adapter/inbound/api/public_form_guard.py`). FastAPI 는 의존성보다 본문을 먼저 읽어서, 경로의 처리기를 감쌌다. 131,072바이트를 넘거나 길이가 없으면 413, 틀린 본문(422)도 제출 횟수에 든다.
4. **덮는 것은 날짜가 아니라 서명 ID 로 거른다.** 같은 날 지우고 다시 받으면 지우기 전의 서명이 끼었고, 시각과 날짜를 따로 읽어 자정에 걸치면 방금 받은 서명이 세어지지 않을 수 있었다.
5. **잠금의 순서를 테스트가 지킨다**(`tests/integration/test_consent_locking.py`). 다른 트랜잭션이 고객 행을 쥔 채 지병을 더하면 서명이 409 로 거절된다. "기다리는지"만 보아서는 모자랐다 — 잠금이 없어도 서명 행의 외래 키 검사가 같은 자리에서 기다린다. 동시 제출·현장과 링크·익명화와 제출이 겹치는 테스트도 더했다.

## ⑪-A 백엔드에서 남는 것 (미룬 Minor)

- 기준값(10살·365일)이 `visit` 과 `customer` 두 곳에 있고 둘이 같다는 테스트가 없다 — ⑪-B 가 매장 설정으로 바꿀 때 함께 고친다.
- 알림장 토큰 ↔ 서류 토큰 테스트의 한쪽은 "그 `public_id` 의 알림장이 없어서"도 404 다(반대쪽과 단위 테스트는 가른다).
- `pets.grooming_consent_signature_id` 에 FK 가 없다 — 지금은 없는 서명을 가리키는 길이 없지만 ⑪-C 의 주기 삭제가 들어오면 막아 줄 것이 없다.
- `delete_for_pet` 의 남은 줄 찾기가 표 전체를 훑는다.
- `expires_on` 은 날짜인데 링크는 그날 보낸 시각에 닫힌다 — "11월 30일까지"로 읽히지만 30일 낮에 닫힌다.
- 손 표시된 아이는 [지우기]를 먼저 눌러야 서명을 받을 수 있다 — 앱(⑪-A3)이 안내해야 한다.
- 서류 저장소를 주지 않으면 `care_facts` 가 조용히 서명을 손 표시로 본다(실제 프로바이더는 꽂는다).
- `read_public_form_interactor` 가 다른 유스케이스 모듈의 `document_view` 를 쓴다 — `app/services/` 로 옮길 것.
- 횟수 제한의 경고 문구가 서류 이름 공간에서도 "알림장"이다.
- 이름·그림 검사가 잠금 뒤다. 서류 쪽에 운영 로그(매장·요청·결과)가 없다.

## ⑪-A2 웹에서 정한 것 (2026-11-16)

계획 `docs/superpowers/plans/2026-11-16-consent-11a-web.md`. 규칙은 `web/CLAUDE.md` 의 "동의서".

1. **주소는 `/f/<토큰>`** 이고 알림장과 같은 틀이다 — 웹 서버가 백엔드의 공개 API 를 부르고, 보호자의 브라우저는 웹 자신만 부른다.
2. **제출은 폼 POST·303 이 아니라 브라우저의 fetch → 경로 핸들러(상태 코드만)다**(설계 3.6 의 11 과 다르다). 서명에 스크립트가 어차피 필요하고, 결과를 303 으로 알리려면 토큰이 든 주소에 질의를 붙여야 한다. 스크립트가 꺼져 있으면 문안은 읽히고 `서명하려면 자바스크립트를 켜 주세요` 가 보인다.
3. **보호자가 글자를 치는 칸은 이름 하나다.** 그리고 서명, 체크 하나, [동의하고 보내기]. e2e 가 칸 수를 고정한다.
4. **빠진 것은 보내기 전에 그 자리에서 말한다**(이름 → 서명 → 체크). 백엔드를 부르지 않는다.
5. **두 번 내면 오류가 아니라 `보냈어요` 다.** 410 을 받으면 화면을 다시 읽는다.
6. **내용이 바뀌었으면(409) 알리고 다시 읽는다.** 이름은 남기고 서명과 체크를 비운다 — 새 문안을 읽고 다시 서명한다.
7. **미리보기에는 매장 이름과 "미용 동의서"뿐이다.**
8. 서명 칸은 600×240 캔버스(화면 배율을 곱하지 않는다), 크면 300×120 으로 줄인다. 웹도 본문 131,072바이트를 넘으면 읽지 않고 413 이다.

### 최종 검토에서 고친 것

새 맥락의 검토자가 가짜 백엔드와 실제 크롬으로 재현하며 보았다. Critical 은 없었고 Important 넷을 테스트 먼저 쓰고 고쳤다.

1. **스크립트가 오기 전에는 보내기 버튼이 잠겨 있다.** 그때 누르면 브라우저가 폼을 GET 으로 내 적은 이름이 주소(`?signer_name=…`)에 실렸다. 서버가 그린 버튼은 `disabled` 이고 폼은 `method="post"` 다. 스크립트가 오기 전에 친 이름은 올 때 한 번 상태로 옮긴다.
2. **보내면 화면을 다시 읽기 전에 곧바로 `보냈어요` 를 보인다.** 느린 망에서 버튼이 되살아나 "안 눌렸다"로 보였다. 그 글로 포커스를 옮긴다(`role="status"`).
3. **서명 칸은 한 번에 포인터 하나만 받는다.** 두 손가락·손바닥이 닿으면 두 점 사이에 선이 지그재그로 그어졌다. 마우스는 왼쪽 단추만, 포인터를 빼앗기면 그리기를 끝낸다. 선은 토막마다 따로 긋는다.
4. **실제 브라우저 테스트가 서명 칸의 실제 동작을 본다.** 터치로 긋고 캔버스의 픽셀에서 그은 자리의 잉크를 본다(좌표가 600×240 으로 맞게 옮겨지는지), 그어도 화면이 구르지 않는지, 둘째 손가락, 409 뒤 서명이 비었는지, 두 탭에서 같은 링크를 내면 둘째도 `보냈어요` 인지, 스크립트를 끈 채 Enter 를 눌러도 이름이 주소에 실리지 않는지.

함께 고친 작은 것(편의 기준에 닿아서): 빈 서명 칸의 `여기에 서명해 주세요`, 서명 그림의 흰 바탕(앱이 어두운 바탕에 그려도 보인다), 빠진 것을 채우면 안내가 사라진다, [다시 쓰기]·체크 줄의 누르는 자리 44px, 이름표 글자의 대비, 이름 칸의 포커스 표시.

### 남는 것 (미룬 Minor)

- `lib/form.ts` 가 200 응답의 모양(`kind`·`state`)을 보지 않는다 — ⑪-C 가 같은 경로에 문진표를 주면 화면이 터진다. ⑪-C 에서 고친다.
- 413·422 를 같은 글(`서명을 조금 간단하게 다시 적어 주세요`)로 말한다. 웹의 413 은 `Content-Length` 가 없을 때도 난다 — **배포 환경(Vercel)이 이 헤더를 넘기는지 확인해야 한다.** 떼면 모든 제출이 막힌다.
- 버튼이 잠기는 동안 포커스가 문서 맨 위로 떨어진다. 빠진 칸으로 포커스를 옮기지 않고 `aria-invalid` 가 없다.
- 서명 칸은 `role="img"` 이고 키보드·스위치로 서명할 길이 없다 — 서명을 못 하는 사람은 매장의 [여기서 서명]·[받았어요]로 받는다(설계의 한계).
- 캔버스 위에서 시작한 스크롤 손짓도 선이 된다(칸 안에서는 화면이 구르지 않는다).
- `web/CLAUDE.md` 의 "꼭 지킬 것" 첫 줄의 경로 목록에 `/f/…` 가 없다(아래 "동의서" 절에는 있다).
- `next dev` 가 브라우저의 하이드레이션 경고를 기록에 옮길 때 경로의 앞 열 글자가 찍힌다(개발 환경뿐이다).

확인: 단위·컴포넌트 383, 빌드와 형 검사, 서버 응답 검사 118줄(동의서 18줄), 실제 브라우저 35(동의서 11). 실기기에서 볼 것 — 손가락 서명의 감(선 굵기, 끊김), 아이폰 사파리·카카오톡 인앱 브라우저에서 서명 중 글자 선택·돋보기·뒤로 가기 스와이프가 끼어드는지, 키보드가 떠 있을 때 서명 칸이 가려지는지, 화면을 돌렸을 때.

## ⑪-A3 앱에서 정한 것 (2026-11-16)

- **공유 시트에는 주소만 넘긴다.** 보내는 글의 템플릿은 ⑪-B(한 번에 보내기)가 만든다 — 그때 매장이 고치는 글과 함께 넘긴다.
- **반려동물 상세에서 보낼 때는 기준일이 없다**(오늘 기준). 방문 상세에서 보내면 그 예약 날이 기준일이다.
- **받지 않은 아이에게도 동의 줄에 `···` 메뉴가 있다**(동의서 보내기·여기서 서명 — 받은 아이에게는 오늘 다시 받았어요·받은 기록 지우기까지 넷) — 예약이 없어도 미리 받을 수 있게.
- **보낸 서류 줄은 0건이거나 읽기에 실패하면 없다.** 고객 탭을 막지 않는다. 실패를 알리지 않는 것이 값이다.
- **동의 체크 문구는 해요체다**(`위 내용을 읽었고 동의해요`) — 앱의 문구 검사(`copy_tone_test`)에 맞추고 웹·문서도 같이 바꿨다.
- **그림 만들기는 `signaturePngMakerProvider` 로 갈아 끼운다** — 위젯 테스트에서 실제 래스터를 기다리지 않게. 실제 그림은 `signature_png` 의 단위 테스트와 시뮬레이터 흐름이 본다.
- **현장 서명은 보낸 뒤 저절로 닫지 않는다** — 기기를 보호자가 들고 있으니 `보냈어요` 를 보이고 [닫기]로 돌려준다.
- 확인: 분석 0·앱 테스트 1307·시뮬레이터 흐름 iOS·안드로이드 7/7.

### 최종 검토에서 고친 것

- **가로로 돌린 폰에서 서명 칸이 화면을 덮어 굴릴 자리가 없었다** → 칸은 보이는 높이의 반·폭 560 까지만 커지고 가운데에 놓인다(`signaturePadMaxWidth`). 가로 폰·아이패드 크기의 테스트를 더했다.
- **[여기서 서명]이 손으로 적은 동의가 있는 아이에게 길을 말하지 않았다** → 열자마자 더 받을 것이 없으면 "손으로 적은 동의를 서명으로 바꾸려면 받은 기록을 지운 뒤 다시 받아 주세요"를 함께 말한다. 보내는 사이에 그렇게 된 때(보호자가 들고 있다)는 받았다고만 말한다.
- **빠진 테스트** → 300×120 으로 다시 만드는 길(`signaturePng(maxBytes:)`), 보내는 단계의 `CONSENT_UP_TO_DATE`.
- 확인: 분석 0·앱 테스트 1312. 세로 폰의 칸 크기는 바뀌지 않아 시뮬레이터 흐름은 다시 돌리지 않았다.

### 남는 것 (미룬 Minor)

- 보내는 동안 계속 긋다가 409 로 서명이 비워지면 손을 뗄 때까지 선이 그어지지 않는다(`SignatureController._extend`).
- `보낸 서류 N` 은 보호자가 링크로 서명해도 탭을 떠났다 오기 전에는 그대로다 — 고객 탭의 당겨서 새로고침이 다시 읽지 않는다.
- 서명 그림을 읽지 못하면 흰 칸만 보인다 — 알리는 글과 다시 시도가 없다.
- 모르는 서명 채널을 링크로 친다. 현장 서명 화면이 모르는 토막을 조용히 뺀다(지금은 토막이 셋뿐이다).
- 스낵바 문구가 덜 맞는 때: 화면이 낡았을 뿐인데 "받은 기록을 지워 주세요", 365일보다 먼 예약의 422, 제출의 422 는 전부 "서명을 조금 간단하게".
- [링크 끊기]를 빠르게 두 번 누르면 확인 시트가 둘 뜬다(끊기는 멱등).
- 서명 목록·한 장의 날짜가 기기 시간대이고 시각이 없다(계획은 시각을 적었다).
- `signaturePngMakerProvider` 가 `screens/` 에 있다. `/consent/sign` 에 `pet_ids` 가 없으면 읽기 실패 화면이다. `SentForm.kind` 를 읽지 않고 제목이 `미용 동의서` 고정이다(⑪-C 에서 고친다).
- 계획이 적은 골든(현장 서명 화면·보낸 서류·서명 보기)과 큰 글자 테스트가 없다.
- **사용자가 정할 것**: 공유 시트에 주소만 넘긴다(계획은 매장 이름이 든 한 줄을 붙였다) — 문자로 보내면 설명 없는 주소만 간다. ⑪-B 가 템플릿을 만들 때까지 이대로 둘지.

## ⑪-A 의 API 계약 (웹·앱이 기댄다)

매장(`/v1/shops/{shop_id}/…`):

- `POST consent-forms {pet_ids, for_date?}` → `{form_id, url, expires_on, sent_on}` (201 새로 / 200 같은 링크 — 그 아이들을 모두 담은 살아 있는 요청). `customer:write`. `for_date` 는 예약 날이다 — 그날에 유효한 동의를 받는다.
- `GET forms` → `{items: [{form_id, kind, customer: {customer_id, name}, pets: [{pet_id, name}], sent_on, expires_on, url}]}` · `DELETE forms/{form_id}` → 204.
- `GET consent-document?pet_ids=1&pet_ids=2&for_date=` → `{pets: [{pet_id, name, conditions, parts}], texts: {part: {body}}, previous_consent_on, doc_digest}` · `POST consent-signatures {pet_ids, doc_digest, signer_name, signature_png(base64), for_date?}` → 201 `{signature_id}` (`for_date` 는 문서를 읽을 때 준 것과 같아야 지문이 맞는다).
- `GET pets/{pet_id}/consent-signatures` · `GET consent-signatures/{id}` · `GET consent-signatures/{id}/image`(`image/png`).
- 반려동물 상세의 `pet.grooming_consent_via`: `signature`·`manual`·`null`.
- 오류: 404 `FORM_NOT_FOUND`·`SIGNATURE_NOT_FOUND` · 409 `CONSENT_DOCUMENT_CHANGED`·`CONSENT_UP_TO_DATE` · 410 `FORM_CLOSED` · 429 `TOO_MANY_ATTEMPTS`.

공개(로그인 없음, 헤더 `X-Form-Token`):

- `GET /v1/public/form` → 열림 `{kind, state: "open", shop: {name}, previous_consent_on, pets: [{name, conditions, parts}], texts, doc_digest}` / 냄 `{kind, state: "submitted", shop: {name}, submitted_on}`.
- `POST /v1/public/form/consent {doc_digest, signer_name, signature_png}` → 204 / 409 / 410 / 404 / 413(본문 131,072바이트 초과) / 422 / 429(10분에 10번 — 틀린 본문도 센다).

## 받아들인 한계

- **본인 인증이 없다.** 서명한 사람이 누구인지 증명하지 않는다. 화면·문서에서 "법적 효력"을 말하지 않는다. 기본 문안은 법률 검토를 받지 않았다.
- 링크를 받은 사람은 아이 이름과 지병의 **이름**을 본다(메모는 싣지 않는다).
- 동의의 '오늘'은 매장 쪽 경로가 `seoul_today`, 공개 경로가 매장 시간대다 — 한국 밖의 매장에서는 하루가 어긋날 수 있다(스포크의 지금 규칙과 같다).
