## 무엇을 만들었나

`app/`에 Flutter 앱 골격을 만들었다: `core/{config,proxy,storage,router,error}` · `design/{tokens,bridge,widgets}` · `features/{auth,shop,account,home}/{screens,state,api}` · `l10n`. 화면 흐름은 로그인(개발 환경은 `dev` 제공자) → 소속 없음이면 초대 코드 입력 → 홈(탭 셸: 캘린더 자리 + 빈 상태 안내, 고객·매출은 준비 중 안내, 글래스 탭바, + 버튼) → 설정에서 매장(멤버 목록·초대 코드 발급·역할 변경·내보내기·매장 정보 수정)과 계정(연결된 로그인 수단·연결·해제·로그아웃·회원 탈퇴)으로 이어진다. `ApiClient`는 401을 받으면 갱신을 동시에 하나만 보내고 실패해도 자동으로 다시 보내지 않으며, 갱신이 백엔드에 닿아 실패하면(502·503·504 제외) 세션을 끝내고 로그인 화면으로 보낸다. 연결·해제·탈퇴 앞에는 "최근 로그인 확인"(재인증) 시트를 두어 `REAUTH_REQUIRED`를 받으면 소셜 로그인을 한 번 더 하고 원래 요청을 한 번만 다시 보낸다. 기본 위젯 9개(`AppButton`·`AppFab`·`AppGlassBar`·`AppGlassCard`·`AppSheet`·`AppSegment`·`AppPhotoTile`·`AppBigDate`·`AppChip`)를 만들고 골든 테스트를 붙였다. 최종 검토에서 목록 행·시트용 불투명 카드 `AppCard`를 더했다.

## 설계와 다르게 가거나 새로 정한 것

- **재인증(사용자 결정 2026-09-22)**: 연결·해제·탈퇴 앞에 "최근 로그인 확인"을 둔다. 소셜 로그인이 준 액세스 토큰에만 있는 `auth_time`이 300초 이내여야 통과한다. 갱신이 준 토큰에는 `auth_time`이 없어 항상 막히고, 해제가 주는 새 토큰은 요청에 쓰인 토큰의 `auth_time`을 그대로 물려받는다(해제를 되풀이해 창을 늘릴 수 없다). 실패하면 앱은 소셜 로그인을 한 번 더 하고 원래 요청을 한 번만 다시 보낸다.
- **문구는 상수 클래스 하나**(`lib/l10n/app_strings.dart`)에 모은다. `gen-l10n`은 코드 생성기라 도입하지 않는다. 다국어가 필요해지면 그때 구조를 바꾼다.
- **테스트와 "투명도 줄이기"에서는 글래스를 불투명한 면으로 그린다.** `flutter test` 환경의 셰이더를 믿을 수 없어서다. 골든 테스트는 위젯마다 이 불투명 대체 모습 하나만 찍는다 — 설계 8.2절의 "대체 모습도 찍는다"는 이렇게 충족했다고 본다(투명 버전과 대체 버전을 나란히 찍지는 않는다).
- **Flutter 3.44에는 "투명도 줄이기" 신호가 없다.** 그래서 시스템 고대비 설정(`MediaQuery.highContrastOf`)으로 근사한다.
- **Apple 로그인 버튼은 iOS에서만** 보인다. 안드로이드의 Apple 로그인은 웹 흐름뿐이라 이 브랜치에서 제공하지 않는다.
- **웹뷰 방식을 쓰지 않는다**(사용자 지시 2026-09-22). 웹뷰 패키지를 넣지 않고, 소셜 로그인도 네이티브 경로(카카오톡 앱 전환 우선, 구글 네이티브 SDK)로 간다.
- **갱신 실패의 분류**: 백엔드에 닿지 못한 실패(연결 오류·타임아웃)와 502·503·504(게이트웨이 오류로 본다)는 토큰을 유지하고 "다시 시도" 안내를 보여준다. 백엔드에 닿은 그 밖의 모든 실패 응답 — 401·403뿐 아니라 400·404·422·429·500 등 — 에서는 이 기기만 로그아웃한다(토큰이 이미 소모됐을 수 있다고 본다). 단 갱신이 오가는 동안 다른 경로가 저장소를 바꿨으면 지우지 않는다(최종 검토 E).
- **탈퇴의 401을 둘로 나눈다(최종 검토, 결정 003의 의무를 좁힌다)**: 갱신 없이 온 401(리프레시 토큰이 이미 없는 경우 등)과 204는 지금처럼 "탈퇴 완료"다. 원 요청 401 → 갱신까지 401/403으로 실패해 `ApiClient`가 세션을 끝낸 경우는 "탈퇴 완료"가 아니라 "세션 만료"다. `ApiClient`가 그 경로의 예외에 `ApiException.sessionEnded`를 싣고, `AccountApi.withdraw`는 그 401을 다시 던지며, 탈퇴 화면은 오류 문구 없이 둔다 — `completeWithdrawal()`을 부르지 않으므로 `endSession()`이 세운 `SignedOut(sessionExpired: true)`가 남아 로그인 화면에 만료 띠가 보인다.
- **네트워크 타임아웃**: 원 요청과 갱신 `Dio` 모두 연결 10초, 수신·송신 15초(최종 검토 A). 없으면 서버가 응답하지 않을 때 갱신·restore·signOut이 수 분 멈춰 "다시 시도" 경로가 실기기에서 성립하지 않는다.
- **Riverpod 자동 재시도를 끈다**(`ProviderScope(retry: (retryCount, error) => null)`). 갱신 요청을 리프레시 토큰 재사용 감지 없이 자동으로 다시 보내지 않기 위해서다.
- **`crypto`를 열 번째 의존성으로 더한다.** 백엔드가 Apple 토큰의 `nonce`가 `sha256(원본)`인지 확인하므로 앱에서 SHA-256이 필요하다(dart-lang 공식 패키지). 설계 6.1절의 9개(`flutter_riverpod`·`go_router`·`dio`·`flutter_secure_storage`·`kakao_flutter_sdk_user`·`sign_in_with_apple`·`google_sign_in`·`liquid_glass_widgets`·`flutter_animate`)에 이것을 더해 총 10개다. 설계 문서 6.1절도 이 절에 맞춰 고쳤다.
- **카카오·구글·Apple의 네이티브 설정은 키가 생길 때 한다**(설계 8.3절 — 등록은 사용자만 할 수 있다). 이 계획은 Dart 쪽 구현과 `app/NATIVE-SETUP.md`(패키지 소스를 근거로 무엇을 어디에 넣어야 하는지 남긴 문서)까지다.
- **`flutter_animate`는 설치만 되어 있고 쓰는 곳이 없다.** 누르는 위젯의 움직임은 `Pressable`의 스프링 물리로 충분했다. ③(예약·달력)에서도 쓸 곳이 없으면 의존성에서 뺀다.
- **사전 점검 P11 — Material `BackButton`·`CheckboxListTile`을 `Pressable` 없이 쓰는 곳**: `grep -rn "BackButton" lib`로 확인한 결과 화면의 뒤로 가기는 전부 `AppBackButton`(내부에서 `Pressable`을 쓴다)으로 바뀌었고 Material `BackButton`은 `lib/`에 남아 있지 않다. 예외로 남는 것은 `lib/features/account/screens/withdraw_screen.dart`의 `CheckboxListTile` 하나다(회원 탈퇴 동의 체크박스) — Material 기본 동작(탭 영역·상태 표시)을 그대로 받아들이기로 하고 `Pressable`로 바꾸지 않았다. 시스템 뒤로 가기 제스처와 마찬가지로 플랫폼 관례를 따르는 예외로 둔다.

## 검토에서 고친 것

작업별 검토가 계획서 코드의 결함을 잡았다. 작업 순서대로 적는다.

- **Task 5(ApiClient 갱신)**: 검토가 세 가지를 실제로 재현했다 — 갱신 중 로그아웃하면 늦게 온 응답이 새 토큰을 다시 저장해 로그아웃한 세션을 부활시킴, 리프레시 토큰이 이미 없을 때 401마다 세션 종료를 반복해 정상 로그아웃·탈퇴 뒤에도 만료 띠가 뜸, `_refreshFuture`를 해제하는 코드를 지워도 테스트가 통과함. 저장 직전 저장소의 리프레시 토큰이 갱신에 쓴 값과 같을 때만 저장하고, 리프레시 토큰이 없으면 `UNAUTHENTICATED`만 던지며, 같은 클라이언트에서 갱신이 두 번 겹치는 테스트를 더해 고쳤다.
- **Task 6(세션 상태)**: `endSession` 뒤 늦게 온 `/v1/me` 응답이 로그인 상태를 되살리는 문제, 앱 시작 때 갱신이 401/403이면 만료 띠가 잘못 뜨거나 스플래시가 "다시 시도"에 갇히는 문제, 배선 테스트가 제품 코드의 `onSessionEnded` 연결을 실제로 검증하지 못하는 문제를 잡아 상태가 이미 로그아웃이면 되돌리지 않게 가드를 걸고, 세션 종료 뒤에는 로그인 화면에서 정지 문구가 보이게 하고, 배선 테스트를 실제 `apiClientProvider`로 바꿨다.
- **Task 7(라우터 가드)**: 유효한 액세스 토큰인데 `/v1/me`가 `ACCOUNT_SUSPENDED`(403)면 오류 상태에 갇혀 로그아웃도 못 하는 문제를 잡아, 정지 계정도 토큰을 지우고 로그아웃 화면으로 보내게(다시 로그인하면 정지 문구가 보인다) 고쳤다. 루트 위젯의 `retry` 끔과 라우터 단일 인스턴스 유지를 검증하는 테스트도 더했다.
- **Task 8(로그인 화면)**: 소속 없는 사용자의 초대 코드 화면에 계정 설정·로그아웃 규칙(브리프 필수)이 테스트로 덮이지 않은 것을 잡아 테스트를 더했다. 컨트롤러가 시뮬레이터에서 로그인 화면의 "차곡노트" 제목이 한글인데 영문 세리프(글리프 없음 → 시스템 폰트로 대체)로 그려지는 것을 발견해 마루 부리(`titleKo`)로 바꿨다.
- **Task 10(멤버 관리)**: 멤버 목록 조회가 매장 범위 공용 처리(`runShopScoped`)를 거치지 않아 `NOT_A_MEMBER`를 받아도 `/v1/me` 재조회로 이어지지 않는 문제(S8이 가장 흔히 걸리는 경로), 직원/사장 메뉴 노출 테스트가 헤더 버튼만 보고 행 단위 권한을 확인하지 않는 문제를 고쳤다. 같은 라운드에 만료일·가입일이 UTC로 그대로 찍혀 한국 시간 기준 하루 이르게 보이는 표시 오류도 고쳤다.
- **Task 11 / 11b(매장 정보, 뒤로 가기)**: 매장 정보 저장 성공 뒤 `/v1/me` 재조회를 부르는지 단언하는 테스트가 없어(지워도 통과) 더했다. 계획서에 없던 결함도 이 사이에 나왔다 — **사용자가 시뮬레이터에서 발견**: 설정·멤버 화면에 뒤로 가기 버튼이 없고 홈→설정이 `context.go`라 설정에서 홈으로 못 돌아갔다. 별도 작업(Task 11b)으로 홈→설정을 `push`로 바꾸고 설정·멤버·매장 정보·매장 선택 화면에 `AppBackButton`을 달았다.
- **Task 12(계정 연결·해제)**: 해제 성공 뒤 `/v1/me` 재조회가 실패하면 해제 전체를 실패로 보고 구글 연결 끊기(`disconnect()`)를 건너뛰는 문제, 해제로 받은 새 토큰을 저장한 직후 진행 중이던 갱신이 401로 끝나면 방금 저장한 토큰을 비교 없이 지워 로그아웃시키는 경합(S5)을 고쳤다. 구글 연결 끊기를 해제 직후·재조회 앞으로 옮기고, 갱신 실패 분기도 저장소의 리프레시 토큰을 다시 읽어 갱신에 쓴 값과 다르면 지우지 않게 했다.
- **Task 13(회원 탈퇴)**: 401 경로에서 `endSession`(만료 띠)과 탈퇴 완료 처리 사이에 로컬 정리(`clearLocal`)의 플랫폼 채널 대기가 끼어들어 실기기에서 만료 띠가 잠깐 보일 수 있는 문제를 잡아, 탈퇴 완료 상태로의 전환을 `clearLocal` 앞으로 옮겼다. 같은 라운드에 탈퇴 버튼 연타 방지(`_busy` 가드)를 더하고, 리프레시 토큰이 없어 `endSession`이 애초에 불리지 않는 첫 401 테스트의 이름을 실제 동작에 맞게 고쳤다.
- **Task 14(소셜 로그인 어댑터)**: 구글 `disconnect()`가 초기화 확인을 거치지 않아 앱을 재시작한 뒤 구글 로그인 없이 해제·탈퇴를 하면 조용히 실패할 수 있는 문제를 고쳤다. 같은 라운드에 초기화 캐시를 재시도 가능하게 정리하고 Apple 신원 토큰이 없을 때의 방어를 더했으며, `NATIVE-SETUP.md`가 iOS 배포 대상 15.0 상향을 Task 14에서 한 것처럼 적은 사실을 Task 1로 바로잡았다.
- **Task 15(백엔드 재인증 가드)**: R2(해제가 준 토큰이 원래 로그인 시각을 물려받는다) 통합 테스트가 로그인과 해제가 같은 초에 실행되면 회귀해도 통과하는 문제를 잡아, 개인키로 `auth_time`을 과거로 서명한 토큰을 직접 만들어 결정적으로 확인하게 바꿨다. 미래 시각 토큰 거절, 300/301초 경계 테스트도 더했다. 경로 접두어 규칙만으로는 경로 이름이 바뀌면 아무것도 검사하지 않고 통과하므로, 연결·해제·탈퇴 경로가 실제로 최근 로그인 가드를 거치는지 경로 집합을 직접 단언하는 테스트를 더했다.
- **Task 16(재인증 화면)**: 계정 화면에서 탈퇴 화면으로 갔다가 뒤로 오면 탈퇴 화면의 `dispose`가 계정 화면의 재인증 프롬프트를 공유하는 자리를 비워 재인증 시트가 사라지는 문제를 잡아, 이전 프롬프트를 기억했다가 자기 것일 때만 되돌리게 고쳤다. 같은 라운드에 `me == null`이면 재인증을 시도하지 않고 원래 오류를 그대로 던지게(S6을 닫힌 쪽으로) 하고, 재인증 시트에서 SDK `signIn()`이 예외를 던지면 시트에 문구로 보여주게 했다.
- **최종 검토(브랜치 전체, 2b951f2..abad242)와 사용자의 시뮬레이터 확인**:
  - A: `dioProvider`·`refreshDioProvider`에 타임아웃이 없었다 — 연결 10초, 수신·송신 15초를 한 곳(`_baseOptions`)에서 건다.
  - B: 탈퇴 401 → 갱신 401로 세션이 끝난 경우를 "탈퇴 완료"로 오인해 만료 띠를 지우고 있었다 — 위 "탈퇴의 401을 둘로 나눈다" 판정대로 고쳤다. Task 13의 `clearLocalGate` 순서 테스트는 204 경로로 옮겨 유지한다.
  - C: 멤버·매장 정보 화면이 첫 조회 오류에 갇혔다(family가 오류를 계속 들고 있고, 매장 정보 화면은 오류 상태에 뒤로 가기도 없었다) — 두 컨트롤러를 `autoDispose.family`로, 머리의 뒤로 가기를 모든 상태에 보이게, 오류 상태에 "다시 시도"를 두었다.
  - D: 스크롤 목록 행(멤버·매장 선택·계정)과 시트가 글래스를 쓰고 있었다(설계 6.2 위반). **사용자가 시뮬레이터에서 초대 코드 시트의 만료 문구가 안 읽히는 것을 발견**했다. 불투명 `AppCard`를 두어 목록 행과 `AppSheet`에 쓰고, 시트 뒤 막을 옅은 `AppColors.scrim`(검정 26%)으로 바꿨다. `AppGlassCard`는 남긴다(지금 `lib/`에서 쓰는 곳은 없다 — 떠 있는 카드용).
  - E: 갱신 성공 갈래는 다른 경로가 새 토큰을 저장했을 때 원 요청을 실패시키고, 실패 갈래는 저장소가 비었을 때 헤더 없는 재시도를 보냈다 — 두 갈래를 같은 규칙(비었으면 `UNAUTHENTICATED`, 다른 토큰이면 저장·삭제 없이 그 토큰으로 한 번 재시도)으로 맞췄다.
  - F: 갱신 중 `ApiException`이 아닌 예외(200인데 토큰 없는 본문 등)도 잡아 `HTTP_ERROR`로 요청을 끝낸다. 쓰지 않는 `cupertino_icons`를 뺐다(의존성 10개). 시트가 키보드만큼 아래 여백을 둔다. 초대 코드는 음수 자간의 `bigNumeral` 대신 자간을 벌린 `AppTypography.inviteCode`로 그린다. `IDENTITY_ALREADY_LINKED` 문구에 "그 계정에서 탈퇴한 뒤 다시 연결해 주세요"(설계 5.6)를 넣었다. 초대 수락 뒤 `/v1/me` 재조회가 실패하면, 소속이 이미 있는 유저는 홈으로 가고 소속이 없는 유저는 스피너를 풀고 문구를 보여 다시 누를 수 있게 한다. 다시 눌러 `ALREADY_A_MEMBER`(앞선 수락이 이미 끝남)를 받으면 재조회해 소속이 생겼으면 홈으로 간다(재검토에서 첫 수정이 소속 0개 유저를 스피너에 가두는 것이 드러나 고쳤다).
  - 최종 재검토: **사용자가 시뮬레이터에서 발견** — 설정 화면의 뒤로 가기 아이콘이 `ListView`에 늘어나 화면 가운데에 그려졌고(매장 선택 화면도 같은 모양), 소속 있는 유저의 초대 코드 화면은 `AppBar`가 검은 띠로 칠해져 검은 뒤로 가기 아이콘이 묻혔다. 두 목록 화면은 버튼을 왼쪽에 붙이고, 초대 화면은 `AppBar`를 없애고 본문 머리 왼쪽에 둔다.

## 남는 것 — 알고 미룬다

- 로그인 직후 300초 안에 훔친 토큰은 여전히 재인증을 통과한다(결정 003의 위협을 창을 좁혔을 뿐 닫지는 않았다).
- 카카오·구글·Apple의 실기기 확인은 사용자가 각 콘솔에 키를 등록한 뒤에만 할 수 있다(설계 8.3절). SDK 어댑터 세 개는 단위 테스트가 없고 실기기 확인이 유일한 검증이다.
- 글꼴 용량 — Pretendard 가변(6.7MB) + 마루 부리(3.3MB). 출시 전 서브셋(실제 쓰는 글리프만 남기기) 검토가 필요하다.
- 오프라인 캐시가 없다. 다국어도 없다(`AppStrings`는 한국어 고정).
- **탈퇴의 401 판정은 갱신 여부로만 나눈다.** 갱신 없이 온 401은 여전히 "완료"로 본다 — 리프레시 토큰이 이미 없는 상태에서 보낸 탈퇴 요청은 실제로는 계정이 남아 있을 수 있다(다시 로그인하면 보인다). 두 기기에서 경합한 두 번째 탈퇴(첫 요청이 모든 세션을 폐기해 두 번째가 401 → 갱신 401)는 이제 "완료"가 아니라 "다시 로그인" 안내가 되고, 거기서 다시 로그인하면 새 빈 계정이 만들어진다.
- **`OWNERSHIP_TRANSFER_REQUIRED` 뒤 멤버 화면은 현재 선택된 매장 기준이다.** 다른 매장에서 문제가 나면 엉뚱한 매장의 멤버 목록으로 이동한다(제품 판단 필요, Task 13 발견).
- **502·504를 "백엔드에 닿지 못함"으로 묶어 토큰을 유지하는 분류는 완벽하지 않다.** 업스트림이 요청을 받은 뒤 처리 중 끊긴 경우에도 같은 코드가 나올 수 있어, 실제로는 처리됐는데 토큰만 유지하고 재시도를 유도하는 경우가 있을 수 있다(Task 5 발견).
- **Apple 로그인의 이름 결합 순서가 정해지지 않았다.** `sign_in_with_apple`이 주는 `givenName`·`familyName`을 구분자 없이 이어 붙이는데, 한국어 성·이름 순서(성이 먼저)로 할지 Apple이 주는 순서 그대로 할지 결정이 필요하다(Task 14 발견).
- **카카오톡 앱 로그인이 실패했을 때(취소가 아닌 다른 오류) 계정(웹) 로그인으로 자동 전환할지 정하지 않았다.** 지금은 취소일 때만 계정 로그인으로 넘어간다(Task 14 발견).
- **네트워크 오류로 끝난 갱신 직후의 좁은 창.** 갱신이 타임아웃 등으로 끝나 토큰을 유지하면, 서버가 실제로는 그 갱신을 처리했을 때 다음 요청이 같은(이미 소모된) 리프레시 토큰으로 또 갱신해 재사용 감지로 모든 기기가 로그아웃될 수 있다(최종 검토가 미룸).
- **정지 계정의 안내 문구.** 앱 시작 때 정지 계정은 만료 문구("다시 로그인")로 보이고 다시 로그인해야 정지 문구가 보인다. 사용 중에 받은 `ACCOUNT_SUSPENDED`는 세션을 끝내지 않고 화면 문구로만 보인다.
- **재인증을 취소하면 만료 문구와 같은 문구("보안을 위해 다시 로그인해 주세요")가 보인다.** 세션이 끝난 것처럼 읽힐 수 있다.
- **운영 빌드의 `API_BASE_URL` 기본값이 로컬 평문 주소(`http://127.0.0.1:8080`)다.** 운영 빌드에서 값을 넘기지 않으면 그대로 나간다 — 출시 전 기본값을 막거나 빌드에서 강제한다.
- **iOS에서 앱을 지웠다 다시 깔아도 키체인의 토큰으로 로그인이 유지된다.** 첫 실행 표시(설정 저장소)로 키체인을 비울지 정해야 한다.
- **매장 범위 화면을 저장·변경 요청 도중에 떠나면 뒤이은 `/v1/me` 재조회를 건너뛸 수 있다.** 컨트롤러가 `autoDispose`라 화면을 떠나면 버려지기 때문이다. 오류는 화면이 삼키고, 다음 재조회 때 맞춰진다.
- **탈퇴 요청의 401이 오가는 동안 사용자가 로그아웃하면** 탈퇴 경로와 로그아웃 경로가 겹친다(드문 경합, 재검토가 Minor 로 미룸 — 끝 상태와 안내 문구를 따로 확인하지 않았다).
- **갱신이 200인데 본문이 깨졌으면** 요청은 `HTTP_ERROR`로 끝나지만, 서버에서 이미 소모된 옛 리프레시 토큰을 계속 들고 있어 다음 갱신이 재사용 감지에 걸릴 수 있다(서버 버그 경로).
- **초대 코드 만들기·역할 변경·내보내기에 연타 방지가 없다.** 짧은 시간에 여러 번 누르면 초대 코드가 중복 발급되는 등 서버에 여러 요청이 나갈 수 있다(Task 10 발견, 서버 쪽 멱등성 여부와 함께 정할 제품 판단).
